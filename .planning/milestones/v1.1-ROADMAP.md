## Summary

SumUp embedded checkout + drink ordering system. Members buy drinks via embedded payment widget, receive HMAC-signed tokens, and redeem at the bar with anti-fraud countdown. Anonymous guests can scan a QR code, purchase drinks without login, and manage tokens via localStorage.

## Key Accomplishments

1. **SumUp Embedded Checkout** -- Replaced hosted checkout redirect with in-app card widget. SumUpCardWidget component reused across ticket and drink purchases.
2. **Drink Menu & Purchase** -- Per-event drink menu with CRUD management, quantity selectors, embedded SumUp payment, webhook-based order fulfillment with individual token generation.
3. **Drink Redemption** -- 3-second countdown anti-tap protection, HMAC signature verification, SECURITY DEFINER RPC with FOR UPDATE row lock, full-screen SERVED animation. Works on event page and dashboard.
4. **Public Drink Menu** -- QR-accessible page at `/events/[slug]/menu` for anonymous guests. Guest purchase with null user_id, localStorage + URL param token persistence, pre-checkout login warning, downloadable QR code for organizers.
5. **Webhook Hardening** -- Error handling for drink order RPC failures (matching ticket pattern), removal of unused `p_transaction_code` parameter.

## Key Decisions

- SumUp SDK script in root layout for site-wide availability
- useRef for callback stability in SumUpCardWidget (prevents widget re-mounts)
- Webhook fallback pattern: check pending_purchases first, then drink_orders
- Token signing in webhook handler (not PG function) because HMAC uses Node.js crypto
- redeemDrinkToken verifies ownership via authenticated supabase client before service-role RPC
- Guest server actions use getServiceClient() for all DB ops (service-role bypasses RLS)
- Guest token API route uses UUID as capability token, secured by user_id null guard
- QR code dual rendering: SVG for display, Canvas for PNG download (qrcode.react)
- GuestDrinkMenu/GuestTokenDisplay communicate via CustomEvent (avoids prop drilling through server component)
- localStorage stores array of order IDs per event, URL param contains only latest
