  **Add imports at the top of the file:**
  ```typescript
  import { render } from "@react-email/render";
  import { sendEmail } from "@/lib/email";
  import { MemberApprovedEmail } from "@/emails/member-approved";
  import { MemberRejectedEmail } from "@/emails/member-rejected";
  ```

  **Create helper functions for email sending:**

  ```typescript
  const APP_URL = process.env.NEXT_PUBLIC_APP_URL || "https://resonate.app";

  async function sendApprovalEmail(email: string, fullName: string) {
    const html = await render(
      MemberApprovedEmail({ memberName: fullName || "Member", loginUrl: APP_URL })
    );
    await sendEmail({
      to: email,
      subject: "Welcome to Resonate - You're Approved!",
      html,
    });
  }

  async function sendRejectionEmail(email: string, fullName: string) {
    const html = await render(
      MemberRejectedEmail({ memberName: fullName || "Member" })
    );
    await sendEmail({
      to: email,
      subject: "Update on Your Resonate Membership",
      html,
    });
  }
  ```

  **Modify `approveMember` function:**
  1. BEFORE the status update, fetch the member's email and full_name:
     ```typescript
     const { data: member } = await serviceClient
       .from("profiles")
       .select("email, full_name")
       .eq("id", memberId)
       .single();
     ```
  2. AFTER the successful status update (after the error check), send the email fire-and-forget:
     ```typescript
     if (member?.email) {
       sendApprovalEmail(member.email, member.full_name).catch((err) =>
         console.error("Failed to send approval email:", err)
       );
     }
     ```
  3. The function still returns `{ success: true }` regardless of email outcome.

  **Modify `rejectMember` function:**
  Same pattern as approveMember:
  1. Fetch member email and full_name before the update
  2. After successful update, fire-and-forget the rejection email
  3. Return `{ success: true }` regardless of email outcome

  **Modify `bulkApproveMember` function:**
  1. BEFORE the bulk update, fetch all affected members' emails and names:
     ```typescript
     const { data: members } = await serviceClient
       .from("profiles")
       .select("id, email, full_name")
       .in("id", memberIds);
     ```
  2. AFTER the successful bulk update, send emails sequentially (not concurrently) to respect Resend rate limits:
     ```typescript
     if (members && members.length > 0) {
       // Fire-and-forget: send emails sequentially but don't block the action response
       (async () => {
         for (const m of members) {
           if (m.email) {
             try {
               await sendApprovalEmail(m.email, m.full_name);
             } catch (err) {
               console.error(`Failed to send approval email to ${m.email}:`, err);
             }
           }
         }
       })().catch(console.error);
     }
     ```
  3. Return `{ success: true, count: memberIds.length }` as before.

  **Modify `bulkRejectMember` function:**
  Same pattern as bulkApproveMember but sends rejection emails.

  **CRITICAL implementation notes:**
  - Email sending MUST NOT block the admin action response. Use fire-and-forget pattern.
  - The DB update is the critical operation. If it succeeds, the action returns success even if email fails.
  - Bulk operations send emails sequentially (not via Promise.all) to avoid Resend rate limits.
  - The fire-and-forget IIFE pattern `(async () => { ... })().catch(console.error)` ensures the async email loop runs in the background.
  - Do NOT change the function signatures or return types of any existing actions.
  - Do NOT modify verifyMaster, verifyAdminOrOrganizer, getServiceClient, updateMemberRole, deactivateMember, or reactivateMember functions.
