  <files>src/lib/analytics/event-queries.ts, src/components/analytics/RevenueCard.tsx, src/components/analytics/AttendanceCard.tsx, src/components/analytics/TokenLifecycleCard.tsx, src/components/analytics/DrinkSalesBreakdown.tsx, src/components/analytics/TicketVelocityChart.tsx</files>
  <action>
1. Create `src/lib/analytics/event-queries.ts` with all data-fetching functions. Each function receives a Supabase client instance and eventId. All functions are async and return typed results.

   a) `fetchEventRevenue(supabase, eventId)` -- Returns `{ grossTickets, grossDrinks, netTickets, netDrinks, totalGross, totalNet }`.
      - Query `tickets` for `amount_paid` where `event_id` matches
      - Query `drink_orders` for `total_amount` where `event_id` matches AND `status = 'completed'`
      - For ticket refunds: fetch tickets for the event first (get their IDs), then query `ticket_refunds` where `ticket_id` is in that list AND `status = 'approved'`. NOTE: The Supabase JS SDK nested filter `tickets.event_id` in a join may not work -- use the two-step approach (get ticket IDs, then get refunds for those IDs).
      - For drink refunds: query `drink_tokens` where `event_id` matches AND `status = 'refunded'`, sum their `price` values.
      - Net = gross minus refunds for each category.

   b) `fetchDailyVelocity(supabase, eventId)` -- Returns `{ date: string; count: number }[]`.
      - Query `tickets.created_at` for event, group by date (YYYY-MM-DD) in JS using Map, return sorted array.

   c) `fetchDrinkSales(supabase, eventId)` -- Returns `{ drinkName: string; quantity: number; revenue: number; redeemed: number; refunded: number }[]`.
      - Query `drink_tokens` for event, group by `drink_name` in JS.
      - For each drink: count total tokens (quantity), sum prices (revenue), count status='redeemed', count status='refunded'.
      - Sort by revenue descending.

   d) `fetchAttendanceRate(supabase, eventId)` -- Returns `{ sold: number; checkedIn: number; rate: number }`.
      - Two count queries on `tickets` with `head: true`: total where event_id matches, checked_in where event_id matches AND `checked_in = true`.
      - Rate = round((checkedIn / sold) * 100) or 0 if no sales.

   e) `fetchTokenLifecycle(supabase, eventId)` -- Returns `{ total: number; redeemed: number; refunded: number; purchased: number; redeemedRate: number; wastedRate: number }`.
      - Query `drink_tokens.status` for event, count each status in JS.

   Export all 5 functions and their return types.

2. Create `src/components/analytics/RevenueCard.tsx` -- Server Component (no 'use client').
   - Props: revenue data object from fetchEventRevenue + use CountUp for animated numbers.
   - Actually, CountUp is a client component, so RevenueCard needs to be a client component OR use CountUp as a child. Make it a CLIENT component (`'use client'`) since it uses CountUp.
   - Display: gradient border card (match SalesDashboard pattern: `rounded-2xl border border-accent/30 bg-gradient-to-br from-card to-accent/5`).
   - Show totalNet with CountUp animation as primary number, format as EUR.
   - Below: two columns -- Tickets (gross / refunds / net) and Drinks (gross / refunds / net).
   - Use `format={(n) => \`EUR ${n.toFixed(2)}\`}` for CountUp.

3. Create `src/components/analytics/AttendanceCard.tsx` -- `'use client'` (uses CountUp).
   - Props: `{ sold: number; checkedIn: number; rate: number }`
   - Card with rate as large CountUp percentage, sold/checkedIn as detail.
   - Progress bar showing rate (green if >70%, yellow 40-70%, muted below).

4. Create `src/components/analytics/TokenLifecycleCard.tsx` -- `'use client'` (uses CountUp).
   - Props: token lifecycle data from fetchTokenLifecycle.
   - Show redeemedRate as primary metric (CountUp %), wastedRate as secondary.
   - Visual: two progress bars side-by-side (green=redeemed, red=refunded, muted=purchased/pending).

5. Create `src/components/analytics/DrinkSalesBreakdown.tsx` -- Server Component (no animation needed).
   - Props: `{ drinks: DrinkSalesItem[] }` where DrinkSalesItem has drinkName, quantity, revenue, redeemed, refunded.
   - Desktop: table with columns Name, Qty, Revenue, Redeemed, Refunded.
   - Mobile: card layout per drink (same pattern as SalesDashboard buyers).
   - Empty state: "No drink sales yet".

6. Create `src/components/analytics/TicketVelocityChart.tsx` -- `'use client'` (Recharts requires client).
   - Props: `{ data: { date: string; count: number }[] }`
   - Recharts BarChart with ResponsiveContainer (h-48 w-full).
   - XAxis: date formatted as "Mar 9" style. YAxis: integer only. Tooltip with dark theme styling matching project (card bg, card-border).
   - Bar fill: `var(--color-accent)` with rounded top corners.
   - Empty state: "No ticket sales yet" text.
   - Follow exact pattern from research RESEARCH.md code examples.
