<objective>
`src/app/api/auth/callback/route.ts:25-33` promotes on every login and never
demotes. Every past master stays master forever and nothing declares it — an
undeclared one-way switch, which is the class of error this project treats as
most dangerous. `meta-gates.md` allows a monotone guard to be worked against only
with explicit authorisation documented in the commit; D-12 **is** that
authorisation and the commit must say so and cite it.

Five defects live in nine lines, and each is a work item: it never demotes; the
result of the write is discarded so a failure is invisible; the comparison is
exact, case-sensitive and untrimmed, on a variable this project has already been
bitten by; it fires on every login and is idempotent by luck; and — repaired in
plan 43-04 — the redirect was unvalidated.

D-16 draws the boundary that keeps a repair from becoming a lockout: demote only
when the named account **exists and holds `master`**, and never into a
zero-master state. An unset variable is a deployment accident — a Vercel value
dropped in a redeploy — not an instruction to remove every administrator.

**One shape decision, forced by Guardrail 5.** The reconciliation cannot be a
one-shot migration with the address inlined: this repository is public and a
commit is a publication. So the migration ships the *rule* as a function taking
the address as an argument, and the address is supplied at call time — by the
login path, and once by hand at apply time. The rule is dated and in the history;
the address never is.

Purpose: ROLE-04, without turning a recovery path into a lockout.
Output: one function, one repaired route, one declared demotion.
</objective>

**No address appears in this file.** Write that as the first line of the header,
with the reason: this repository is public, a commit is a publication, and a
publication is irreversible. The rule is versioned; the value is supplied by the
caller.

Behaviour, in order, and every branch returns a **structured outcome** the caller
can act on rather than a bare boolean:

1. `p_email` null, empty after trimming, or containing no `@` → do **nothing**
   and return an outcome naming that the variable is unset or malformed. It is a
   deployment accident, not an instruction to remove every administrator, and
   demoting on unset turns a config slip into a lockout.
2. Resolve the named account by `lower(trim(...))` on **both** sides. No match →
   do nothing, and return `no_such_account`. The incumbent keeps `master`:
   demoting before the new master exists is the lockout D-12 exists to repair.
3. Match found and it does not yet hold `master` → promote it, writing `role` and
   `status` together, and record the act in the register as `promoted` with
   `actor_kind = 'system'`.
4. Match found and holding `master` → demote every **other** account holding
   `master`, one register row each, `act = 'demoted'`, `actor_kind = 'system'`.
   The demotion writes `role = 'member'` **only**, never `status`: `member` and
   `approved` are different axes, someone who was approved stays approved when
   they stop being staff, and demoting to `staff` instead would acquire an
   obligation under plan 43-06's constraint for no benefit.
5. **The zero-master guard, checked before the write commits, not after.** After
   the demotions the count of accounts holding `master` must be at least one. If
   the arithmetic would reach zero, raise and abort the whole call: a recovery
   path that can empty itself is not a recovery path.

Idempotent by construction, in the shape of the guest-list backfill: a second
call with the same argument finds nothing to change and writes no register row.
Say that in a comment — the current promotion is idempotent by luck, and luck is
not a property.

Then lock the function down as plan 43-07 did: `revoke all on function` from
`public`, `anon` and `authenticated`, `grant execute` to `service_role` only. A
`SECURITY DEFINER` function that writes `role` and is callable by an
authenticated session is a privilege-escalation primitive, and PostgREST exposes
`public` functions by default.

The header carries the `meta-gates.md` paragraph in full: this is the one place
in the phase where the monotone-guard rule is deliberately worked against, D-12
is the authorisation, and the commit message cites it.
