## How to read a step

- Rows are executed **in the order written**, per section.
- Each row's `Result` began as `pending`. Fill it with what was **observed** — a
  number, with the width it was taken at.
- An observation is a fact a second person standing beside the device could
  confirm or deny. *"It looked fine"* is not one. *"At 390px the leading edge of
  the first card was 24px from the viewport edge and a sideways drag moved the page
  0px"* is.
- Where a row fails, **write what happened, verbatim. Do not retry until it
  passes**, and do not adjust the viewport until it does.
- Where a device or a session is not available, write `human_needed` **and the
  reason**. That is an honest verdict and a tick would not be.
- **Nothing in this pass creates a row in production.** See the closing block. It
  is not boilerplate: this project lost 63 rows across seven tables to a
  verification script and it has no PITR.

## §1 — The ten surfaces, at three widths

Thirty rows. **The ten surfaces are this phase's whole declarable perimeter**, taken
from `41.2-CONTEXT.md`'s Phase Boundary and not from memory.

**How to measure, so the result is a number.**

- **The leading clearance.** From 768px up the navigation is a **side column** and
  the shell reserves **224px** on the leading edge for it. Read the distance from
  the viewport's leading edge to the leftmost pixel of any content: **224px, within
  8px**. Below 768px that same distance is **0px, within 4px** — a column reserved
  on a phone is the silent half of the same defect.
- **Content centring.** The shell centres a **1024px** content column in whatever
  is left, with **24px** of its own gutter each side. Read the space between the
  navigation column's trailing edge and the content's leading edge, and the space
  between the content's trailing edge and the viewport's trailing edge: **the two
  differ by no more than 8px**, which puts the column's centre within 4px of the
  centre of the space it lives in.
- **Horizontal scroll.** Put a finger, or the trackpad, on the page body and drag
  sideways. The page moves **0px**. Not *barely*, not *a little*: zero.
- **The bottom clearance on a phone.** The shell reserves the navigation bar's own
  height plus **16px**. Scroll to the end: the last element's bottom edge clears
  the bar's top edge by **at least 16px, within 4px**.
- **A control's height.** Read the box, not the ink. **44px is a MINIMUM, not a
  fixed height** — a control whose label wraps to two lines is taller and is
  correct; a control at 43px is not.

## Closing block

### What this pass creates in production: nothing

It opens pages and reads them. Its four most tempting rows are all written to stop
short of a write: **D5** opens the redemption confirmation and presses nothing;
**D8** opens the refund request and leaves without submitting; **D15** raises the
upload's confirmation and cancels; **D17** opens the reveal and presses Escape.

project lost 63 production rows across seven tables to a verification script, with
no PITR, and authorisation to write to production is an act that is spent once and
recorded — never a standing permission.

### Nothing here reveals a venue

No row sends mail and none touches the reveal flag. **D16–D18 open the
secret-venue dialog and dismiss it**, which is reading the guard rather than
operating it.

**And the observation this phase earned is NOT in this document.** The venue
block's behaviour under a **role session** — the address to an entitled reader,
nothing to everybody else — belongs to `41.2-RESP-01-PASS.md`, for two reasons
stated together: it is the requirement's evidence rather than this phase gate's,
and **no tool in this repository can authenticate as a role**, so it could not have
been taken here in any case. Recording it in the phase pass would have put a
Critical observation where a blanket reply could close it.

### No real credential is used, and no class string is spelled

No row asks for a key, a token or a password to be typed anywhere but into the
product's own sign-in, and none is written down. And per DEF-41-01 no class string
appears above: every criterion is a measurement in pixels, and the clearance
declaration is cited at `src/app/(public)/gallery/page.tsx:110` rather than
written out — because Tailwind's source detection scans `.planning/` and would
compile a rule out of this prose.

### Why not one of these sixty-seven was taken during execution

**D-41.2-04**, and it is a decision rather than an omission. No worktree in this
phase held `.env.local`; the middleware reads Supabase credentials on **every**
request, so nothing renders without them; and supplying them would point a running
application at production. This repository has incident D12 behind that sentence —
a verification that deleted 63 rows across seven tables, none recovered, PITR not
enabled. **The safe default was also the road that does not touch production, and
when those two coincide the decision is not close.** It is a standing decision for
this phase, not a permanent one.

Sixteen gates prove the **files**, and not one of them has seen a pixel. There is
**no test runner in this repository** and this phase did not introduce one, so
nothing above is covered by a test and nothing above may be described as verified
because something passed.

An approval on this document is a real and sufficient authorisation to **close the
phase gate** — a decision the owner is entitled to make, and the honest name for it

**Approved is not verified.**
