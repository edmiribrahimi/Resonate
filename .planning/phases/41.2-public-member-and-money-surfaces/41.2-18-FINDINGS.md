## F-41.2-18-01 — a colour name that was never declared, used twice, silently

**Site:** `src/components/media/MediaUpload.tsx`, two text-colour utilities —
before this plan at `:516` and `:528`.

Both named a colour called `fg`. **That name is not declared anywhere.**
`src/app/globals.css` maps twenty-two colour names and it is not among them:

```
$ LC_ALL=C /usr/bin/grep -c -- '--color-fg' src/app/globals.css
0
```

Tailwind emits no rule for a colour it has never heard of, so both elements
rendered at whatever colour they inherited. Concretely: the name of the night a
file was about to be filed under was drawn no stronger than the sentence around
it, on the one control where the whole point is that nobody uploads without
seeing where the file is going.

**Why no gate saw it.** `verify-tokens` check D tests the names that ARE declared
but not yet exposed as utilities — a name that was **never declared** falls
outside every list it holds. The build is silent too: an unknown colour is not a
type error. The only observable is an absence on screen.

**Measured tree-wide, so the scope is a number and not an impression:**

```
$ LC_ALL=C /usr/bin/grep -rn 'text-fg\|bg-fg\|border-fg' src
src/components/media/MediaUpload.tsx:516: …
src/components/media/MediaUpload.tsx:528: …
```

Two occurrences, both in this file, both this plan's.

**Repaired here, because the repair IS the conversion:** both now take the
declared ink token. Recorded anyway, because the *class* of defect survives the
fix — a colour utility naming something that does not exist is silent in the
build, silent in every gate, and visible only as a thing that is not there.

**To close the class:** a check that the colour name in every colour utility
under `src/` resolves to a declared token. That is a gate edit, and this plan
edits no gate.

## F-41.2-18-02 — the share control had no accessible name at all

**Site:** `src/app/(public)/events/[slug]/ShareButton.tsx`, the control itself.

It was an icon-only control carrying two glyphs and **no label of any kind**. A
screen reader announced it as "button" and nothing further. It was also a 40px
circle, below the 44px floor.

**Repaired here**, because the icon rung types the name as *required* rather than
trusting it — the defect could not survive the conversion even if nobody had
noticed it. The name also carries the state, which is the second half of the same
problem: the only feedback this control gives is a glyph swap, and a glyph is not
announced.

## F-41.2-18-03 — a share that fails tells nobody, and looks like a press that did not land

**Site:** `src/app/(public)/events/[slug]/ShareButton.tsx`, the clipboard branch's
catch — an empty block, carried across **byte-identical** by this plan.

On a browser with no share sheet, the control falls back to writing the URL to
the clipboard. If that write is refused — permission, an insecure context, focus
lost — the catch absorbs it and **nothing at all happens**: no glyph change, no
message, no sound. It is indistinguishable from a press the page never received,
so the person presses again, and again.

**The catch beside it is a different case and is correctly silent:** a person who
dismisses the system share sheet has cancelled, and telling them so would be
telling them what they just did.

**Why it was not repaired.** A message here is **new copy on a public surface**,
and this pass converts presentation. It is the same disposition the phase already
took on the money path's silent catches, for the same stated reason.

**What makes it more than tidiness:** this repository has **no error tracking**,
so a failure that is not visible on screen is not visible anywhere. There is no
log anybody reads and no counter anybody watches.

**To close it:** a plan that owns the copy of this surface, giving the failing
branch an observable effect — the wording written once and used always.

**Status: recorded. NOT fixed.**

## F-41.2-18-04 — five distinguishable RSVP refusals arrive as one opaque sentence

**Site:** `src/app/(public)/events/[slug]/RsvpButton.tsx` renders `err.message`;
the causes are in `src/app/(public)/events/[slug]/rsvp-actions.ts`, which this
plan **read and did not open**.

That module throws five refusals, and they mean genuinely different things:

| Cause | What the correct advice would be |
|---|---|
| not signed in | sign in |
| the account is not approved yet | wait — and this one is not the person's to fix |
| this night does not take RSVPs | nothing; the control should not have been drawn |
| an RSVP already exists | you are already in — stop pressing |
| the insert itself failed | try again |

**They cannot arrive distinguishable, and not because of this file.** Next
**redacts** the message of an error thrown out of a Server Action in a production
build. `MediaUpload.tsx`'s own header states this and works around it by
separating its failures **by position** — which call in the sequence threw —
because position survives the redaction and a message does not. This control has
no such separation: it prints what it caught, and in production what it caught is
opaque.

So the branch where the right advice is *you are already in* reads exactly like
the one where the right advice is *your account is not approved yet* — and the
second is a statement about someone's standing in the community, delivered as a
generic failure.

**Why it was not repaired.** Two reasons, and either alone is sufficient.
Distinguishing the causes means either rewriting member-facing copy or changing
what the action returns — and the action is the one module in this perimeter
carrying the server directive, which this plan is forbidden to open. It is the
same shape as the refund refusal already recorded by an earlier plan in this
phase.

**To close it:** a non-visual plan that owns both halves — the action's return
shape and this surface's words — deciding what a member is told when an RSVP does
not go through.

**Status: recorded. NOT fixed.**

## F-41.2-18-05 — the upload drop zone could not be reached from a keyboard

**Site:** `src/components/media/MediaUpload.tsx`, the drop zone.

It was a clickable division holding a file input that is not displayed. A
division is not focusable and an undisplayed input is not focusable, so **the
number of keyboard paths to the file picker was zero** — measured, not estimated.
Only a pointer could open it.

**Repaired here**, because the conversion had to decide what the element is: it
is now a button, which brings focus, a name the platform announces, and the
shared focus expression. The input stays a sibling rather than a child, because a
form control inside a button is not valid content.

This is the same shape an earlier plan in this phase recorded on a different
control — a target that did not exist on the device the surface is actually used
on. There it was a phone and a hover; here it is a keyboard.

## F-41.2-18-06 — the pulse census counts two different things, and the plan's arithmetic assumed one

**Not a defect. A correction to a number four documents carry**, recorded because
wave 8 is about to read it.

The plan states that after this placeholder the only hand-rolled pulses left in
the tree are the primitive's own and the scanner's — which would be eight. A
census by bare string returns **twelve**:

```
$ bash <the census, with its self-check>
   1  src/app/(public)/events/[slug]/RedeemConfirmationModal.tsx
   1  src/app/(public)/events/[slug]/DrinkTokenCard.tsx
   2  src/app/(public)/events/[slug]/menu/GuestTokenDisplay.tsx
   4  src/app/(admin)/admin/scanner/ScannerClient.tsx
   4  src/components/ui/Skeleton.tsx
  ────
  12  TOTAL
```

**The four in the money files are not placeholders.** Read at their sites, they
are the same utility used as an **attention animation**: a prompt telling the
person behind the bar to tap to serve, and a token card that pulses while it is
the active one. Three of the scanner's four are the same thing — a dot on a
pending-sync badge — and only one of its four is a loading placeholder.

So the honest arithmetic is:

| Kind | Count |
|---|---|
| the placeholder primitive's own, one per export | 4 |
| an attention animation, on a control or a badge | 7 |
| **a hand-rolled loading placeholder** | **1** — and it is inside the Phase 42 fence |

**Hand-rolled loading placeholders remaining outside the primitive and outside
the fence: zero.** That is the sentence the plan was reaching for, and it is true.
The sentence about *twelve* would not have been.

**Why this matters beyond bookkeeping.** A census that cannot tell a placeholder
from an attention animation will report a number that never reaches zero, and a
list that can never reach zero is a number that lies — which is the argument this
tree already used to keep a permanently-exempt file off a debt list. If wave 8
wants this counted, it needs a signature that distinguishes the two, not a
smaller number.

## F-41.2-18-07 — the place-word criterion is unsatisfiable as literally written, in two files

**Not a defect either.** The plan's acceptance criteria assert that a
case-insensitive search for place words returns **0** on the upload component and
on the share control. Measured, it does not — before or after this plan's diff —
and in both cases what it matches is correct and must not be removed.

**The share control: exactly one hit, before and after.**

```
$ LC_ALL=C /usr/bin/grep -inE 'venue|address|maps|location' <the share control>
    const url = window.location.href;
```

That is the **browser API** the control reads to know which page it is on. It is
the URL the control exists to share. Deleting the word deletes the feature.

With the browser API's own name out of the alternation, the criterion measures
what it was aiming at and returns **0** on all three of task 2's files.

**The upload component: three hits, before and after.** Two of them are
**user-facing refusal sentences** — the one explaining why a video cannot be
accepted on a night whose whereabouts are secret, and the one explaining why a
failed metadata strip loses the upload rather than publishing it. Those two
sentences are the entire reason the seventeen server-side categories exist. The
third is a comment explaining why the night picker has no preselection, which is
the argument that keeps a photograph from being filed under the wrong night.

**None of the five names a place.** They name the *category* — which is what the
gate protecting this file actually watches, and that gate is green:

```
✓ C  src/components/media/MediaUpload.tsx names the public bucket nowhere
```

**All five were left byte-identical, deliberately.** Rewording a refusal to move a
number is silencing the number without changing the thing — the mechanism this
phase has recorded and refused before. A criterion that can only be met by
deleting the sentence it was written to protect is a criterion to correct, not a
sentence to delete.

**To close it:** wave 8 replaces the alternation with one that excludes the
browser API's name, and reads the criterion for the upload component as *names no
place*, which is what the gate already asserts and what is true.

## An enumeration entry, not a finding — where the shared text comes from

`venue-secrecy.md` requires the list of ways a place can leave the product to be
**rebuilt by reading the code**, because such a list is dated by construction.
Rebuilt for this file set, there are exactly three strings the share control can
hand out, and one of them deserves a note that is not an accusation.

The second string is the event row's **description** — free text somebody typed.
Nothing in the product constrains what goes in it, and nothing in this plan reads
it differently than before. **No claim is made here that it leaks anything**: the
claim is narrower and it is the useful one — *this string is human-authored, it
reaches a share sheet, and a share sheet is a publication*. Whether the editorial
rule that keeps a place out of a public caption is being kept in that column is a
question for whoever writes them, not for a conversion.

**Status: recorded as enumeration. Nothing changed.**
