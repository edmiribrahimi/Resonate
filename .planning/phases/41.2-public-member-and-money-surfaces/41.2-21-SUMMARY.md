# Phase 41.2 Plan 21: Closing G5 on its seven reds — Summary

Closed `verify:touch-targets` on the seven elements F-41.2-19-01 named, by
writing **two** declared exemptions kept deliberately apart — five elements whose
box this parser cannot read, and **two controls the product places below the 44px
floor on purpose** — without editing a source file, moving a threshold, or
widening an existing entry by a character.

## The two constants, and how the seven split

**By kind, not by convenience.** The split *is* the decision — see
F-41.2-21-01 for why one list of seven would have been the cheaper edit and the
worse artefact.

### `UNREADABLE_BOX_ELEMENTS` — exemption 9, five entries

The box is there and comfortably above the floor; the thing that decides it is
not a class string this parser can resolve. Shape `[path, tag, fragment, token,
reason]` — exemption 8's shape, with the **construction the box comes from** in
place of the constant.

| # | Element | Box comes from | What it is |
| --- | --- | --- | --- |
| 1 | `RedeemConfirmationModal.tsx:207` `<button>` | `flex-1` | the bartender's serve area — the **largest tap target in the product**, a `flex-1` child of a `fixed inset-0 flex flex-col` |
| 2 | `GuestTokenDisplay.tsx:284` `<button>` | `flex-1` | the same serve area on the drinks menu; the file says of itself it is a fork |
| 3 | `MediaUpload.tsx:578` `<button>` | `p-8` | the drop zone — icon and two rows of text inside 32px of padding on every side |
| 4 | `MediaUpload.tsx:610` `<input>` | `hidden` | the file input — **no box at all**, hidden by a display utility rather than by the attribute exemption 7 reads |
| 5 | `MyMediaSection.tsx:179` `<a>` | `block` | the event heading, wrapping a title and a date; its height is its content's |

### `BELOW_FLOOR_BY_DECISION_ELEMENTS` — exemption 10, two entries

**Not a parser limit.** These two are measured, they are under 44px, and they are
under it by decision. Shape `[path, tag, fragment, act, reason]` — the fourth
field is **the act the control performs**, because that is what the entry rests
on.

| # | Element | The act |
| --- | --- | --- |
| 1 | `RedeemConfirmationModal.tsx:244` `<button>` | reverts an active drink token — money going backwards at the counter |
| 2 | `GuestTokenDisplay.tsx:322` `<button>` | the same act on the drinks menu, re-derived from that file's own comment rather than inherited |

Both files' own comments, predating this phase, say the row is *"kept narrow so
the bartender's tap can't hit it by mistake"*, under a serve area that *"takes
the whole screen"*. **The floor exists to make a control easier to hit, and on
this one control easier is the failure** — at two in the morning, with a queue in
front. `checkin-offline.md`'s asymmetry decides which error to design against;
§6.2 applies the same asymmetry to sizing and reaches the opposite default, which
is right everywhere the act is forward and is exactly what inverts here.

cannot quietly stop framing what it says.

## The guards each list added, and all three proved reachable

Both lists refuse (exit 2) on a fragment matching **zero** elements (stale — it
forgives nothing while looking guarded) or **two or more** (ambiguous — it
forgives an element nobody named). Those are exemption 2a's refusals, one level
down, and they are shared by one resolver so two copies cannot drift apart.

On top of them, three new guards, each pointing away from a green:

| Guard | Direction it closes |
| --- | --- |
| **9** — the named construction is not on the element | the entry would forgive an element on the strength of a box it does not have: a stated reason **false about its target** |
| **9** — the element declares the minimum after all | the entry forgives nothing and tells the next reader an element is unmeasurable when the gate measures it perfectly well |
| **10** — the element declares the floor | the entry says the product deliberately went under, the element says it did not. One is false and the parser cannot say which, so it says nothing was measured — exemption 7's call on a hidden input carrying a height. **This is what stops the list becoming a place to park an element and quietly raise it later** |

The token test carries the same boundary guard `HEIGHT_RE` uses, so `block` does
not match inside a longer utility — the defect this phase has already paid for
three times (41-02, 41-07, 41-10).

## Proof — twelve cycles, every mutation asserted before its result was read

The harness refuses to run unless it first reproduces a **non-zero** grep on a
positive fixture and a **zero** on a negative one; this phase has already been
handed a corroborating instrument that returned `0/0/0` because of a defect in
itself, and believed, it would have authorised twelve wrong deletions.

Each cycle: mutate → `grep -c` asserting the mutation **landed, non-zero** → run
the gate → revert → `git status --porcelain` **empty** → run the gate again and
require the baseline back (exit 0, measured 63).

```
self-check OK — positive 1, negative 0
baseline: exit 0, measured 63, e9 5, e10 2

PASS  E9 entry …/RedeemConfirmationModal.tsx:207 is load-bearing
PASS  E9 entry …/menu/GuestTokenDisplay.tsx:284 is load-bearing
PASS  E9 entry src/components/media/MediaUpload.tsx:578 is load-bearing
PASS  E9 entry src/components/media/MediaUpload.tsx:610 is load-bearing
PASS  E9 entry src/components/media/MyMediaSection.tsx:179 is load-bearing
PASS  E10 entry …/RedeemConfirmationModal.tsx:244 is load-bearing
PASS  E10 entry …/menu/GuestTokenDisplay.tsx:322 is load-bearing
PASS  E9 narrowness — a DIFFERENT control in MyMediaSection.tsx still reddens
PASS  E10 narrowness — a control ADDED beside the exempt row is NOT pre-forgiven
PASS  E9 refusal — the named construction is not on the element
PASS  E9 refusal — the element declares the minimum after all
PASS  E10 refusal — an entry declared below the floor whose element declares it

12 cycle(s), 0 failed.
git status --porcelain EMPTY at the end.
```

**Per-entry (7).** Each entry was commented out of its list — a mutation asserted
present by `grep -c MUTATION_41_2_21 = 7` — and the gate exited **1 with exactly
one failure, at exactly that `file:line`**. Seven entries, seven single-element
reds, each naming the line its entry names. An entry that is not load-bearing
would have left the gate green, and none did.

**Narrowness (2), because an exemption that forgives more than it names is
exemption 2a's original defect returning.**

- *Mechanism A.* `MyMediaSection.tsx`'s thumbnail button — a **different** control
  in the **same** file — was shrunk from `min-h-11` to `min-h-8`. The gate exited
  1 naming `MyMediaSection.tsx:196` at *"min-h-8 = 32px — below 44px"*, while
  `:179` stayed exempt and did not appear. The exemption forgives its element and
  not its neighbour. *(The failure is reported at 196, the line the opening tag
  starts on, not 201 where the class attribute is written — the gate reports the
  tag, and the expectation was corrected to the tree rather than the other way
  round.)*
- *Mechanism B.* A raw `<button className="mx-auto block min-h-8 …">` was **added
  immediately beside** the exempt reverting row in `RedeemConfirmationModal.tsx`.
  The gate exited 1 naming the new element at `:252` **while `e10` still read 2**
  — the exempt row unchanged, the new arrival **not pre-forgiven**. That is the
  exact defect the per-file blanket had, and this is the stronger of the two
  narrowness forms. It was used here because the shrink form was **not
  available**: after these exemptions that file has no other measured raw element
  (its third is a primitive call site), and saying so is better than dressing an
  addition as a shrink.

**Refusal reachability (3).** Each of the three new guards was tripped by a
source mutation and exited **2**, naming its reason: the drop zone's `p-8`
changed to `p-7` (*"does not carry p-8"*); the drop zone given a `min-h-11`
(*"unreadable, and that element declares an unprefixed minimum this parser reads
perfectly well"*); and the reverting row given a `min-h-11` (*"deliberately BELOW
the 44px floor, and that element declares the floor"*). **An exemption nobody can
trip is decoration, and this repository has already measured what a decorative
check costs.**

## What this does NOT close

- **RESP-03 criterion 5 is not closed, and is now partly FALSE by decision.**
  Two controls are under the floor on purpose. `REQUIREMENTS.md` was not touched
  and RESP-03 stays unticked: its traceability row says *"measured on a device"*,
  and a class-string green is not that.
- **Nothing here measures a rendered box.** Five more elements are forgiven on a
  stated reason rather than measured. **H41-4, on a large touch screen, remains
  the only thing in this repository that would prove anything renders at 44px**,
  and the two serve areas are where it should be pointed first: if either is not
  the full screen its comment claims, exemption 9 is wrong about it and no
  amount of reading the source will reveal that.
- **The cross-gate shadow is only half closed.** Both lists and §13 now carry the
  cross-reference, so a person moving one decision finds the other. Nothing
  installed here would catch the *next* instance — see F-41.2-21-07.

## Deviations from Plan

**None in substance.** Three things worth naming, each recorded rather than
smoothed over:

1. **A contract edit to `41-UI-SPEC.md` §13 was made and was not in the task
   list.** It is Rule 2 territory — the gate's own docblock says *"Adding a
   seventh is a contract edit, not a fix for a red"*, and entries 7 and 8 arrived
   by exactly that route: decision → §13 → gate written to match. Leaving §13 at
   eight would have put the gate **ahead of its contract**, which is the state
   the whole exemption mechanism exists to prevent.
2. **The narrowness proof for mechanism B is an addition, not a shrink**, because
   the shrink form does not exist in that file. Stated in place rather than
   presented as the requested form.
3. **One proof expectation was wrong and the tree was right**: the gate reports a
   failure at the line the **opening tag** starts on (196), not where the class
   attribute is written (201). The expectation was corrected; the gate was not.
