# Phase 41.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
>
> **`nyquist_compliant: false` is deliberate and will stay false.** It is the same
> declaration Phases 31, 36 and 41 made, for the same reason: **this repository has no test
> runner for the product**, so three of this phase's behaviours — and the whole content of
> RESP-01 — can only be closed by a person looking. Setting the flag true would claim a
> sampling rate that does not exist. See *Manual-Only Verifications* below, and
> `meta-gates.md`, *«Il gate della verifica, in un repo senza test»*.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | **none.** `package.json` declares no `test` script; no `*.test.*` or `*.spec.*` exists anywhere in the tree |
| **Config file** | none — **and no Wave 0 gap is filed for it.** Introducing the repository's first test runner is a project decision, not a side effect of a visual conversion phase |
| **Quick run command** | `npm run verify:conversion && npm run verify:dialogs && npm run verify:breakpoints && npm run verify:touch-targets` — the four gates this phase moves |
| **Full suite command** | `npm run verify && npm run build` |
| **Estimated runtime** | quick ~15 s · full suite ~30 s + build ~90 s |

**What the "suite" is here, said plainly.** `npm run verify` runs 16 structural gates that
read class strings, import clauses and declarations. It **runs no product code, executes no
test, and proves nothing anybody looked at**. `npm run build` is `next build --webpack` and is
the typecheck. Neither renders a pixel. That boundary is not a caveat on this document — it is
the reason the *Manual-Only* section below is the longest one.

---

## Sampling Rate

- **After every task commit:** the quick run, plus `npm run build` on any commit touching a
  page file's props or imports.
- **After every plan wave:** the full suite. **A wave that merges red is a wave that reopens.**
- **Before verification:** full suite green, the three ratchets closed with their emptiness
  refusal proved, and both passes of D-41.2-05 written with every `Result: pending`.
- **Max feedback latency:** ~15 s for the four moving gates.

## Domain-Gate Verification — the assertions no requirement asks for

These are not requirement coverage. They are the **stop conditions** of `41.2-CONTEXT.md`,
turned into commands, and they run on **every plan that opens the named file**.

| Assertion | Command shape | Why |
|---|---|---|
| the three-branch ternary at `[slug]/page.tsx:1075-1119` is still three branches | count the branches after the diff | a collapsed branch opens a venue to a reader without entitlement |
| the reveal test at `[slug]/page.tsx:206-207` is still written **positively** | grep the predicate | `undefined !== null` is TRUE — a negated null test plus a dropped column opens every secret night |
| `export const dynamic = "force-dynamic"` at `[slug]/page.tsx:243` is present | grep | a statically renderable page puts an address in a shared cache |
| this route still exports **no** `generateMetadata` | grep, expect 0 | a social preview carrying a secret address is a publication (T-37-25) |
| no server action was opened | `git diff --name-only`, expect zero `actions.ts` / `route.ts` / `.sql` | no server action in the perimeter carries a class string; needing one is **stop condition 2** |
| no spine file was edited | `git diff --name-only` against the four spine paths | the spine is the only bridge to Phase 42 — editing one is a **halt** |

**The negative-space check is the strongest of these**, and Phase 41.1's verification proved
it: enumerating the whole phase's changed files and showing the enforcement surface is
**byte-identical** says more than any assertion about a diff's content.

## Ratchet Closure — proved, not asserted

Criterion 3 requires every `REMAINING` list empty **and** the gates turned into absolutes.
`verify-tables` has already made this transition and is the template:
`scripts/verify-tables.mjs:534-571` (`MIGRATION_CLOSED`) and `:721-742` (the emptiness guard).

| Gate | Today | Emptiness refusal | Closure proof required |
|---|---|---|---|
| `verify-tables` | **0**, `MIGRATION_CLOSED` set | already closed | — |
| `verify-dialogs` | **8** | `:1471` — refuses (exit 2) when the list empties | mutation: reintroduce a hand-rolled shell, assert red |
| `verify-breakpoints` | **5 files / 16 uses** | `:661` — same | mutation: reintroduce an `sm:`, assert red |
| the manifest itself | no gate compares `page.tsx` on disk against `CONVERTED` | — | check F, or the written reading (Wave 0) |

**Every ratchet closure is proved by asserted mutation, and the mutation is asserted *applied*
before its result is read.** A substitution that silently failed to match has already produced
a false negative in this repository. And a `REMAINING` at zero is a claim: this project has
watched the debt-goes-quiet defect return through **four distinct mechanisms**.

**Two documents, one sitting** (D-41.2-05). `41.2-RELEASE-PASS.md` closes the **phase gate**
on this phase's own work and may be closed by the owner's judgement. The **RESP-01 closing
pass** ticks the requirement and therefore must contain the **union** of its evidence, or it
ticks something it did not measure. Both are batched into the end-of-v1.5 sitting that
`41-RELEASE-PASS.md`'s `batch:` field already commits, alongside `40-RELEASE-PASS.md`,
`39-DOOR-PASS.md` and `38-PROCEDURES.md`.

**Phase 41 lost exactly this distinction** — one approval, one document, a phase marked closed
with four criteria still unticked. That is the failure this split exists to prevent.
