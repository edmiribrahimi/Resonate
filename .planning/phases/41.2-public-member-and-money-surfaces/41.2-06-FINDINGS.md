## F-41.2-06-01 — The placeholder's assigned analog is a grid; the surface it stands in front of is a single column

**Severity:** would have shipped the exact defect the analog exists to prevent.
**Disposition:** the analog was **not** followed; the card form was taken instead, and the
divergence is written into the file's own docblock as well as here.

`41.2-PATTERNS.md` §2.2 assigns `src/app/(public)/gallery/loading.tsx:35-38` — a
two-column tile grid — as this file's specimen, and the plan repeats it: *"The placeholder
takes the grid analog, not the list one."*

Measured on the surface it precedes:

```
$ LC_ALL=C /usr/bin/grep -n 'StaggeredList className' 'src/app/(public)/events/EventTabs.tsx'
214:    <StaggeredList className="flex flex-col gap-4">
```

**A single column of cards.** `grid-cols` does not occur anywhere in that file. So a grid
of tiles in the placeholder would have moved every row sideways the instant the data
landed — which is constraint 1 of the three the primitive carries (`Skeleton.tsx:20-53`,
`(work)/members/loading.tsx:29-34`) and the one thing a loading state exists to avoid.

**What was taken instead**, and why it is stronger than either analog: `SkeletonCard`'s
shell is the card contract — the container radius, the line token on the edge, the surface
ground and the 24px padding — and **since this plan's task 2 the loaded row on this
surface writes exactly those four values**. The two boxes are the same box, asserted from
source rather than resembled.

**Where the mis-assignment came from.** §2.2's own table gives this file the gallery
analog *"(grid)"*, and §2.2 was written against the placeholder's own shape — the file it
replaced drew three card outlines in a column — rather than against the surface's. It is
recorded rather than corrected in that document, which is another plan's.

## F-41.2-06-02 — The draft mark was NOT substituted to the amber semantic, and the plan's "first substitution beside format identity" therefore did not occur

**Severity:** the plan's instruction was declined; the reason is a collision the token
file names by hand.
**Disposition:** the raw amber went to `Badge tone="neutral"`, the tree's converted
precedent for the same word. **No `--sem-*` utility landed in this file at all.**

The plan's task 2 says: *"Substitute it to the semantic token, and then run
`verify-semantic-separation` explicitly: the check is line-scoped, so the substitution is
correct — but this is the first substitution in the project to land in a file that also
renders format identity."*

**The amber semantic is the one substitution this surface cannot take.** `globals.css:161`,
verbatim:

> `--sem-warn` IS `--amber` IS SunSet's identification colour. An amber mark cannot tell a
> reader "caution" from "this is a SunSet night" by hue, so ANYTHING AMBER CARRIES TEXT.

And `FormatMarker.tsx:120-128` states the same prohibition from the other side, in a
component that renders **eight lines above** the draft mark on the same card:

> No `--sem-*` and no `--accent` fallback is added for a format: a state that borrowed a
> format's channel would make the two unreadable from each other, and `--sem-warn` already
> holds SunSet's identification value.

So on this surface — the one public listing that paints a catalogue colour per night — an
amber mark eight lines below a catalogue colour is precisely the ambiguity both files
were written to prevent. `verify-semantic-separation` check C would have stayed **green**
on it, because check C is line-scoped and neither line carries a format identifier in the
gate's sense (`color_hex`, `SunSet`, `RamaDub`, `MotionLab` — `verify-semantic-separation.mjs:269`).
**A green there would not have been evidence.**

**What was done instead** is a copy rather than a judgement:
`src/components/events/EventList.tsx:246-252`, a converted work surface, renders the same
word as `Badge tone="neutral"` — a span, because the sentence at the top of `Chip.tsx`
decides it: a badge that is a link or a button is a chip, and this is neither.

**The consequence for the plan's own criterion, stated rather than rounded up.** The
criterion *"`node scripts/verify-semantic-separation.mjs` exits 0 and its check C output is
pasted"* is met — but the run says nothing about the case the plan wanted checked, because
that case was not created. Check C's green is over 264 files and 0 semantic utilities in
this closure. Recorded so the SUMMARY's green is not read as a measurement of a
substitution nobody made.

**Still owed to whichever plan wants it:** the project's first semantic substitution in a
file that renders format identity has not happened yet. Wave 0's check-A table names
several money-surface files with far heavier raw-palette loads and no format identity at
all; the case will most likely arrive on `/events/[slug]`, which renders both.

## F-41.2-06-03 — The inversion: the floor declarations stay, and the reason is mechanical

**Severity:** a decision the plan required be written down; both readings were weighed.
**Disposition:** reading **2** taken — the file converts its colour and focus utilities and
does **not** adopt the chip primitive. `min-h-11` still occurs twice tree-wide, both here.

`41.2-PATTERNS.md` §6.3 names this as one of the map's three declared gaps: the primitive
is *downstream* of this file (`Chip.tsx:28-48` says the shape was taken from
`FormatFilterRow.tsx:109-165`, which is the tree's only prior art at 44px), so replacing
the floor with the primitive is a judgement and not a copy.

**Reading 1 — adopt `Chip` — is unavailable, for two reasons and one trap:**

1. **The primitive's only filled form is its selected state, and that fill is the
   interaction accent.** `Chip.tsx:62-69` — `CHIP_SELECTED = "border-accent bg-accent
   text-ground"`. Handing the current format chip to it puts the interaction hue on the
   format channel, which this file's own docblock refuses in as many words: *"That accent
   is barred from the format channel: the moment one channel borrows the other, a format
   stops being identifiable."* It is barred here **one element below** a tab row that owns
   that hue legitimately — and as of this plan's task 2 that tab row renders it.
2. **The selected state is also what emits `aria-current`** (`Chip.tsx:178`
   — `const current = selected ? ariaCurrent : undefined`). So declining the fill by
   passing `selected={false}` would silently drop the only non-colour channel the current
   chip has, which is `40-UI-SPEC.md` §10's whole subject.
3. **The remaining road — an unselected chip with the ground and ink re-applied from the
   call site — is the WR-05 trap** named at `PageShell.tsx:109-114`: same property, same
   specificity, so the emitted stylesheet's order decides, not the class list.

**What "stays" does NOT mean.** The file was converted:

| | before | after |
|---|---|---|
| boundary | the legacy alias | `border-control` — a chip is a control, and `Chip.tsx:41-44` records 7.14 : 1 against a line token's 1.39 : 1 |
| current ground | the legacy alias | `bg-surface` |
| current ink | the legacy alias | `text-ink` |
| hover ink | the legacy alias | `text-ink` |
| focus | **nothing declared** | `FOCUS_RING`, imported from the ladder and never re-spelled |
| the floor | `min-h-11` ×2 | `min-h-11` ×2 — unchanged |
| the run-time border | `color-mix` ×2 | `color-mix` ×2 — unchanged |
| the page gutter | written here | the shell's; the bleed-and-restore on the scroller stays |

**Where the floor lives now:** in **both** places — twice in this file and twice inside
`src/components/ui/Chip.tsx` (`LC_ALL=C /usr/bin/grep -rc 'min-h-11' src/components/ui/Chip.tsx`
→ **2**). That is the honest state and it is a cost: two declarations of one number, and
`Chip.tsx`'s docblock still points at this file as the source. **It is not a duplication
that a later plan should close by adopting the primitive** — the two reasons above do not
expire. If it is ever closed, what is needed is a chip form whose *selected* state is
ground and ink rather than an accent fill, and that is a new rung on a spine file, which
41.2 may not edit.

## F-41.2-06-04 — The listing's catch collapses every query failure into an empty page, and there is no observability behind it

**Severity:** pre-existing. **Recorded at its `file:line`, not repaired.**
**Disposition:** carried forward. Repairing it is a behaviour change delivered under a
visual mandate.

`src/app/(public)/events/page.tsx:512-516`, byte-identical before and after this plan:

```js
  } catch {
    // Graceful fallback: render empty state if DB unavailable
    upcoming = [];
    past = [];
  }
```

**What it costs.** The two *named* failure categories around it are already correct and
were left exactly as they were: a database-level refusal on the nights carries a code and
is thrown past this catch (`:520-522`), and a refused set of venue names is thrown after it
in its own category (`:527-529`). Both reach Next's error boundary, and both were built by
an earlier phase precisely so that a list rendering with every venue name stripped could
not look healthy.

**This catch is the residue**, and it is the transient case: a transport failure with no
code. Its observable effect is a page that says *"No upcoming events"* on the product's
shop window. There is **no error tracking in this repository** — `package.json` declares no
monitoring dependency — so nothing else reports it, and the sentence is the whole of what
anybody learns.

**Why it is not fixed here.** Distinguishing it would mean giving the empty state a second
sentence, which is a copy decision on a public surface (`41-UI-SPEC.md` §11: *none
introduced*), and the file's own comment already states that the catch *"was written for
'DB unavailable' and keeps covering exactly that"*. The same treatment the four money-path
catches got in plan 41.2-01 and the subscribe form's catch got in 41.2-03: named at its
line, routed, unrepaired.
