## Summary

Phase 41.1 closed the work surface. What is left is **ten declarable page files and their
closures — 51 files, 9 650 lines**, carrying **183 raw palette utilities, 239 legacy token
utilities and all 16 remaining `sm:` uses in the tree**. Every one of the three ratchet
gates that still forgives a file (`verify-dialogs`, `verify-breakpoints`, and the manifest
itself) now forgives **only** files in this perimeter: `verify-tables` reached zero in
41.1 and closed its migration with a written decision, and the `work` group reads zero in
every gate that carries a group tag. **41.2 is the phase where the last three ratchets
either close or the criterion 3 sentence stops being true.**

Two structural findings change how the phase must be planned.

**First: the bar's money and the venue's address are not on the same page in the way the
roadmap sentence implies.** The bar's own QR surface, `/events/[slug]/menu` and its six
files, contains **zero occurrences of `venue` or `address`** — measured. The page where
money and the address genuinely meet is `/events/[slug]`: 1 283 lines, 15 unconverted
files in its closure, the drinks section and the three-branch venue block in one file, and
the only `force-dynamic` declaration among the ten. That page is the knot, and it is a
different unit from "the bar".

**Second: all ten surfaces mount `MobileNav` — the navigation wrapper locked to its phone
form — and its own docblock says Phase 42 deletes it** (`src/components/layout/MobileNav.tsx:29-33`).
Two consequences follow mechanically, not by opinion: check E of `verify-conversion`
asserts *focus width if and only if no navigation is mounted*, so **none of the ten can be
declared `focus`** while it mounts the wrapper — including `/tickets/[id]`, which already
writes the focus measure by hand twice. And RESP-01 says *usable on phone, tablet and
desktop*: a member on a 1440px screen currently meets a bottom bar and no column on every
one of these ten. Whether that is the intended end state is **the owner's decision and the
single largest one this phase carries**.

**Primary recommendation:** cut the phase into eight waves that put the three cheap public
surfaces first and the two money knots last — `/events/[slug]/menu` plus `/dashboard` in
one wave behind a shared money core converted once, and `/events/[slug]` alone in a wave of
its own, split across two plans on disjoint file sets exactly as 41.1 split the event form
from its satellites. Settle the navigation-form question and the two dead files **before**
wave 1, because neither is cleared as a by-product of any surface conversion and both block
criterion 3.

### 2.2 What mechanically has to change for a ratchet to become an absolute

This is a code question, and the answer is already written in the tree: **`verify-tables`
made the transition on 2026-08-14 and is the template.**

**The branch that forgives an empty list** is not the one that forgives a *listed* file —
it is the one that **refuses when the list empties**:

```
scripts/verify-breakpoints.mjs:661   if (REMAINING.length === 0) { refuse('REMAINING is empty. …') }
scripts/verify-dialogs.mjs:1471      if (REMAINING.length === 0) { refuse('REMAINING is empty. …') }
```

Both refusal texts say what to do in their own sentence: *"the emptiness should be a
DECISION written above the constant — not a list that quietly emptied itself while nobody
was reading."* Emptying the array **breaks the gate on purpose** (exit 2, nothing measured)
until the decision is written.

**`verify-tables` already did it**, and the shape is exact:

```
scripts/verify-tables.mjs:564-571    export const MIGRATION_CLOSED = { date, by, why };
scripts/verify-tables.mjs:721-742    if (REMAINING.length === 0) {
                                       const complete = c && typeof c === 'object'
                                         && typeof c.date === 'string' && c.date.length > 0
                                         && typeof c.by   === 'string' && c.by.length   > 0
                                         && typeof c.why  === 'string' && c.why.length  > 0;
                                       if (!complete) refuse(…);
                                     }
```

All three fields are required, so a truthy placeholder does not satisfy it. Above the
constant sits a 30-line docblock (`:534-563`) that answers the one question that matters —
**why an empty list does not become a number that lies** — with the arithmetic:

> *"This gate's check A is a TREE-SIDE accounting, not a list-side one… With the list empty
> the arithmetic is 2 = 1 primitive + 0 remaining + 1 exempt, and an eighth hand-rolled
> table added tomorrow makes check A fail as an unaccounted file — not as a missing list
> entry. The migration can therefore be closed without the gate losing its teeth."*

**So, for each of the two open ratchets, what "becoming an absolute" is, mechanically:**

| Gate | Precondition | The edit | Does it keep its teeth? |
|---|---|---|---|
| `verify-dialogs` | all 8 entries converted, deleted or exempted; gate prints each STALE first | delete the entries; add `MIGRATION_CLOSED = {date, by, why}` above `REMAINING`; extend the `:1471` guard to read it exactly as `verify-tables.mjs:721-742` does | **Yes.** Check B is tree-side: it opens 257 files and requires each shell to be the primitive, exempt, fenced, or on the list. With the list empty the gate becomes *"`sm:` appears nowhere"* — the gate's own header already names this outcome: *"this gate has become check A alone"* |
| the manifest | the 10 surfaces declared | ten entries appended to `CONVERTED`, each carrying `[route, pageFile, width, reason]`, the reason written **from the files that render** and not from the route | **Partially.** `checkManifest()` refuses on an empty list and on a missing path, but **nothing refuses on a page file that exists and is not declared.** There is no tree-side census of `page.tsx` against `CONVERTED` |

## 9. Common pitfalls

**P1 — A `REMAINING` count that falls because the gate stopped looking.** Four recorded
recurrences in this family (D-41.1-16). Both remaining lists print two numbers on purpose —
*entries declared* and the live count of declared files still carrying the thing. Every
reconciliation diffs the **entries against the tree**, never the counts, and re-derives with
a second instrument that does **not** use the gates' shared comment stripper.

**P2 — A joint obligation between two plans in one wave.** §1.7's five shared files. Wave 6a
exists to discharge it.

**P3 — A gate that goes red on a correct file.** §0 rule 3, and this repository's own record
at `verify-media-strip.mjs:51-62`. ~98 new touch targets (§2.3) is the highest-volume
opportunity this phase offers. Wave 0's dry run is the answer.

**P4 — A conversion that changes what a query returns.** `[slug]/page.tsx:421` is a
17-column select feeding a seven-branch predicate. Prove the column multiset unchanged over
comment-stripped source, the technique 41.1-22 used.

**P5 — Losing a fact that only one branch carried.** The three-branch venue ternary
(§3.3) and the five-branch payment callback are the same shape: branches that look
redundant and are the safety property.

**P6 — A `sm:` migration that changes the layout instead of the boundary.** All 16 remaining
uses are here. Twelve of them are absorbed and **deleted** by the Dialog primitive rather
than migrated to `md:` — the primitive owns the sheet-vs-window pair. Migrating them instead
of deleting them leaves a second author.

**P7 — Declaring a surface whose `loading.tsx` is not converted.** Now caught (§1.5), and
that is new since 41.1. Five files, 70 legacy tokens, 35 pulses.

**P8 — Fixing a silent failure while converting a class string.** §3.5. It is a behaviour
change on the money path delivered under a visual mandate. Record and route.

## Open Questions — for the owner, not for a planner

### D-1 — The navigation form on the public and member surfaces *(the largest)*

All ten mount `MobileNav`, the wrapper locked to the phone form, whose own docblock says
**Phase 42 deletes it**. Two answers, and both are defensible:

- **They stay on the bottom bar at every width.** Then RESP-01's *"usable on phone, tablet
  and desktop, with the layout chosen for the device the surface is actually worked on"* is
  ticked for a member on a 1440px screen who meets a phone bar — and that reading has to be
  written down, because it is not the reading Phase 41 applied to the work surface. And
  Phase 42 inherits ten mount sites it did not plan to delete a wrapper for.
- **They take `AppNav`'s responsive form**, as the work surface and `/gallery` did. Then each
  must **also** declare the column clearance at the tablet tier, because check E asserts the
  declaring set and the mounting set are **equal in both directions** — mounting without
  declaring puts content under a 224px column, loudly. Ten new declarations, and a real
  change to what every member and every visitor sees on a desktop.

**Consequence of leaving it open:** the wave cut does not change, but every plan in waves 1,
3, 5, 6 and 7 writes a navigation mount it may have to rewrite, and the RESP-01 pass cannot
state what it is looking for.

### D-2 — The `wide` and `focus` lists are closed. Do any of the ten open them?

Default is 1024px for all ten. Two candidates, and one is coupled to D-1:

- **`wide` (1280px):** `/events` — a multi-column grid of nights, which is §4's stated
  criterion for the form — and possibly `/dashboard`.
- **`focus` (384px):** `/tickets/[id]` **already writes the focus measure by hand, twice**.
  But check E forbids `focus` on any surface that mounts a navigation, so this is only
  available if D-1 removes the navigation from that surface — which is a different and
  larger change than a width.

**Consequence of leaving it open:** every surface takes `default`, which is an answer and not
a fallback (§4). It is reversible: one line in the shell's call, no page declares a width.

### D-3 — The two files nothing imports

`GuestLoginBanner.tsx` (155 lines, on **two** ratchet lists, its import commented out with
*"re-enable by restoring this import"*) and `RefundRequestButton.tsx` (90 lines, on the
dialogs list, **no importer at all**, and its entry reads *"money leaving"*).

Three dispositions, all defensible: **convert** them (spends work on code nobody runs, and
keeps the re-enable path warm), **delete** them (removes the re-enable path, and a deletion
on a public repo is a publication of the decision), or **move them to a declared permanent
exemption** with a written reason (the shape `Lightbox.tsx` already has, and its own rule —
*"a file that will never convert is not a debt"* — is the argument for it).

**Consequence of leaving it open:** two ratchets cannot reach zero and criterion 3 does not
close. This one **blocks**, which is why it is in wave 0.

*(Sub-question, cheap: `/tickets/[id]` renders a venue line and is dynamic by derivation
only. Declaring `dynamic` on it is one line and closes the same gap D-37-09 closed for the
event page.)*

### D-4 — May a worktree run the application against `.env.local`?

This checkout **holds the credentials that no worktree in Phase 41 or 41.1 held**. With
them, `npm run dev` runs and a meaningful fraction of §5's rows becomes headless-measurable
— the precedent exists, since `41-CR01-PASS.md` rows 1–6 read *"measured, headless"*.

It also **points a running application at production**, which `41-CR01-PASS.md` states
requires an authorisation no agent held, and this repository has an incident (D12) in which a
verification deleted 63 rows across seven tables.

**Consequence of leaving it open:** the phase plans as Phases 41 and 41.1 did — every human
row `pending`, batched to the end-of-v1.5 sitting, RESP-01 waiting on a person. That is the
safe default and this research assumes it.

### D-5 — One pass or two, and does 41.2's absorb the thirteen?

§5.4 recommends **one sitting, two documents**, with the reason. The alternative — one
document — is not wrong; it is a different trade between a phase gate that can close on its
own evidence and a requirement that closes on the union of everyone's.
