# Phase 41.2 Plan 14: The Dashboard's Satellites Summary

Six files converted; the tree's only hand-rolled role-marked overlay stops
declaring a shell of its own by **delegating to the file already declared
permanently exempt** — decided in writing before the diff — and three

## 1. The decision this plan owned, written before the diff

### The disposition: **delegate to the exempt viewer**

`src/components/media/MyMediaSection.tsx` is one of the pattern map's three
declared gaps (§6.1), and it is a gap because the gate and the tree point in
different directions. `scripts/verify-dialogs.mjs:468-472` names it as **Exception
2 — NOT exempt**, on `REMAINING`; fourteen lines above, `:474-478` declares
`src/components/media/Lightbox.tsx` **permanently exempt**, with its own rule:

> *"a full-bleed media viewer at every tier, carrying a heavier scrim than a
> sheet … deliberately NOT on REMAINING: a file that will never convert is not a
> debt, and a list that can never reach zero is a number that lies"*

Three dispositions were open. **Converting it onto the dialog primitive** would
put a sheet-and-window panel around a full-bleed photograph — the *correct file
goes red* shape `41-UI-SPEC.md` §0 rule 3 forbids, and it would be the same
argument the exemption fourteen lines up already won. **Declaring an exemption of
its own** was available and was **refused**: D-41.2-06 grants an exemption *per
file, on that file's own argument, or it becomes a way to make a list empty*, and
this file has no argument for permanence — it has an argument for **delegation**,
which is a stronger outcome, because it removes the shell instead of blessing it.
The debt list then falls **honestly**: the entry goes stale because the shell is
gone, not because the gate stopped looking.

So the road taken is the one the tree already walks. Two files import that
viewer, and one of them is **inside this phase's own perimeter** —
`(public)/events/[slug]/MediaGallerySection.tsx:73-80`. No exemption was widened.
No gate was edited.

### What was measured to choose it

The disposition did not rest on the reading alone. Both files were read in full
first, and the two overlays compared on the three axes that decide whether the
behaviours line up:

| Axis | The incumbent overlay (`:179-202`, pre-conversion) | `Lightbox.tsx` |
|---|---|---|
| **What it shows** | full-bleed photo at a translucent black scrim, close cross, `stopPropagation` on the image | full-bleed photo **or** video at a translucent black scrim, close control, backdrop-click guarded by `e.target === e.currentTarget` |
| **How it closes** | backdrop click and the cross. **Escape does nothing** — it is a `<div>`, so the two modal attributes it carried asserted a contract nothing implemented: no focus trap, no background inertness, no top layer | native `<dialog>` + `showModal()`, so **Escape, the focus trap, background inertness and the top layer arrive from the platform** |
| **On a phone** | close control was a text glyph with **no declared minimum** | the shared icon rung at **44 x 44** |

Delegation is not a lateral move on any of the three: it is strictly better on
all three. That is the measurement that decided it.

### The two item shapes, quoted

`LightboxItem` — `src/components/media/Lightbox.tsx:39-42`:

```ts
interface LightboxItem {
  url: string;
  type: "photo" | "video";
}
```

`MediaItem` — `src/components/media/MyMediaSection.tsx:8-15` (unchanged by this
plan):

```ts
interface MediaItem {
  id: string;
  url: string;
  type: "photo" | "video";
  status: "pending" | "approved" | "rejected";
  file_size: number | null;
  created_at: string;
}
```

**They matched.** `MediaItem` is a **structural superset** of `LightboxItem` —
the same two field names, the same literal union, so it is assignable as-is and
**nothing had to be bridged**. It is nevertheless shaped explicitly at the
hand-over, exactly as the perimeter sibling shapes it, so the four fields the
viewer has no use for do not travel into it:

```tsx
item={lightboxItem ? { url: lightboxItem.url, type: lightboxItem.type } : null}
```

No edit to the viewer was needed, and none was made — which matters, because
editing it would have been a HALT: it is a declared permanent exemption and its
exemption is a decision this plan does not own.

### One behaviour deliberately not widened

The viewer can play video. **This call site still hands it nothing but photos**,
because the incumbent guarded on `item.type === "photo"` and widening what opens
is not a rendering change.

### D-41.2-14-B — one badge tone for three moderation states

The three badges were a yellow, a green and a red. `Chip.tsx:246-254` states that
the badge fill means *look here first* and that **there is deliberately no tone
per outcome**. Assigning one colour per moderation state would settle in CSS a
grading the primitive refuses to carry, and reaching for `className` to do it
anyway would be circumventing a declared decision rather than using a primitive.
All three take the neutral tone; the word itself is the channel, which is the
direction §10 asks for regardless — colour is never the only one.

### D-41.2-14-C — log out is not destructive

Hard constraint: *the destructive rung is for acts that destroy.* Signing out
destroys nothing — the account, its tickets and its uploads are where they were,
and the act is undone by signing back in. Painting it in the critical semantic
would spend, on a reversible act, the one colour this system has for saying *this
cannot be taken back*. **This is a visible change**: the control is no longer red.
