> ## ⚠ Check E uses two different meanings of "mounted", and one of them will mislead you
>
> **Measured in wave 0** (`41.2-WAVE0-FINDINGS.md`). `scripts/verify-conversion.mjs`
> reports the navigation question twice, and the two answers disagree today:
>
> - its **route table** already prints all ten of this phase's surfaces as *mounting* a
>   navigation — because they reach one through `MobileNav`;
> - its **pairing check** uses `importsDirectly`, so those same ten count as **not
>   mounting**.
>
> **The failure this sets up:** a plan that reads the route table concludes the surface
> already mounts a navigation and therefore needs no clearance declaration — then ships
> the loud red, which at 768px is **content sitting under a 224px column**.
>
> **Mounting, for every assertion in this plan, means importing `AppNav` DIRECTLY.**
> Reaching it through `MobileNav` does not count. The pair is two halves and check E
> fails on either half alone:
>
> 1. `LC_ALL=C /usr/bin/grep -c 'layout/AppNav'` on the page file → **1**
> 2. `LC_ALL=C /usr/bin/grep -c 'layout/MobileNav'` on the page file → **0**
> 3. the tablet-tier clearance utility present, copied byte-identically from
>    `src/app/(public)/gallery/page.tsx:110`, on a `div` wrapping the shell with the
>    navigation as its **sibling**
>
> Pairing baseline is **2/2** (the two surfaces that already declare); the target at the
> end of the phase is **12/12**.
>
> **Read `scripts/verify-conversion.mjs` with `LC_ALL=C /usr/bin/grep` or the Read tool** —
> it holds two NUL bytes and the shell's default `grep` skips it silently, returning
> nothing with no error.

> **`npm run verify` cannot exit 0 inside a worktree, and that is expected.**
> Measured in wave 0: `verify:capabilities` **refuses with exit 2** when `.env.local`
> is absent, printing *"Nothing was measured"* **before touching anything**. A
> worktree has no `.env.local`, and putting Supabase credentials into one is
> forbidden by **D-41.2-04** — the road that does not touch production. So the
> executor-side bar is:
>
> **all 15 gates that reach a verdict pass, 0 fail, and `verify:capabilities`
> refuses for want of credentials.** A refusal that names its missing input is a
> gate declining to measure, not a gate failing — and it is distinguishable from
> both a pass and a failure, which is the whole point. Quote the tail of the run
> showing the counts.
>
> **Do not make it green.** Not by adding credentials, not by skipping the gate,
> not by rewording the criterion. The full 16/16 suite is run by the orchestrator
> in the main checkout after this wave merges, where `.env.local` exists.


> **Findings go in this plan's own file, not in the shared one.** This plan may run
> in parallel with another plan in its wave, in a separate worktree. Two worktrees
> appending to one shared file is a merge conflict on an append-only document — the
> exact hazard the intra-wave overlap rule exists to prevent, and the previous phase
> avoided it only by luck (its one recorded finding came from a plan that happened to
> be alone in its wave). Write to `.planning/phases/41.2-public-member-and-money-surfaces/41.2-07-FINDINGS.md`, which this plan owns
> exclusively. **Plan 41.2-20 consolidates every `41.2-*-FINDINGS.md` into
> `deferred-items.md` in wave 8**, where nothing runs beside it.
