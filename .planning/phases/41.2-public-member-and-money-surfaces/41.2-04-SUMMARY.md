`size="lg"` is checkable rather than argued: `Dialog.tsx:161-166` names this file

**The dialog pattern, point by point.** The confirming control (`Save`) sits on
the **primary** rung with `form={FORM_ID}` — outside the `<form>`, because the
primitive puts `actions` below the scroller and a submit written inside would
scroll away. `data-initial-focus` is declared **once**, on **Cancel**, so the key
that arrives before anyone has read the panel is not the key that saves. The
refusal is the primitive's `status` region, which sits **outside the scroller**
(`Dialog.tsx:316-325`) and renders `role="alert"` for the critical tone — never a
toast, which a native dialog would paint over. `close()` resets the refusal on
every route out, so no stale sentence survives to the next open.

**Save is not on the destructive rung, and that is a recorded refusal**
(**F-41.2-04-04**): `destructive` is `bg-sem-crit`, reserved by §5.1 for an act
that destroys, and the named analog — `EditVenueButton.tsx:237-244`, *"the same
file with different nouns"* — renders its Save on primary. Painting a red fill on
a bio save would have been a visual regression decided by an executor.
