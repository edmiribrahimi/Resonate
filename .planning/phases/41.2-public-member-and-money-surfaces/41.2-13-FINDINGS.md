## F-41.2-13-03 — The clearance grep returns **2**, and so does the specimen it is checked against

**Severity:** informational; it corrects an acceptance criterion's arithmetic rather than
the tree. **Disposition:** recorded, and the criterion is reported satisfied against the
measurement it actually means.

The criterion reads *"`grep -c 'nav-inset-inline-start'` returns exactly **1**, byte-identical
to `src/app/(public)/gallery/page.tsx:110`"*. Both halves cannot hold at once, because the
specimen itself returns **2**:

```
$ LC_ALL=C /usr/bin/grep -c 'nav-inset-inline-start' 'src/app/(public)/gallery/page.tsx'
2
$ LC_ALL=C /usr/bin/grep -c 'nav-inset-inline-start' 'src/app/(members)/dashboard/page.tsx'
2
```

The second hit in each file is the **custom property named in prose**, inside the comment
that explains the declaration — `gallery/page.tsx:99` and the corresponding line here. It
is a property name, not a class string, so DEF-41-01 is not engaged: Tailwind compiles a
*utility* out of a comment, and a bare `--property` is not one.

The number the criterion means is the count of the **live utility**, and it is 1 in both:

```
$ LC_ALL=C /usr/bin/grep -c 'md:[--nav-inset-inline-…'  (both files)      → 1
$ node scripts/verify-conversion.mjs
      bracketed declaration(s) of the inline axis found : 10   (264 file(s) read, comments blanked)
```

The gate blanks comments before it counts, which is why it reads 10 across 10 files rather
than 20. **A criterion that a correct file cannot satisfy is the shape §0 rule 3 warns
about**, and the honest resolution is to report both numbers rather than to pick the one
that reads better.

The two declaration lines are byte-identical, proved rather than eyeballed:

```
$ sed -n '110p' 'src/app/(public)/gallery/page.tsx'      | shasum -a 256
$ sed -n '359p' 'src/app/(members)/dashboard/page.tsx'   | shasum -a 256
0050d1d2c973acfeb63de00eced17839960e9431741c9a7bb8aad368435d9166   (both)
```

## F-41.2-13-05 — A fifth catch of the same family **does** live on this surface, and it is on money

**Severity:** real, and it is the one finding here that costs a member something.
**Disposition:** **recorded, not repaired.** Repairing it is a decision about what a
person is told when a read of their own purchases fails, and this is a visual conversion.

`src/app/(members)/dashboard/page.tsx` performs four reads and **discards the error object
on every one of them**:

```
$ LC_ALL=C /usr/bin/grep -n 'const { data' 'src/app/(members)/dashboard/page.tsx'
173:  const { data: profile } = await supabase          ← the profile
200:    const { data } = await supabase                 ← the member's tickets
214:    const { data: allTokens } = await supabase      ← the member's DRINK TOKENS
256:  const { data: myMedia } = await supabase          ← the member's uploads
```

**The consequence, on the token read specifically.** If that query fails, `allTokens` is
`null`, the grouping below coalesces it to `[]`, `drinkTokenGroups.length > 0` is false, and
the *My Drinks* section **is not drawn at all**. A member who paid for drinks and whose read
failed sees a dashboard that looks exactly like the dashboard of a member who bought
nothing. The same shape holds for the ticket read: a failed read renders *No tickets yet*
beside a link inviting the person to discover events.

**Why that is worse than the ordinary version of this defect.** There is no error tracking
in this repository, so the failure reaches nobody by itself; and the wrong answer here is
not a blank screen a person distrusts — it is a **confident, well-formatted, wrong
statement about what they own**. `meta-gates.md` is explicit that a failure that matters
needs an observable effect and that "log it" is not sufficient. This one does not even log.

**Why this plan did not fix it.** Distinguishing *you have no tokens* from *we could not
read your tokens* is new copy on a money surface, it needs a sentence that does not
manufacture alarm, and it needs the same treatment on all four reads or it is an
inconsistency instead of a fix. That is the same reason the four recorded catches were
recorded rather than fixed — a visual conversion is not where the product decides what a
buyer is told when a read fails. **Route: the plan that owns the dashboard's error copy.**

**Status: recorded. NOT fixed.** Nothing about it changed in either direction: the four
reads are unchanged context lines in the diff.

## F-41.2-13-06 — The disclosure control refused the button ladder, and the reason is the rung

**Severity:** a refused conversion, stated as one. **Disposition:** decided in the file,
with the argument written into its docblock.

`DashboardDrinkTokens.tsx`'s *Completed (N)* toggle was a raw `<button>` carrying
`border border-card-border` — **a line token on an operable control**, which is finding
A1's exact shape and is not in question: it moved to `border-control`, 7.14 : 1 against a
line token's ceiling of 1.39 : 1, and WCAG 1.4.11 asks 3 : 1.

**What was refused is the rung, not the token.** Every size in `Button.tsx:86-91` is
`rounded-full`, and this is a full-width disclosure bar with a chevron that rotates.
Two roads were available and both are worse than the third:

- **append a container radius to a rung** — it would depend on which of two same-property
  utilities Tailwind emits last, the named-value ordering defect `Skeleton.tsx:60-81`
  measured in the emitted sheet on 2026-08-12 and `DrinkTokenCard.tsx:81-87` records again;
- **take the pill** — a full-bleed lozenge where a bar was, which is a visual decision
  nobody asked this plan to take.

So it stays a raw element, **declares the 44px floor itself** and **imports** the focus
expression rather than re-spelling one. That is the same reasoning shape as plan
41.2-07's D-41.2-07-B, where the referral input stayed raw because the primitive could not
carry the thing that mattered: the primitive is adopted where it fits, and where it does
not the reason is written down instead of the element being bent to fit.

## F-41.2-13-07 — The two quick-action tiles took the **line** primitive, on a box measurement

**Severity:** informational. **Disposition:** decided, with the measurement.

The loaded tile fixes its own height at 96px. The card placeholder
(`Skeleton.tsx:123-133`) draws **three** lines inside 24px of padding — roughly 124px —
so `SkeletonCard` inside a 96px box overflows it. A placeholder that does not occupy the
box it stands in for **reintroduces the jump it exists to prevent**, which is the
primitive's own stated contract. The two tiles therefore take `SkeletonLine` at
`h-24 w-full`: one raised block, the exact box, no hand-rolled pulse.

The ticket rows take `SkeletonCard` unmodified, following
`(work)/members/loading.tsx:70-74` — there the loaded row is a card too.

**No radius is appended at any of the eleven call sites** (DEF-41-05, still open):

```
$ LC_ALL=C /usr/bin/grep -c 'rounded' 'src/app/(members)/dashboard/loading.tsx'   → 0
```

## F-41.2-13-08 — One behaviour was added, and it is named rather than smuggled

**Severity:** an addition, declared. **Disposition:** kept.

The disclosure toggle announced its open/closed state through **one channel only** — the
rotation of a chevron. `41-UI-SPEC.md` §10 and `40-UI-SPEC.md` before it state that colour,
and by extension any purely visual signal, is never the only channel. `aria-expanded` was
added, carrying the same boolean the rotation already carried.

It is the only behaviour this plan adds, it changes no wording, it moves observability in
the direction `meta-gates.md` asks for, and it is recorded here rather than left for a
reader to find in a diff — the same treatment plan 41.2-10 gave the one `role="alert"` it
added on the bartender's screen.

## F-41.2-13-09 — Two accent marks lost their hue, and the loss is the decision

**Severity:** a visual change, declared. **Disposition:** applied, with the contract's own
sentence behind it.

Three marks on this surface were tinted: the **role** mark in the header (accent), the
**Upcoming** mark on a ticket row (green) and the **tier name** mark beside it (accent).
All three state something and none can be operated, so all three are `Badge` and not
`Chip` — `Chip.tsx`'s own opening sentence — and the neutral badge is the only tone that
does not grade an outcome. Two reasons, both already written down elsewhere:

- **`--accent` is not a state signal.** §5.1 reserves it for four things and names a state
  signal among the ones it is never for; `Chip.tsx:256-257` says neither badge tone uses it.
- **D-41.1-25 refuses a tone per outcome.** `DrinkTokenCard.tsx:30-37` made the same trade
  one wave earlier, on the same surface's own rows, and states it as *two hues lost, and
  the loss is the decision*.

In every case the **word** was already the channel that carried the meaning, and the word
is unchanged.
