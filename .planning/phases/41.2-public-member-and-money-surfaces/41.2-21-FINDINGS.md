## F-41.2-21-01 — The seven reds were **two problems wearing one number**, and writing them as one list would have hidden the one that matters

F-41.2-19-01 named seven elements at `file:line` and called them, correctly, a
decision for a person. What that finding could not do — because it was reporting
rather than resolving — is say **how many kinds of thing the seven are**. They
are two, and the count is the finding:

| Kind | How many | What it is |
| --- | --- | --- |
| **the gate cannot READ the box** | 5 | the box is comfortably above the floor and is decided by something that is not a height utility |
| **the product went UNDER the floor on purpose** | 2 | the element really is small, by decision, because the floor would make the act easier |

**These have opposite directions and opposite remedies.** The first five are the
gate reddening on correct code — the failure mode `41-VALIDATION.md` rates as
G5's highest risk and D-41-19 names outright: *a gate that fires on correct code
gets switched off, and a switched-off gate guards nothing while looking like it
does.* The remaining two are the opposite: the code is deliberately outside the
contract, and the honest disposition is to **say so loudly**, not to absorb it.

**A single list of seven would have been the cheaper edit and the worse
artefact.** Its seven reasons would all have read as *"G5 could not measure
this"*, and the two that are an accessibility exception would have been filed
under a parser limitation — which is precisely how an exception stops being
revisited. The distinction is now mechanical: two constants, two docblocks, two
sections of the report, and the second printed in a framed banner on every run.

## F-41.2-21-02 — The load-bearing fact for entries 1 and 3 is that they are the **largest** targets in the product, and the gate was calling them too small

`RedeemConfirmationModal.tsx:207` and `GuestTokenDisplay.tsx:284` are the
bartender's serve areas. Read at the element:

```
$ LC_ALL=C /usr/bin/sed -n '205,212p' 'src/app/(public)/events/[slug]/RedeemConfirmationModal.tsx'
      <div className="fixed inset-0 z-[100] flex flex-col bg-ground/95 backdrop-blur-md">
        {/* Big tap-to-serve area: takes the whole screen above the Cancel row */}
        <button … className="flex flex-1 flex-col items-center justify-center px-6 …">
```

A `flex-1` child of a `fixed inset-0 flex flex-col` parent **is** the screen
minus one row. G5's own opening box has named this shape as unreadable since
before its first execution — *"It cannot see a flex stretch"* — so the red is not
a discovery about the product. **A gate that prints "no unprefixed height
declaration — every target is 44px unconditionally" against the biggest target in
the product is a gate teaching its reader to stop believing it**, and the cost of
that is not the seven lines: it is every future red on the same gate.

Recorded because it is the argument that makes exemption 9 a correction rather
than an indulgence, and because it is the sentence a reviewer will want tested
against a device: **if the serve area is not the full screen its comment claims,
exemption 9 is wrong and only H41-4 can say so.**

## F-41.2-21-03 — Exemption 7 could have absorbed the file input in one character, and that is exactly why it did not

`MediaUpload.tsx:610` is `type="file" className="hidden"`. Exemption 7 already
forgives `type="hidden"`, and the two facts are the same fact: **no box, not a
target.** Widening 7 to also read a display utility would have been a one-token
edit, would have cleared the red, and would have been wrong for a reason the gate
already wrote down about itself:

> *an input carrying this attribute AND a height utility is a contradiction, and
> a contradiction is exit 2, never a silent exemption … the attribute cannot
> become a way past the measurement.*

That refusal works because 7 is an **attribute** test over one shape. Turned into
a test of *ways to be invisible*, its contradiction check no longer covers the
new members of the set, and the abuse route it was written to close reopens — a
gate weakened by an edit that looks like a generalisation. The element instead
takes a declared line in exemption 9, where a person reads it and where the
construction (`hidden`) is asserted present on the element itself.

**This is the gate's own prescription applied where it points**, and it is worth
stating that the cheap road here was one character, not a refactor: the size of a
tampering edit is no guide to its cost.

## F-41.2-21-04 — The drop zone shows why exemption 8 is not a catch-all for interpolation

`MediaUpload.tsx:578` interpolates a module constant (`FOCUS_RING`), so exemption
8 — *a call site whose declared minimum lives in a module constant* — looks like
the route. It is not, and the gate would have said so itself:

```
$ LC_ALL=C /usr/bin/grep -n "FOCUS_RING" src/components/ui/Button.tsx | head -1
71:export const FOCUS_RING =
72:  "focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ink";
```

No minimum in it. Exemption 8's **premise check** — *the constant not declaring
the minimum is a FAILURE, not a refusal* — would have fired and reported the
entry as a defect. **Correctly**: the drop zone's height is not in a constant, it
is in `p-8` on the element. Filing it under 8 would have produced a red with a
misleading reason, which is worse than the red it replaced.

Recorded because "it interpolates something, so it is exemption 8" is the
plausible wrong answer, and the gate's own guard is what rules it out.

## F-41.2-21-06 — **RESP-03 criterion 5 does not close, and exemption 10 makes part of it deliberately false**

RESP-03 reads *"Touch targets stay large wherever the input is a finger,
including large touch screens"*. After this plan:

- **two controls do not**, by decision, and the product says so in three places
  — the gate's constant, the gate's printed banner, and §13 entry 10;
- **nothing here measures a rendered box.** G5 asserts class strings, and the
  five elements under exemption 9 are now forgiven on a stated reason rather
  than measured. **H41-4, on a large touch screen, is still the only thing in
  this repository that would prove anything renders at 44px**, and it is still
  owed;
- `REQUIREMENTS.md` was **not** touched. RESP-03 stays unticked, and its
  traceability row still reads *"measured on a device"*. A green from a
  class-string gate is not that measurement, and marking it would be the
  quietest possible version of the defect this phase exists to remove.

**The two elements H41-4 should be pointed at first** are the serve areas: if
either is not the full screen its comment claims, exemption 9 is wrong about it
and no amount of reading the source will reveal that.

## F-41.2-21-07 — One gate's exemption cast a shadow on another's, and nobody had a mechanism to notice

This is the transferable finding, and it is not about touch targets.

D-41.2-06 and D-41.2-07 granted permanent exemptions to two files' **dialog
shells**, against `verify-dialogs`, on a domain argument about the shell. The
same screens' **controls** were never exempted from `verify-touch-targets`, and
**no plan in the phase noticed the second gate existed on those files** until
plan 41.2-19's declaration turned it red. F-41.2-19-01 called it exactly: *"the
exemptions cast a shadow on a second gate and the shadow was not anticipated by
any plan in this phase."*

**The partial mechanism this plan installs:** both new lists carry the
cross-reference in their docblocks, and §13 carries it in prose, so a person
moving either decision finds the other. **What it does NOT install:** anything
that would catch the *next* instance. There is no index of which gates read which
file, and an exemption granted in one gate still cannot know it has made a claim
another gate will test. That is unclosed, stated rather than papered over, and it
is a cheap thing to build the day somebody wants it — the manifest already knows
every file in scope, and each gate already prints its own exemptions.

## What this plan did not measure

- **Nothing here renders.** No dev server, no headless render, no browser
  (D-41.2-04). Every figure is a class string, a gate's own printed line, or an
  exit code.
- **`verify:capabilities` measured nothing**, as on every run in this phase, for
  want of `.env.local`. `npm run verify` therefore exits 2 with **15 passed / 0
  failed / 1 refused**, which is its honest state on a machine without those
  credentials. Supplying them would point a running gate at production and is
  forbidden.
- **No production read and no production write** of any kind.
- **No test runner exists for the product.** Nothing here is verified because
  tests pass; the verification is `npm run build` (exit 0), the gate's own exit
  code, and twelve asserted mutation cycles.
