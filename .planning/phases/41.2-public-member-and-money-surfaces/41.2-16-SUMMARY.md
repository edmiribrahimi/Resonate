the approved case. **Three before. Three after.** And more than a count: the chain's whole

**The two bullets, and the paragraph that explains their asymmetry** — quoted whole in the

They look like an unbalanced pair and they are correct: **a ticket unlocks immediately

## The focus decision, stated as a decision

```
$ LC_ALL=C /usr/bin/grep -c 'data-initial-focus'  <the file>   →  1
$ LC_ALL=C /usr/bin/grep -c 'autoFocus'           <the file>   →  0
```

The marker is declared **once**, on the way out, quoted whole:

```tsx
actions={
  <Button
    variant="secondary"
    className="w-full"
    data-initial-focus
    onClick={() => setOpen(false)}
  >
    Close
  </Button>
}
```

**Why declared rather than inherited, and why on that control.** This dialog has no
destructive control and no control that performs an act: its three answers are a way in, a
second way in, and a way out. §11's rule for a confirmation — *the cancel is the
initial-focus target and the confirming control is focused by nothing* — reads here as
*the way out carries the marker and neither road in may hold it*. `Close` is the only
control in the actions region, so it is first there; the primitive's own close control
precedes it in the DOM and is also a way out. A declared marker forces the author to say
which control is the least destructive and is the thing a person can grep — **one
mechanism, not two**, which is the precedent this project already corrected once, and the
inert framework attribute that made that pair ambiguous is absent here and was absent
before.

## Every string this dialog can render, branch by branch

Thirteen rows, one line each, in findings §9. The short version, and it is the same for
every row: **nothing beyond the hint the night's own author wrote.**

- The two words of the trigger and of the heading name **the absence** of a place.
- The night's own hint renders with a two-character prefix and **no** caption, label,
  tooltip or accessible description around it. *A hint made precise by its caption is a
  reveal with extra steps, and this conversion added no caption.*
- Every other string says **when** the address appears, never **what** it is. A duration
  is not a location.

**Proved mechanically, not by the table:**

```
before: 14 string(s)
after : 14 string(s)
multiset identical: true
```

Fourteen and fourteen, order discarded, text-bearing attributes included — which is how
the heading's move from a text node into the panel's `title` is accounted for rather than
appearing as a loss. *(The night's hint is a prop; its content is quoted nowhere in this
document or in the findings. `.planning/` is published.)*

**Twelve attributes added, and each names an action rather than a place.** The only one
carrying a string a reader sees is `title="Secret Venue"`, byte-identical to the deleted
heading's text. **No `aria-label`, no `aria-describedby`, no `aria-description`, no
tooltip, no placeholder and no helper line was added.** The panel did gain an accessible
name it never had — the primitive labels the dialog by its own heading — and that name is
the heading's own two words.

## Instruments, and why any of their zeros may be believed

Wave 4's corroborating instrument returned `0/0/0` on eight files including four with
visible overlays, because of a defect in itself. **So every instrument here proves itself
before it reports, in the same run, and exits 2 without printing a result if it cannot.**
None is a regular expression; all three parse the file with the compiler the build runs.

| Instrument | Negative fixture | Positive fixture(s) |
|---|---|---|
| the copy census | a file against itself → **0** ✓ | a word of copy changed → **1** ✓ · an attribute added → **18** ✓ · a branch condition rewritten → **differs** ✓ |
| the multiset | a file against itself → **identical** ✓ | one visible string cut → **differs** ✓ |
| the comment-blind diff | a file against itself → **identical** ✓ | a code change planted → **survives** ✓ · a comment change planted → **removed** ✓ |

**One instrument was discarded rather than reported.** A first attempt used a *line*-based
comment filter and returned 177 "non-comment" changed lines — most of them the interior
lines of block comments, which do not look like comments. A line filter cannot answer the
question the knot rule asks. Removing comment **ranges** instead gives the answer above,
and the wrong instrument's number is recorded here so nobody rebuilds it.
