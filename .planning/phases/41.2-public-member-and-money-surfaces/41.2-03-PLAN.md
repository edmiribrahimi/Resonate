## The navigation pair — the two halves, and they land in the same commit

This block is identical in every plan that owns a page file, and it is written out
each time on purpose.

**Half one — the mount.** Replace the phone-locked wrapper's import with a direct
import of `AppNav`, and the wrapper element with `AppNav`, passing **the same four
props in the same order** — the role, the status, the capability set, and the
live-assignment capability set. Verbatim analog:
`src/app/(public)/gallery/page.tsx:2` (the import) and `:125-132` (the mount).
The diff is smaller than it looks: plan 39-03 already threaded the capability set
through all thirteen mount sites, so every one of these page files passes exactly
that prop block today. **Mounting means importing `AppNav` DIRECTLY** — check E's
`importsDirectly` at `scripts/verify-conversion.mjs:2803-2809` does not count
reaching it through the wrapper.

**Half two — the declaration.** One `div` wrapping the **shell**, carrying the
single bracketed arbitrary-property utility that sets the inline-start
navigation inset at the `md` tier and no other. **Copy the line verbatim from
`src/app/(public)/gallery/page.tsx:110`.** A declaration at another variant is
reported separately as off-tier, not silently excluded.

**Two placement rules, each of which ships a red if it is got wrong:**

1. **The declaring wrapper wraps the SHELL, not the navigation.** In `/gallery`
   the navigation is a **sibling** of the declaring `div`, at `:110-132`. Putting
   it inside would still pass the textual pairing and would pad the column by its
   own clearance.
2. **The navigation is a sibling of the shell, not a child of the old page
   root.** Eight of the ten surfaces render the wrapper inside their
   `min-h-dvh` root today. That root is deleted by the shell adoption, so the
   mount **moves up a level** into a fragment — the shape at
   `src/app/(public)/gallery/page.tsx:88-133`.

**What the move does not change** (UI-SPEC §0 rule 5): **width may change layout,
never membership.** The server decides which navigation entries exist; CSS decides
how they sit. `AppNav` receives the same four props the wrapper received, so no
entry appears and none disappears — and that sentence goes into the SUMMARY in
the *no capability check touched* position.
</conversion_rules>
