> **How this document was produced, because the method is part of the decision.** The owner

> decide on deep research. So the research ran **first**, the five open questions it raised

> reversible in the way its entry states. That split is the point: `checkpoint-delegation`
> says a technical checkpoint is the expert's and the road that does not touch production is
> the one to look for — and D-4 is exactly that shape.

<decisions>
## Implementation Decisions

### D-41.2-01 — The navigation takes its responsive form on all ten *(owner, 2026-08-14)*

All ten surfaces mount `MobileNav`, the wrapper locked to the phone form, whose own docblock
says Phase 42 deletes it. **They take `AppNav`'s responsive form**, as the work surface did
and as `/gallery` — a public surface, already converted — already has.

**What it costs, and it is not optional:** each of the ten must **also declare the column
clearance at the tablet tier**, because check E asserts the declaring set and the mounting set
are **equal in both directions**. Mounting without declaring puts content under a 224px
column, loudly. Ten new declarations.

**Why it was the owner's and not the expert's:** it changes what every visitor and every
member sees on a desktop. The events page is the funnel into the community, and a public page
that presents a phone bar on a 1440px screen reads as broken at the exact moment the product
is making its first impression.

**What it unlocks:** RESP-01 can close **in its own words** rather than by a reading that
would have had to be written down — *"usable on phone, tablet and desktop, with the layout
chosen for the device the surface is actually worked on"* — and it is not the reading Phase 41
applied to the work surface. It also spares Phase 42 ten mount sites it never planned to
delete a wrapper for.

### D-41.2-02 — Every surface takes the default width; `wide` and `focus` stay closed

Default 1024px for all ten. **This is an answer, not a fallback**, and it is reversible in one
line of the shell's call — no page declares a width.

Two candidates were considered and both are deferred, not rejected: `/events` for `wide`
(1280px — a multi-column grid of nights, which is §4's stated criterion), and `/tickets/[id]`
for `focus` (384px — the surface **already writes the focus measure by hand, twice**). The
second is not merely deferred but **unavailable**: check E forbids `focus` on any surface that
mounts a navigation, and D-41.2-01 mounts one on all ten.

Revisit after wave 0's dry run produces real numbers, if it produces a reason.

### D-41.2-03 — Both unreachable files are **converted**, not deleted and not exempted

`GuestLoginBanner.tsx` (155 lines, on **two** ratchet lists) and `RefundRequestButton.tsx`
(90 lines, on the dialogs list, entry reads *"money leaving"*). Neither is reached by any
closure, so **no surface conversion clears either as a by-product** and **criterion 3 cannot
close without an explicit disposition.**

**Converted, for one reason: it is the only disposition that is reversible and that decides
nothing outside this phase.**

- **Delete** would answer a product question — *should these features exist?* — that is not
  this phase's to answer, and on a public repository a deletion is a publication of the
  decision.
- **Permanent exemption** would be a lie about `GuestLoginBanner`, whose import is commented
  out with *"re-enable by restoring this import"*. The exemption's own rule is *"a file that
  will never convert is not a debt"*, and this one is meant to come back.
- **Convert** costs 245 lines, clears both ratchets, and leaves the re-enable path warm: when
  the banner returns it lands already converted instead of reopening a gate that had closed.

If the owner later wants either deleted, deleting a converted file is trivial. The reverse is
not.

### D-41.2-04 — No worktree runs the application against `.env.local`

This checkout holds credentials no worktree in Phase 41 or 41.1 held. With them `npm run dev`
runs, and a meaningful fraction of the human rows becomes headless-measurable — the precedent
exists, `41-CR01-PASS.md` rows 1–6 read *"measured, headless"*.

**It also points a running application at production.** `41-CR01-PASS.md` states that
requires an authorisation no agent held, and this repository has an incident — D12 — in which
a verification deleted 63 production rows across seven tables, of which the 63 were never
recovered because PITR is not enabled.

**Decided: no.** The phase plans as 41 and 41.1 did — every human row `pending`, batched to
the end-of-v1.5 sitting. The safe default is also the road that does not touch production, and
when those two coincide the decision is not close.

*This is a standing decision for the phase, not a permanent one. If the owner authorises it
later, it is a new authorisation, spent once, for what was described when it was asked.*

### D-41.2-05 — One sitting, two documents

- **`41.2-RELEASE-PASS.md`** covers this phase's ten surfaces and **closes the phase gate
  only**. Its frontmatter says so. It is the document a blanket owner approval may close.
- **The RESP-01 closing pass** is the document that **ticks RESP-01**, and its rows are the
  **union**: the thirteen already owed (seven from Phase 41, six from Phase 41.1) plus this
  phase's ten surfaces.

Both go into the **same sitting** — the one `41-RELEASE-PASS.md`'s `batch:` field already
commits alongside `40-RELEASE-PASS.md`, `39-DOOR-PASS.md` and `38-PROCEDURES.md`. A second
sitting would not add attention, it would split it.

**Why two documents and not one:** a document that ticks a requirement must contain the union
of that requirement's evidence, or it ticks something it did not measure. A document that
closes a phase gate must be closable on the phase's own work. **Phase 41 lost exactly this
distinction** — one approval, one document, a phase marked closed with four criteria still
unticked. Two documents make the two acts separable, and make it visible when only one of them
happened.

<constraints>
## Binding constraints, carried forward as stop conditions

These are not style preferences. Each one has a recorded incident or a domain gate behind it.

1. **The venue reveal is monotone.** `venue_reveal_sent` is one-way; once the mail is sent the
   address is public and there is no undo. On `/events/[slug]` this means, concretely and
   asserted after every diff that opens the file:
   - the three-branch ternary at `:1075-1119` **stays three branches**;
   - the reveal test at `:206-207` **stays written positively** — the file says why in place:
     `undefined !== null` is TRUE, so a negated null test plus a dropped column opens every
     secret night;
   - `export const dynamic = "force-dynamic"` at `:243` **stays present**;
   - **no plan adds a `generateMetadata`** to this route. Its absence is a decision (T-37-25),
     and a social preview carrying a secret address is a publication.

2. **Money does not trust its announcer, and no plan here touches money's code.** No server
   action is in the visual perimeter. If a plan finds it must open one, that is **stop
   condition 2** — halt and report, do not proceed.

3. **41.2 does not edit the spine.** Four files bridge to Phase 42. Needing to edit one is a
   **halt**.

4. **Zero silent failures, and there is no error tracking.** No monitoring dependency exists,
   so no production error reaches a human by itself. "Log it" is not sufficient — a failure
   that matters needs an observable effect. The four existing violations on the money path are
   **recorded, not fixed** (see Phase Boundary).

5. **A `REMAINING` list at zero is a claim, not evidence.** This repository has watched the
   debt-goes-quiet defect return through **four distinct mechanisms**. Every ratchet closure
   must be proved by asserted mutation — and the mutation asserted **applied** before its
   result is read, because a substitution that silently failed to match has already produced a
   false negative here.

6. **⚠ `scripts/verify-conversion.mjs` is invisible to the shell's default `grep`.** Two
   literal NUL bytes (the `permitKey` joiner); the default `grep` is `ugrep -I`, which skips
   binary files **silently**. Use `LC_ALL=C /usr/bin/grep` or the Read tool. The file now
   carries a notice at its head. A zero-hit grep there is not evidence of absence.

7. **`.planning/` is public.** Every plan, summary and verification here is a publication.
   Roles, never people. No venue under negotiation, no unannounced date, no line-up, no
   contact.

8. **No test runner exists.** Verification is `npm run build`, the gate scripts, `npm run
   verify`, and written manual procedures. Never write that something is verified because
   tests pass.

</constraints>

  end where they strand criterion 3.

  split the event form across 41.1-18 and 41.1-19.

  own counts, and with a second instrument that does not use the gates' shared comment
  stripper (D-41.1-22).

  three stop conditions: the shared money core, `/events/[slug]`, and `SecretVenueDialog`.
- 39 of the tree's 47 hand-rolled `animate-pulse` blocks are in this perimeter. `Skeleton.tsx`
  exists; D-41-04's recorded failure is a primitive that is correct and has zero importers.
