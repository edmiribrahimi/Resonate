## F-41.2-07-01 — the referral control reports success it did not have

**Where:** `src/components/membership/CopyReferralLink.tsx:76-83` (post-conversion
line numbers; the same statements sat at `:25-32` before this plan).

**Measured.** The confirmation is set **unconditionally**, after a `try` whose
`catch` runs a fallback that can itself do nothing:

- the clipboard call can reject — that is the whole reason the `catch` exists;
- inside the `catch`, `inputRef.current` can be `null`, in which case **no copy
  is attempted at all** and the branch falls through in silence;
- `document.execCommand("copy")` returns a boolean saying whether it worked, and
  **the return value is discarded**.

Past all three of those, `setCopied(true)` runs on the next line regardless, so
the control says *Copied!* for two seconds whether or not anything reached the
clipboard.

**Why it is worth an entry rather than a shrug.** The value on the clipboard is
the community's entry path. A person who believes they have copied a referral
link and pastes nothing sends an empty message to somebody they meant to invite,
and finds out — if ever — from the person who did not arrive. This repository has
**no error tracking** (`meta-gates.md`, verified 2026-08-05), so nothing here
reaches a human by itself: the only observer of this failure is the person in
front of the control, and the control is currently telling them it worked.

**Why this plan did not fix it.** Two reasons, both structural:

1. It is **pre-existing** — the three statements are byte-identical to the ones
   this plan inherited, and the filtered diff in the SUMMARY shows the copy path
   untouched. A visual conversion that changed what a control reports would be a
   behaviour change wearing a conversion's commit message.
2. Fixing it properly means **telling the two failures apart in copy** — the
   clipboard refused, versus the fallback had nothing to select — which is a
   rewrite of this surface's words and belongs to a plan that owns that
   decision. Collapsing both into one new sentence would reproduce the newsletter
   precedent `CONCERNS.md` already records, which is the pattern this project
   has written down as not to be repeated.

**Where it belongs:** a plan that owns the referral surface's copy. Routed
through 41.2-20 into `deferred-items.md` in wave 8.

## F-41.2-07-02 — the card says `Resonate Member`, and the brand is `re:sonate`

**Where:** `src/components/membership/MembershipCardView.tsx:80` — the label
above the member's name, inside the card a person presents at a door.

**Measured.** The string is `Resonate Member`. `brand-visual-system.md`'s grafia
gate is unambiguous and applies **everywhere**, not only to artwork: *"Si scrive
`re:sonate` con la e normale — nelle grafiche, nell'app, nelle mail, in prosa,
ovunque."* The reversed `ɘ` lives only inside the drawn logo; the brand written
in text is `re:sonate`, lowercase, with the colon.

**Why it is recorded here rather than corrected.** It is **copy**, and copy is
not this plan's to move: the plan's mandate is class strings, JSX structure and
imports. It is also not a one-line fix in isolation — the same label almost
certainly recurs on other member-facing surfaces and in the e-mail templates, and
a brand correction applied to one of them makes the product inconsistent in a way
that is harder to see than the original error. `production-calendar.md`'s rule
for a sigla change applies to a wording change by the same logic: **the change is
accompanied by a census of where the old form has already gone out, and the
census is closed by declaring it closed.**

**Where it belongs:** a copy pass over the member-facing surfaces and the e-mail
templates, with the census. Routed through 41.2-20.

## F-41.2-07-03 — `/attendance` renders a stub, and the stub is the whole surface

**Where:** `src/app/(members)/attendance/page.tsx:66-67` — a `TODO` comment and a
hardcoded empty array literal, both inherited unchanged.

**Measured.** `attendances` is declared as an empty literal and nothing writes to
it, so **the empty branch is the only branch a member can ever reach**: the page
says *0 events attended* and *No attendance recorded yet* to every member,
including one who has been to every night. The list branch is real markup that
has never rendered.

**Why it is recorded.** `nextjs-architecture.md`'s empty-state gate names exactly
this shape — *"una lista vuota identica a una lista non ancora caricata e' un
guasto silenzioso con una faccia neutra"* — and this is the harder version of it:
a list that is empty because nobody wrote the query, wearing the face of a member
with no history. The surface is reachable in production today.

**Why this plan did not fix it.** Fetching attendance rows is a **query**, and
this plan changes no query and opens no server action (stop condition 2). It is
also not a conversion-shaped task: it needs a decision about what an attendance
record *is* — a scanned membership code at a door, a redeemed ticket, or an RSVP
— and that decision belongs with the door, not with a stylesheet.

**Note for whoever picks it up:** the list branch **was** converted by this plan
even though it does not render, because a branch that never draws still ships its
class strings to check A and check B. So the work waiting is the query and the
decision behind it, not the markup.

**Where it belongs:** a member-surface feature plan. Routed through 41.2-20.
