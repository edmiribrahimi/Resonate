in `NEVER_MEASURED_BY_B`, so check B's loop hit `continue` on both paths **before

| the same probe, with the corrected gate | 1 | 1, named at `:291` |

The middle row is the finding. `grep -c` returned **1** for the probe marker before

**Nothing was mis-forgiven on the day it was found.** Each file carries exactly two
hand-rolled shells plus one converted primitive. The finding is about the **next**
shell, on the surface where a drink token is served and reverted at a counter.

## F-41.2-22-03 — what the correction is, mechanically

`EXEMPT_SHELLS` — four entries, shape `[path, anchor, shape, reason]`.

| Entry | Shell | Anchor | Applied |
|---|---|---|---|
| 1 | `RedeemConfirmationModal.tsx:180` | the centring utility | 1× |
| 2 | `RedeemConfirmationModal.tsx:205` | the column utility | 1× |
| 3 | `GuestTokenDisplay.tsx:257` | the centring utility | 1× |
| 4 | `GuestTokenDisplay.tsx:282` | the column utility | 1× |

Check B **opens both files** (files opened went 255 → 257) and measures all four
shells. Forgiveness is asked **per shell**. A shell matching no anchor stays in the
measured set and reaches the undeclared-copy failure like any other.

**Five refusals guard the list**, each pointing away from a green: a path not on
disk; a path check B never opens (`neverOpenedReason()` **reused**, not re-derived —
WR-01 is the record of what two lists saying the same thing cost here); an anchor
matching **zero** shells; an anchor matching **two or more**; a resolved shell whose
**shape** is not the declared one. A sixth, post-loop, asserts that resolution and
the loop agree — an entry that resolved onto a real shell and then forgave nothing
means two paths reached the same shell and only one found it.

**The anchor is a layout utility and not a handler name, and that is a decision.**
The sibling gate anchors on `onClick={…}` because it resolves an ELEMENT — a whole
opening tag spanning lines. This gate resolves a LINE: `shellShapes()` reports the
line the three overlay parts appear on, and on these four shells that line holds the
class attribute and nothing else. An anchor a gate cannot read is not an anchor.
Both anchors are **assembled at run time** (DEF-41-01) and matched with the same
boundary guards `OVERLAY_PARTS` carries.

## F-41.2-22-04 — the two reasons stayed distinct, and became four

D-41.2-06 and D-41.2-07 were granted separately, on separate arguments, by two
executors in separate worktrees with no contact — and the second declined the
first's precedent while re-deriving its own. **Collapsing them into one reason cited
twice would erase the only thing that makes the pair evidence rather than a habit.**

- `RedeemConfirmationModal.tsx` keeps the **one-directional** argument: the row that
  reverts a token goes **full-width under the thumb** inside the primitive — the
  guard loosened on the one act nobody wants easier.
- `GuestTokenDisplay.tsx` keeps the **two-directional** one: the serve area
  **shrinks** to a panel body so the bartender has to aim, while Cancel **grows** to
  a full-width control. The guard loosens on the reversible act and tightens on the
  irreversible one.

Each SHELL then carries the half of its file's argument that is true about it: the
serve screens carry the aim/no-aim direction, the acknowledgements carry the
tap-anywhere one. A reason true of a file and false of the shell it is printed
beside is how an exemption stops being read.

## F-41.2-22-05 — the camouflage route, found and closed

The ambiguity refusal turned out to close a route nobody had named: **a new overlay
written with the same class string as an exempt one does not inherit its
forgiveness.** The anchor resolves twice and the gate stops.

Measured: a third overlay in `GuestTokenDisplay.tsx` carrying the serve screen's
class string → **exit 2**, naming both lines (282, 670). This is not decoration of
the ambiguity guard; it is the guard's most useful case, and it is now stated in the
refusal's own text.

## F-41.2-22-07 — what was deliberately NOT touched, and why

**`Lightbox.tsx` stays keyed on its FILE.** Its declared reason is a statement about
the whole file — *a full-bleed media viewer at every tier* — so reason and mechanism
already agree and there is no gap between what it says and what it forgives.

The defect closed here is the **disagreement** between an element-shaped reason and a
file-shaped mechanism, not the existence of a file-scoped exemption. Converting the
media viewer too would have been a widening of this plan's scope on an argument
nobody has made. **Recorded as a residual rather than done quietly**: if a second
dialog is ever written into `Lightbox.tsx`, this gate is silent about it, exactly as
it was silent about the bartender files until today.

## What this does NOT close

- **No behaviour was measured.** This gate reads class strings and import clauses.
  Whether Escape closes a panel, whether a sheet rises from the bottom edge below
  768 px, and whether the page behind it scrolls are **H41-2** — a person, at two
  widths — and still owed.
- **The four exempt shells are still four dialogs without a focus trap.** They are
  *declared correct for their surface*, not *correct as dialogs*. The touch-target
  gate's exemption 10 says the harder half of the same sentence out loud: two of
  these controls are **under the 44 px floor by decision**, and RESP-03's criterion 5
  is partly false because of it.
- **Nothing here was verified by tests.** This repository has **no test runner for
  the product** (`CLAUDE.md` Guardrail 1). The evidence is the mutation runs recorded
  above and `npm run build` exit 0.
