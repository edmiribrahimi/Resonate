## §2 F-41.2-15-01 — "seventeen columns" is a drifted figure, and the multiset is the assertion

`41.2-15-PLAN.md` and `41.2-CONTEXT.md` both say the night select carries
**seventeen** columns. **Measured, twice, with two instruments:**

```
select, comment-stripped : 22 token(s), 21 distinct
select, RAW              : 22 token(s), 21 distinct
```

Counted as **top-level comma-separated items** it is **18**, not 17: sixteen
plain columns plus two embeds. Counted as **identifier tokens**, embed hints kept
whole, it is **22**.

This is the same class of drift `41.2-PATTERNS.md` §5.2 recorded for three of the
four line numbers, and it is recorded rather than quietly corrected because a
plan that had asserted *"the count is 17"* would have **failed on a correct
file** — and the likeliest repair for that failure is somebody deciding the
criterion meant something else. **The multiset is the assertion; the number is a
description of it.** Plan 41.2-19 and 41.2-20 should carry 22/21, or carry no
number at all.

## §3 F-41.2-15-02 — a seventh silent failure on the money path, RECORDED and not repaired

Six are already recorded across this phase. This is a seventh, and it is on this
file rather than on a satellite.

**Three sites, one shape** — a count read whose error is discarded and whose
absent value is then coalesced to zero:

| Site | The read | What a failure becomes |
|---|---|---|
| `:489-493` | the per-tier sold count, via the service client | `sold` becomes **0**, so `available` becomes the full stated quantity |
| `:532-536` | the RSVP count for a capacity-bearing night | the remaining count becomes the full capacity |
| `:637-641` | the same per-tier sold count, for the event-level tiers | as the first |

In all three the error object is not destructured at all, and the value is
coalesced (`count ?? 0`, `rsvpCount || 0`). **A refused or failed count is
therefore indistinguishable from a genuine zero**, and the visible consequence is
the wrong direction: a night that is full renders as open, and the control that
takes money renders beside it.

**Why it is recorded rather than repaired.** Deciding what a buyer is told when a
count cannot be read is a copy and product decision on a money surface, delivered
here under a visual mandate — the same reason the phase's other six are recorded.
And there is no error tracking in this repository, so a log is a place nobody
looks: a repair that only logs would not be a repair. **This plan changed none of
the three, and the money grep over its whole diff returns one line, which is prose.**

## §4 F-41.2-15-03 — the lineup pills lose the accent, and that is the contract rather than an oversight

`41-UI-SPEC.md` §6.4 names this file **by line** as the tree's canonical 20 px
target — *a lineup pill that is a `<Link>`* — and §8.5 gives the rule that
decides it: **a badge that is a `<Link>` or a `<button>` is a Chip.** Both rows
converted, the interactive one to `Chip` and the non-interactive one to `Badge`.

**The cost, stated rather than smoothed over.** §5.1 lists *the lineup pills on
an event card* among the four things the accent is for, and the chip's unselected
form is a neutral outline. So the accent tint is **lost**, and this is a loss and
not a correction.

**The road that would have kept it was refused, with a reason.** The chip's
`selected` state is an accent **fill** — and it is also the only thing that emits
`aria-current`. A pill that is not the current anything may not claim to be, so
taking the fill would have bought a hue with a false assistive-technology
statement. Re-applying the tint from the call site is the **WR-05 trap** named at
`PageShell.tsx`: same property, same specificity, and the emitted stylesheet's
order decides rather than the class list.

**What would close it** is a chip form whose selected state is not an accent fill
— a new rung on a **spine** file, and **41.2 does not edit the spine.** Not this
phase's, and named here so the next reader does not re-derive the argument.
