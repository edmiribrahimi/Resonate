### `src/components/newsletter/NewsletterForm.tsx:43` — RETAINED, with the sentence

docblock as well as here, so the next reader who finds a maximum in a converted file knows

## Deviations from Plan

### 1. [Rule 4-adjacent, decided rather than escalated] The two landing pills did not become `Chip`

- **Found during:** Task 1
- **What the plan said:** *"The two interactive pills become `Chip`, which carries the floor"*
  (`41.2-PATTERNS.md` §3 row 11 assigns them).
- **Why it does not hold for the primary of the two:** read from source,
  `src/components/ui/Chip.tsx:68-69` is the only filled form and `:178` binds it to
  `selected`, which is also what emits `aria-current`. A landing call to action is not *the
  current item among its siblings*, so taking the fill means making that claim falsely to
  every assistive technology that reads the page. Overriding the unselected form from the
  call site is the other road and is `WR-05`'s trap named at
  `src/components/ui/PageShell.tsx:109-114` — same specificity, so emission order decides,
  not the class list. `Button` with an `href` is closed by `Chip.tsx:289-293` for the rest of
  this phase.
- **What was done:** the precedent at
  `src/app/(admin)/admin/(work)/events/page.tsx:173-196` — a converted surface's primary
  internal-navigation action, with its argument written in place. It stays a `<Link>`, so
  client-side navigation and prefetching survive, and it carries the ladder's geometry with
  the focus expression **imported** from `Button.tsx:71` rather than re-spelled.
- **Consequence recorded, not hidden:** two converted surfaces now hand-write the same
  geometry for the same reason. **A third occurrence is the case for a rung, not a third
  copy.** F-41.2-03-04.
- **Files modified:** `src/app/page.tsx` · **Commit:** `d78d234`

### 2. [Rule 3 — blocking] Task 1's `<h1>` criterion is unsatisfiable as written

- **Found during:** Task 1
- **Issue:** the criterion asks `grep -c '<h1' src/app/page.tsx` → **1**, while the action it
  verifies is *"adopting `PageTitle`"*. `PageTitle` renders the element inside
  `Typography.tsx:61`, so a page file that adopts the primitive contains no such tag. Measured
  on the phase's own specimen: `grep -c '<h1' "src/app/(public)/gallery/page.tsx"` → **0**.
- **Resolved toward the intent**, which the `must_haves` state without ambiguity — the surface
  gains exactly one heading — and asserted on the primitive's call site instead. Asserting the
  tag would push a converter into hand-writing the element and bypassing the primitive, which
  is the opposite of what the criterion is for.
- **For plans 41.2-04 and later:** the same criterion is written into every plan that adds a
  heading. F-41.2-03-02.
- **Commit:** `d78d234`
