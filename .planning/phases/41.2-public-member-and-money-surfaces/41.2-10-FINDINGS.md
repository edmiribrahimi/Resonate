## F-10-01 — `RedeemConfirmationModal.tsx` carries THREE overlays, not one

**Measured**, with the dialog gate's own matcher rebuilt from
`scripts/verify-dialogs.mjs:809-823` and proved on five fixtures before it was
believed (two positives, three negatives; it refuses rather than reports if any
disagree):

```
src/app/(public)/events/[slug]/RedeemConfirmationModal.tsx  ->  3 overlay line(s)
   :100  className="fixed inset-0 z-[100] flex items-center justify-center bg-background/95 backdrop-blur-md"
   :125  <div className="fixed inset-0 z-[100] flex flex-col bg-background/95 backdrop-blur-md">
   :167  <div className="fixed inset-0 z-[60] flex items-end sm:items-center justify-center bg-black/60 backdrop-blur-sm">
```

`41.2-10-PLAN.md` task 1 `<read_first>` says *"Its shell is at `:167-168`"* — one
shell, and it models the file as a twin of `RefundActions.tsx`. It is not one.
Two of the three overlays are the screens a **bartender** uses, and the plan
never mentions them.

**Consequence for the plan's acceptance criteria.** Only `:167` converted, so
`grep -cE 'fixed inset-0|backdrop-blur|z-\[60\]'` returns **2** rather than 0 in
that file, and the dialog ratchet's entry for it is correctly **not** STALE. The
criterion was written against a file shape that does not exist.

**Why they were refused rather than converted — and this is the load-bearing
part.** The file states the reason in its own words, and both sentences survive
the diff unchanged:

```
:126  {/* Big tap-to-serve area: takes the whole screen above the Cancel row */}
:150  {/* Cancel row, kept narrow so the bartender's tap can't hit it by mistake */}
```

Inside the primitive the serve area becomes a panel body and the revert control
becomes a full-width control in the actions region — directly under the thumb.
**Reverting an active token is money going backwards at a bar with a queue in
front of it**, so a conversion that makes it *easier* to hit is a behaviour
change on the money path wearing a visual costume. It is `checkin-offline.md`'s
asymmetry read from behind the counter, and it is the exact move the plan's own
impact analysis forbids in principle: *"the conversion makes the guards tighter
rather than looser."*

**Not gamed.** The overlays were left legible to the matcher rather than rewritten
into a shape it cannot see. A number made quiet without the thing changing is the
fifth mechanism this phase already recorded in wave 4.

**Route:** a plan that owns the bar's operating surface, with a person at the
counter, not a class-string conversion.

## F-10-02 — `animate-pulse` in this perimeter is an attention mark, not a placeholder

`41.2-10-PLAN.md` calls the pulse in both files *"one hand-rolled placeholder"*
and its acceptance criteria demand a count of **0**, with §3 row 3's line

**Route:** plan 41.2-12 meets the same two sites on the guest side and should be

## F-10-03 — the redemption confirmation has no Cancel control, and one was not invented

The plan's acceptance criterion asks for `data-initial-focus` **exactly 1, on the
Cancel control**. Read out of the file, the confirmation has **no Cancel**: its
two controls are a close `×` (`aria-label="Close"`) and `Confirm`.

Two roads, and they contradict:

| Road | What it satisfies | What it breaks |
|---|---|---|
| add a Cancel control and mark it | `data-initial-focus == 1` | T-41.2-58 — the copy is byte-identical on a money confirmation |
| declare no marker | the copy rule | the marker count |

`meta-gates.md`: *"se due gate producono requisiti contraddittori, vince il piu'
restrittivo"*. The copy rule forbids an act; the marker rule requires one, so the
copy rule is the more restrictive and it won.

**The intent behind the criterion is fully met and is measurable.** The
primitive's documented fallback focuses the close control, which is first in the
DOM and least destructive by construction (`Dialog.tsx:117-147`):

- **Before:** the focus target was **nothing**. Nothing was focused on open, no
  focus was trapped, and the page behind was fully reachable.
- **After:** the close control. Escape closes, focus is trapped, the background
  is inert, and **Enter never confirms** — it lands on the close control.

The perimeter already holds this precedent with its reason written down:
`GuestLoginBanner.tsx:53-60`, converted in wave 0.

## F-10-04 — activating a token is REVERSIBLE, so the confirming control kept the accent fill

The plan directs the confirming control onto the destructive rung, on the premise
that *"Redeeming a token is not reversible from the guest's side"*. Read out of
the server action and out of this component, the premise does not hold for **this**
control:

```
RedeemConfirmationModal.tsx:121  await redeemDrinkToken(signedToken, "activate");   // purchased -> active
RedeemConfirmationModal.tsx:150  await redeemDrinkToken(signedToken, "cancel");     // active -> purchased
```

`activate` has an explicit path back, and that path is the very Cancel row F-10-01
is about. What is final is `serve`, on the bartender's screen — which this plan
did not convert.

So the affirmative control keeps the accent fill it had. **The destructive rung is
for acts that destroy**; this one claims a drink somebody already bought, and
painting it critical would say *danger* on the button that is the whole point of
the card. D-41.1-25 refuses a tone per outcome.

## F-10-05 — a 44 px floor and a deliberately-small target, on the same screen

`RedeemConfirmationModal.tsx:156` is the bartender's revert control, and it is
about **28 px** tall on purpose — *"kept narrow so the bartender's tap can't hit
it by mistake"*. §6.1's floor is 44 px, and `Button size="sm"` is `min-h-11`.

Raising it to the floor would make the money-reversing control **easier** to hit
in exactly the conditions §6.1 exists for. Leaving it below the floor leaves an
undersized target on a public surface.

`node scripts/verify-touch-targets.mjs` does **not** name this file today, before
or after, so nothing is currently red — which is why this is recorded rather than
resolved: it is a live contradiction between two house rules, and the resolution
is a decision about the bar, not a class string.

**Route:** the same plan as F-10-01.
