## F-41.2-03-02 — Task 1's `<h1>` criterion cannot be satisfied by the action that produces it

**A plan-internal contradiction, resolved by intent. No gate is affected.**

Task 1's action says the page *"has no `<h1>` today, and adopting `PageTitle` gives it one"*.
Its acceptance criterion asks that `LC_ALL=C /usr/bin/grep -c '<h1' src/app/page.tsx` return
**1**.

Those two cannot both hold. `PageTitle` renders the element **inside
`src/components/ui/Typography.tsx:61`**, so a page file that adopts the primitive contains no
such tag. Measured on the phase's own specimen, which has adopted it since plan 41-08:

```
$ LC_ALL=C /usr/bin/grep -c '<h1' "src/app/(public)/gallery/page.tsx"
0
$ LC_ALL=C /usr/bin/grep -c '<PageTitle' "src/app/(public)/gallery/page.tsx"
1
```

**Resolved toward the intent**, which the `must_haves` state without ambiguity — the surface
gains exactly one heading. Asserted as:

```
$ LC_ALL=C /usr/bin/grep -c '<PageTitle' src/app/page.tsx
1
$ LC_ALL=C /usr/bin/grep -c '<h1' src/app/page.tsx
0
```

**For plans 41.2-04 and later:** the same criterion is written into every plan that adds a
heading. Read it as *the surface renders exactly one*, and assert the primitive's call sites,
not the tag. Asserting the tag would push a converter into hand-writing the element and
bypassing the primitive — the opposite of what the criterion is for.

## F-41.2-03-03 — `PageTitle` may not carry the brand name as text, and the landing surface is where that first bites

**Applied, not deferred.** Recorded because the next plan that converts a surface whose
dominant line is a format name will meet it.

`src/components/ui/Typography.tsx:34-42` — the display role's exclusion list — ends with:

> *"And not on **any format name**: `SunSet`, `RamaDub`, `MotionLab` and `re:sonate` are read,
> not decorated, and a phase that let the display face onto a format name would be making a
> brand decision in a file every surface imports."*

`PageTitle` applies the display face unconditionally. The landing surface's dominant line
**is** the wordmark, so writing that string as the title's text would have put the display
face on the brand — the one thing the primitive's own contract forbids, and
`brand-visual-system.md` backs it: the format is the source of the name, never the other way
round.

**What was done instead:** the title wraps the wordmark image already on the page. The
surface gains exactly one heading, its accessible string is the image's existing
`alt="re:sonate"` — **unchanged, so no copy is introduced** (`41-UI-SPEC.md` §11: *none
introduced*) — and no text is decorated.

**The gap this leaves, stated rather than implied:** there is no body-or-plain heading rung.
`Typography.tsx` exports `PageTitle` and `SectionHeading` and nothing that renders a
top-level heading **without** the display face. A surface whose title must be a format name in
the reading face has no primitive today. It did not block this plan; it will block the first
surface whose heading is a format name.

## F-41.2-03-04 — `Chip` has no fill that is not also a claim of `aria-current`

**Applied as a deviation from `41.2-PATTERNS.md` §3 row 11. Recorded so the next plan
converting an interactive pill does not re-derive it.**

§3 row 11 assigns `src/app/page.tsx:49,55` — the landing surface's two pill actions — to
`Chip`. Read from source, that assignment does not survive the primary of the two:

- `src/components/ui/Chip.tsx:68-69` — the only filled form is `CHIP_SELECTED`, and `:178`
  binds it to `selected`, which is also what emits `aria-current`. A landing call to action is
  not *the current item among its siblings*, so taking the fill means making that claim
  falsely to every assistive technology that reads it.
- Overriding the unselected form from the call site's `className` is the other road, and it is
  `WR-05`'s trap named in `src/components/ui/PageShell.tsx:109-114`: `border-control` against
  `border-accent` are the same specificity, so which one wins is decided by emission order in
  the stylesheet and not by the class list.
- `Button` with an `href` is closed by `src/components/ui/Chip.tsx:289-293`, standing for the
  rest of this phase: it renders a bare anchor, which in the App Router is a full document
  load.

**The precedent taken instead**, and it is a converted surface's primary internal-navigation
action, with its argument written in place: `src/app/(admin)/admin/(work)/events/page.tsx:173-196`.
It stays a `<Link>` — client-side navigation and prefetching survive — and carries the
ladder's geometry (the 44px floor, the named horizontal step, the accent fill whose ink is the
ground at 6.85 : 1) with the focus expression **imported** from `Button.tsx:71` rather than
re-spelled.

**The gap that precedent already named and this plan re-hits:** *"neither the ladder nor the
chip can BE a `next/link`"* with an accent fill. Two converted surfaces now hand-write the same
geometry for the same reason. **A third occurrence is the case for a rung**, not a third copy.
Routed to whichever plan next needs a filled navigation action.
