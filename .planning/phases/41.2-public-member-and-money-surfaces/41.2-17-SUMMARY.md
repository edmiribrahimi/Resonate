## The validation multiset, printed sorted in both states

**The instrument printed its own self-check before it measured anything, and it
refuses rather than reports.** Wave 4's corroborating instrument returned three
zeros on eight files including four with visible overlays because of a defect in
itself; believed, it would have authorised twelve wrong deletions each carrying a
second instrument's agreement. So this one is required to reproduce a known
non-zero on a positive fixture, a known zero on a negative one, a difference on a
positive with one attribute deliberately removed — **with the mutation asserted
applied before its result is read** — and, on a fixture whose only attributes sit
inside prose within an opening tag, a stripped zero beside a raw non-zero. That
last pair is what proves the comment stripper is actually running.

```
  self-check  positive fixture -> NON-ZERO   : yes (7 members)
  self-check  negative fixture -> ZERO       : yes (0 members)
  self-check  mutation actually applied      : yes
  self-check  mutated positive -> DIFFERS    : yes
              removed member                 : step=0.01
  self-check  prose-only: stripped ZERO      : yes (0)
  self-check  prose-only: raw NON-ZERO       : yes (2)
  → self-check PASSED; the instrument can see and can also stay silent.
```

**Its first cut over-reported, and naming that is part of the claim.** It returned
seventeen members on the incumbent file, of which five were not attributes at
all: a Tailwind variant prefix that shares a name with the disabled attribute,
two property accesses, and the TypeScript type keyword. The regex was tightened
to refuse a following colon, a preceding dot, and any position outside a JSX
opening tag. An instrument whose hits a reader cannot separate into real and
spurious is an instrument whose zero cannot be checked.

## The one control that stayed a raw element, and why that is a refused criterion

The plan's acceptance criterion asks that the raw-element grep return **0** —
every control a primitive. It returns **1**, and the one is the tier row.

| Road | What it satisfies | What it breaks |
|---|---|---|
| the labelled pill rung | the criterion | both pill rungs fix a fully round radius, horizontal padding, centred content and non-wrapping text. A full-width card row needs the opposite of all four, and defeating a primitive's own geometry from a caller's class list relies on class-list order — which Tailwind does not honour; it resolves by **source** order. That is undefined behaviour dressed as a conversion |
| the pressable card | the criterion | it renders a `div`. Adopting it would take keyboard operability and the disabled state **off the surface that decides what a guest pays**, which is a behaviour change wearing a visual costume |
| keep the element, pay the contract on it | the contract | the criterion, as written |

**The tree already walks the third road, in a converted file.** The colour-swatch
picker under the format catalogue keeps raw elements for exactly this reason and
pays the 44px floor, the control radius and the imported focus expression on them
— and it is converted, in phase 41. So this is a precedent, not an exception
invented here.

What the row gained: the 44px floor, the container radius from the three-rung
ladder, the imported focus expression, the tree's own press feedback in place of
a hand-written arbitrary-value scale, and semantic ink. `verify-touch-targets`
**PASSED** with it in scope, and the file now declares the floor once where it
declared it zero times.

**One behaviour was added and it is declared rather than slipped in.** The
selected row had exactly one channel — a border hue — which says nothing at all
to a person who cannot see it. The row now carries its pressed state. No wording,
no payload and no condition moved with it. This is 41.2-13's precedent, where the
one behaviour that plan added was a disclosure's expanded state, declared the
same way.

### The one that costs a guest a reduction

A guest without an account chooses a tier, enters a valid code, sees the reduced
figure, and presses buy. They are sent to register. They come back. **The
purchase resumes at the undiscounted figure, and nothing on the screen says the
code was dropped** — there is no refusal, because nothing refused.

The value is written into the stored intent by the tier selection; the handler's
own type for that intent does not declare it, and the purchase action is called
with two arguments where it takes three. The third is **optional**, so nothing
fails to compile and nothing fails at run time. The signed-in path does not have
the defect, because there the action is called directly with all three — which
means it exists only on the path a first-time guest takes, and a code is most
often given to somebody who is not yet a member.

**It was not fixed here.** Passing the third argument changes what the purchase
action is called with, which is a payload change on the money path — stop
condition 2, and the same standard under which six other failures in this phase
were recorded rather than repaired. It also needs a decision this plan does not
own: whether a code that has since been deactivated, exhausted or restricted to
another tier should make the resumed purchase **refuse** or proceed silently
without it. The action already throws in all three cases, so the answer is
probably *let it refuse* — and *probably* is not a thing to settle inside a
visual conversion.
