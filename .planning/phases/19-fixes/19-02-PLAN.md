**Fix the drink items query in `src/app/(public)/events/[slug]/page.tsx`:**

The current query at line 334 fetches ALL available drink items for the event without filtering by party_id. When there are multiple parties each with their own drink items, the count shows the total across all parties (e.g., 8) instead of the count for the current context.

Since the "Drink Menu" button is displayed at the event level (not per-party), and the menu page shows drinks per-party with a party selector, the simplest accurate fix is to **not show a specific item count** and instead show a more useful label.

Replace the drink items query (lines 333-339):
```typescript
// Fetch available drink items for this event
const { data: drinkItems } = await supabase
  .from("drink_items")
  .select("*")
  .eq("event_id", event.id)
  .eq("is_available", true)
  .order("sort_order");
```

With a per-party count that reflects what the user actually sees on the menu page:
```typescript
// Check if any drinks are available across parties
const { count: drinkItemCount } = await supabase
  .from("drink_items")
  .select("*", { count: "exact", head: true })
  .eq("event_id", event.id)
  .eq("is_available", true);
```

Then at line 704, where `drinkItems` is used for the conditional + count display, update:

Change the condition from:
```tsx
{canSeeDrafts && drinkItems && drinkItems.length > 0 && (
```
To:
```tsx
{canSeeDrafts && (drinkItemCount ?? 0) > 0 && (
```

And change the count text from:
```tsx
<p className="mt-1 text-xs text-muted">{drinkItems.length} items available</p>
```
To:
```tsx
<p className="mt-1 text-xs text-muted">View available drinks</p>
```

This removes the misleading count entirely. The menu page handles per-party display correctly.

Note: If `drinkItems` variable was also used elsewhere in the page (check for other references), keep the original query but rename it. Check carefully -- it may only be used for the button display.
