**Server actions:**

1. `createTier(eventId: string, formData: FormData)`:
   - Verify organizer role and event ownership (organizer owns event OR user is master)
   - Extract `name` (string, required, 1-100 chars), `price` (number, >= 0), `quantity` (integer, > 0) from formData
   - Insert into `ticket_tiers` table with `event_id`
   - Use service-role client for master (to bypass RLS ownership check on event verification)
   - `revalidatePath(\`/organizer/events/${eventId}/tickets\`)`
   - Return `{ success: true }`

2. `updateTier(tierId: string, eventId: string, formData: FormData)`:
   - Verify organizer role and event ownership
   - Extract and validate same fields as createTier
   - Update the tier row by id
   - Per user decision: "Tiers are fully editable always -- organizer can change price, name, and quantity at any time, even after sales. Existing tickets remain valid at their original price."
   - `revalidatePath(\`/organizer/events/${eventId}/tickets\`)`
   - Return `{ success: true }`

3. `deleteTier(tierId: string, eventId: string)`:
   - Verify organizer role and event ownership
   - Per user decision: "Tiers with existing sales cannot be deleted. Only unsold tiers can be removed."
   - Check ticket count: `SELECT COUNT(*) FROM tickets WHERE tier_id = tierId`. If count > 0, throw error "Cannot delete a tier with existing sales"
   - Delete the tier row
   - `revalidatePath(\`/organizer/events/${eventId}/tickets\`)`
   - Return `{ success: true }`

- `verifyOrganizer(supabase)` -- same pattern as existing events/actions.ts
