  <action>
Create migration file `supabase/migrations/20260225_phase6_ticketing.sql` with:

**Tables:**

1. `ticket_tiers` table:
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
   - `event_id uuid NOT NULL REFERENCES public.events ON DELETE CASCADE`
   - `name text NOT NULL` (e.g. "Early Bird", "Regular", "VIP")
   - `price numeric(10,2) NOT NULL CHECK (price >= 0)`
   - `quantity integer NOT NULL CHECK (quantity > 0)`
   - `created_at timestamptz DEFAULT now()`
   - `updated_at timestamptz DEFAULT now()`

2. `tickets` table:
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
   - `event_id uuid NOT NULL REFERENCES public.events ON DELETE CASCADE`
   - `tier_id uuid NOT NULL REFERENCES public.ticket_tiers ON DELETE RESTRICT`
   - `user_id uuid NOT NULL REFERENCES auth.users ON DELETE CASCADE`
   - `sumup_checkout_id text UNIQUE` (for idempotent webhook handling)
   - `sumup_transaction_code text`
   - `amount_paid numeric(10,2) NOT NULL`
   - `created_at timestamptz DEFAULT now()`
   - `UNIQUE (event_id, user_id)` -- one ticket per member per event

3. `pending_purchases` table:
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
   - `event_id uuid NOT NULL REFERENCES public.events ON DELETE CASCADE`
   - `tier_id uuid NOT NULL REFERENCES public.ticket_tiers ON DELETE RESTRICT`
   - `user_id uuid NOT NULL REFERENCES auth.users ON DELETE CASCADE`
   - `sumup_checkout_id text UNIQUE NOT NULL`
   - `status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'completed', 'failed', 'expired'))`
   - `ticket_id uuid REFERENCES public.tickets`
   - `error_message text`
   - `created_at timestamptz DEFAULT now()`
   - `updated_at timestamptz DEFAULT now()`

**Indexes:**
- `idx_tickets_event_id ON public.tickets (event_id)`
- `idx_tickets_user_id ON public.tickets (user_id)`
- `idx_tickets_tier_id ON public.tickets (tier_id)`
- `idx_ticket_tiers_event_id ON public.ticket_tiers (event_id)`
- `idx_pending_purchases_checkout ON public.pending_purchases (sumup_checkout_id)`

**RLS Policies:**

Enable RLS on all three tables.

ticket_tiers:
- `ticket_tiers_select`: FOR SELECT TO authenticated USING (true) -- anyone authenticated can see tiers for purchase UI
- `ticket_tiers_insert`: FOR INSERT TO authenticated WITH CHECK ((SELECT public.is_admin_or_organizer()))
- `ticket_tiers_update`: FOR UPDATE TO authenticated USING ((SELECT public.is_admin_or_organizer()))
- `ticket_tiers_delete`: FOR DELETE TO authenticated USING ((SELECT public.is_admin_or_organizer()))

tickets:
- `tickets_select_own`: FOR SELECT TO authenticated USING (auth.uid() = user_id)
- `tickets_select_admin`: FOR SELECT TO authenticated USING ((SELECT public.is_admin_or_organizer()))
- No direct INSERT policy for regular users -- inserts go through `reserve_ticket` SECURITY DEFINER function

pending_purchases:
- `pending_select_own`: FOR SELECT TO authenticated USING (auth.uid() = user_id)
- No INSERT policy needed for regular users -- inserts go through server actions with service-role client

**Atomic Reservation Function:**

Create `public.reserve_ticket(p_tier_id uuid, p_user_id uuid, p_event_id uuid, p_sumup_checkout_id text, p_sumup_transaction_code text, p_amount_paid numeric) RETURNS uuid` as a SECURITY DEFINER plpgsql function that:
1. Checks if user already has a ticket for this event (raises exception if yes)
2. Locks the tier row via `SELECT quantity INTO v_quantity FROM public.ticket_tiers WHERE id = p_tier_id FOR UPDATE`
3. Counts existing tickets for this tier
4. Raises exception if `v_sold_count >= v_quantity` (sold out)
5. Inserts ticket row and returns the new ticket UUID

Use the exact function from the research document (Pattern 2 in 06-RESEARCH.md).

**Update schema.sql:**

Append all three table definitions, RLS policies, indexes, and the reserve_ticket function to `supabase/schema.sql` in a new "Ticketing & Payments" section, following the existing pattern (comments, section headers, etc.).
