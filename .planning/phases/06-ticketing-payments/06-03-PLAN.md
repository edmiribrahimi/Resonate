**Purchase server action** -- add to `src/app/(organizer)/organizer/events/actions.ts`:

Add a new exported async function `purchaseTicket(eventId: string, tierId: string)`:
1. Get authenticated user via `createClient()` + `supabase.auth.getUser()`
2. Verify user is approved: query `profiles` for status, throw if not `approved` (TICK-07 guard)
3. Check user doesn't already have a ticket for this event: query `tickets` table. Throw "You already have a ticket for this event" if found.
4. Fetch the tier (name, price) from `ticket_tiers` to get amount and description
5. Fetch the event (title, slug) for the redirect URL and description
6. Generate a unique checkout reference: `crypto.randomUUID()`
7. Build redirect URL: `${process.env.NEXT_PUBLIC_APP_URL}/events/${event.slug}?payment=success&ref=${checkoutReference}`
8. Build return URL (webhook): `${process.env.NEXT_PUBLIC_APP_URL}/api/webhooks/sumup`
9. Call `createCheckout()` from `@/lib/sumup` with amount: tier.price, currency: "EUR", description: `${event.title} - ${tier.name}`, checkoutReference, redirectUrl, returnUrl
10. Create pending_purchase record using service-role client (to bypass RLS): insert into `pending_purchases` with event_id, tier_id, user_id, sumup_checkout_id (from SumUp response), status: "pending"
11. Return `{ success: true, checkoutUrl: response.hosted_checkout_url }` -- the calling client component will redirect to this URL

Note: This action lives alongside existing event actions. Import `createCheckout` from `@/lib/sumup`. Import `crypto` from Node built-in for randomUUID.

**Webhook handler** -- create `src/app/api/webhooks/sumup/route.ts`:

Export a POST handler following the exact pattern from 06-RESEARCH.md Pattern 3:

1. Parse JSON body. If `event_type !== "CHECKOUT_STATUS_CHANGED"`, return `{ received: true }` with 200.
2. Call `getCheckout(body.id)` from `@/lib/sumup` to verify payment status. If status is not "PAID", return `{ received: true }`.
3. Use service-role Supabase client (no user session in webhook context): `createClient(NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY)`.
4. Look up pending_purchase by `sumup_checkout_id = checkout.id`. If not found, log error and return 200.
5. Check if pending_purchase.status is already "completed" (idempotency). If so, return 200.
6. Call `supabase.rpc("reserve_ticket", { p_tier_id, p_user_id, p_event_id, p_sumup_checkout_id, p_sumup_transaction_code, p_amount_paid })`.
7. On RPC error: update pending_purchase status to "failed" with error_message, return 200.
8. On success: update pending_purchase status to "completed" with ticket_id.
9. Fire-and-forget: generate QR code and send confirmation email:
   - Fetch user email and name from profiles table
   - Fetch event details (title, date, time) from events table
   - Fetch tier name from ticket_tiers table
   - Generate QR buffer: `QRCode.toBuffer(ticketId, { width: 280, margin: 2, errorCorrectionLevel: "H" })` using `qrcode` package
   - Render email HTML using `@react-email/render` with `TicketConfirmationEmail` component
   - Call `sendEmail({ to, subject: "Your ticket for {eventTitle}", html, attachments: [{ content: qrBuffer.toString("base64"), filename: "ticket-qr.png", content_type: "image/png" }] })`
   - Wrap in try/catch -- email failure should NOT cause webhook to fail (fire-and-forget pattern from Phase 4)
10. Return `NextResponse.json({ received: true })`.

**Important webhook security notes (from research):**
- ALWAYS verify via GET checkout API (never trust webhook body for status)
- Only process known checkout IDs (must exist in pending_purchases)
- Idempotent: check if already completed before processing
