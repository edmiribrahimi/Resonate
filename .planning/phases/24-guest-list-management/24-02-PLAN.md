**2. Create src/lib/guest-list/process-entry.ts:**

Create the directory `src/lib/guest-list/` if it doesn't exist.

This is the core processing pipeline for a single guest list entry. Export `processGuestEntry` function.

```typescript
import { getServiceClient } from "@/lib/supabase/service";
import { sendEmail } from "@/lib/email";
import { render } from "@react-email/render";
import { GuestInvitationEmail } from "@/emails/guest-invitation";
import QRCode from "qrcode";
import crypto from "crypto";

interface ProcessResult {
  status: 'ticket_issued' | 'already_has_ticket' | 'name_only' | 'failed';
  profile_id?: string;
  ticket_id?: string;
  error?: string;
}

export async function processGuestEntry(entry: {
  id: string;
  event_id: string;
  party_id: string | null;
  first_name: string;
  last_name: string;
  email: string | null;
}, eventDetails: {
  title: string;
  date: string;
  time: string;
  partyTitle?: string;
}): Promise<ProcessResult>
```

Processing logic:
1. If no email -> return `{ status: 'name_only' }` (no processing, door check-in only)
2. Check if email exists in profiles (case-insensitive: `LOWER(email)`)
3. **If existing user found:**
   - If status is 'pending', update to `status='approved', approved_via='guest_list'` via service client
   - Check if user already has a ticket for this event (and party if specified)
   - If ticket exists -> update guest entry `status='already_has_ticket'`, return
   - If no ticket -> create free ticket (direct INSERT, `ticket_type='guest_list'`, `amount_paid=0`, `tier_id=null`)
   - Update guest entry with `status='ticket_issued'`, `profile_id`, `ticket_id`
   - Send invitation email (fire-and-forget, same pattern as existing approval email in admin/members/actions.ts)
   - Return `{ status: 'ticket_issued', profile_id, ticket_id }`
4. **If no existing user:**
   - Call `serviceClient.auth.admin.createUser({ email, email_confirm: true, user_metadata: { full_name: '{first_name} {last_name}', guest_list_event_id: entry.event_id } })` -- this fires handle_new_user trigger which auto-approves
   - Call `serviceClient.auth.admin.generateLink({ type: 'recovery', email })` to generate password-set link (NOT 'invite' -- see research Open Question 3)
   - Create free ticket for the new user
   - Generate QR code for the ticket (use same HMAC signing pattern as existing `src/utils/qr.ts` -- read it first to replicate the pattern)
   - Render `GuestInvitationEmail` with event details + claimUrl from generateLink
   - Send email via `sendEmail()` with QR as inline attachment (same `cid:ticket-qr` pattern as ticket-confirmation webhook)
   - Update guest entry with `status='ticket_issued'`, `profile_id`, `ticket_id`
   - Return result
5. **On any error:** Update guest entry `status='failed'`, `error_message=error.message`, return `{ status: 'failed', error }`

IMPORTANT: Read `src/utils/qr.ts` and `src/app/api/webhooks/sumup/route.ts` to replicate the exact QR generation + email attachment pattern. The QR should encode the ticket token (HMAC-signed ticket ID), not just the ticket ID.

For the free ticket creation, use a helper `createFreeTicket(eventId, partyId, userId)` that:
- Checks for existing ticket at same event+party (prevent duplicates)
- INSERTs with `ticket_type: 'guest_list'`, `amount_paid: 0`, `tier_id: null`, `sumup_checkout_id: null`
- Returns the ticket ID

- If email provided: call `processGuestEntry()` immediately (auto-process)
- Call `revalidatePath` for the guest list page
- Return `{ success: true, entry }` or `{ error: string }`

**removeGuest(entryId: string):**
- Fetch the entry to check `ticket_id`
- If `ticket_id IS NOT NULL`, the ticket remains valid (just unlink from guest list)
- Delete the guest_list_entry
- Revalidate path
- Return `{ success: true, hadTicket: boolean }`

**fetchGuestList(eventId: string):**
- Not a server action (just an async function for the page)
- Query `guest_list_entries` for this event, ordered by created_at desc
- Join with `profiles(full_name)` via `profile_id` for display
- Return entries array
