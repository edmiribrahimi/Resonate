<objective>
Create the layout for the collapsed work surface — one access-context resolution, both navs
mounted once — and move the four master-only surfaces under it. Give `/admin` a gate of its
own.

Purpose: D-34-07. There is no `layout.tsx` in either route group today, so every page repeats
the mount and the `role as UserRole` cast the code already flags as this phase's to remove.
And finding F2: `(admin)/admin/page.tsx` is a bare `redirect()` with **no gate at all**, held
up solely by the `/admin/*` prefix rule that D-34-02 dissolves — closing that is not optional,
it is a consequence of the collapse.

**Why a nested `(work)` route group and not `admin/layout.tsx`.** A layout at
`src/app/(admin)/admin/layout.tsx` would wrap `/admin/scanner` too, and would put a tab bar
and a second bottom nav on the door — which means editing
`src/app/(admin)/admin/scanner/page.tsx` to remove its own mount. This phase does not touch
the door's page. A route group does not affect the URL, so
`src/app/(admin)/admin/(work)/analytics/page.tsx` still serves `/admin/analytics`, and
`scanner/` stays outside the group, byte-identical. It also pre-positions Phase 39: when the
door leaves for its own address, it is already structurally separate.

Output: `(work)/layout.tsx`, four surfaces moved under it with their hand mounts removed, and
`/admin` bound to `organizer.access`.
</objective>

  <action>
    Create `src/app/(admin)/admin/(work)/layout.tsx` as a Server Component. It calls
    `getAccessContext()` **once** and renders `<StaffNav capabilities={…} />`,
    `{children}` and `<MobileNav role={…} status={…} />`.

    Two things about that call that must be stated in the layout's docblock rather than
    assumed:
    - `getAccessContext` is `cache()`-scoped per request, so a page below that also calls it
      costs **no second round trip**. That matters because the same middleware path serves the
      door, and this project counts round trips on bad networks.
    - It **throws** `capabilities.resolve_failed: <code>` and that must stay a throw
      (D-34-08 state 3). **Do not wrap it in `try/catch`.** An infrastructure fault dressed as
      a permission denial is a silent failure with an alibi, and there is no error tracking
      here to contradict it.

    `MobileNav` keeps its `role` / `status` props — plan 34-04 deliberately did not change its
    signature, because it is mounted on 44 pages including the door's. The layout supplies them
    from the resolved context. `StaffNav` takes the capability key array, as rewritten by
    34-04.

    The layout does **not** contain a capability guard. Each page keeps its own — D-34-09: the
    middleware and the page give the same verdict because they read the same entry, and a
    layout-level guard would be a third place asking a question that already has two askers.
    Say so in the docblock.

    Then `git mv src/app/(admin)/admin/page.tsx "src/app/(admin)/admin/(work)/page.tsx"` and
    give it the gate it has never had: resolve the access context, refuse with
    `redirect("/dashboard")` when `organizer.access` is absent, then `redirect("/admin/events")`
    as before. `organizer.access` is the binding plan 34-01 gave `/admin` in the map, and it is
    the least of the capabilities any collapsed surface needs — an unentitled visitor is
    refused before the redirect runs. Cite finding F2 in a comment: this page was held up
    solely by `middleware.ts`'s `/admin/*` rule, and that rule no longer exists.

    Do not restyle anything. No token, no typography, no spacing, no component restyle — Phases
    40 and 41. The layout's markup is the two mounts and `{children}`, in the order the pages
    used.
  </action>
