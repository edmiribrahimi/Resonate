<objective>
Close the literal sweep: collapse the 36 `revalidatePath` calls, drive
`node scripts/verify-routes.mjs` to zero, and re-point `verify:capabilities` side 4 at the new
map.

Purpose: **`revalidatePath` is the phase's silent-failure category.** Its argument is a plain
string: `typedRoutes`'s augmentation covers `next/link`, `next/navigation` and `next/form` and
**never `next/cache`**, so the compiler cannot see it, `npm run build` cannot see it, and this
project has **no error tracking**. Its failure mode is a members list that stops refreshing
after an approval — an organizer clicks approve, the row does not move, and nothing anywhere
reports it. That is a member-facing consequence of a routing edit (D-34-16).

Re-measured 2026-08-09: **36**, not 26. The first count was 26 because it summed only the
three files this plan had declared *and* used a double-quoted grep
(`revalidatePath\(\s*"/organizer`), while **ten** calls are backtick template literals —
`` revalidatePath(`/organizer/events/${eventId}/…`) `` — in `events/[id]/tickets/actions.ts`
(6), `assignments/actions.ts` (2) and `guest-list/actions.ts` (2). The grep that should have
caught them returned 0 **with all ten still present**. That is why every criterion in this plan
now matches `` [`"] `` and not `"`.

Those ten are not a red script. After plan 34-15 deletes the organizer tree they point at
addresses no route serves, so changing a tier, an assignment or a guest list silently stops
refreshing the corresponding `/admin` surface — and **M-8 as originally written observed only
the members list**, so no procedure in this phase would have seen it.

Sixteen of the 36 are in the members actions as **six** adjacent `/admin/members` +
`/organizer/members` pairs (`:1693/1694`, `:1738/1739`, `:1786/1787`, `:1844/1845`,
`:2061/2062`, `:2580/2581`) plus **four** lone `/admin/members` calls (`:1455`, `:2531`,
`:2551`, `:2571`). Adjacency is not proof of a pair — the earlier count of five got that
wrong — so verify each in its enclosing function. Each real pair collapses to one call, and
**deleting the wrong half of a pair is a one-character mistake with no detector** — which is
why every other plan in this phase was forbidden from touching them and why they all land
here, once, against a committed check.

Output: `verify:routes` green, and a side-4 message that states its own boundary.
</objective>
