<objective>
Replace the middleware's three prefix rules with one lookup in the map written by plan 34-01,
and emit the `/organizer/*` translation from the very top of `src/middleware.ts`, before any
session work.

Purpose: this is **the single most dangerous edit in the phase**. The file says so itself at
`:345-352` — the `/admin/scanner` branch is tested before the general `/admin` branch, the
ordering is *"load-bearing and is NOT a lookup table on purpose"*, and inverting it judges the
door by `admin.access` and locks every organizer out of it, in front of a queue. This plan
replaces that `if / else if` with a lookup table. What makes it safe is not care: it is that
plan 34-01 made specificity a property of the pattern and proved it by mutation with
`door.operate` declared last.

Output: a middleware that asks the same question the page will ask, from the same declaration
(D-34-09), with the three refusal states intact (D-34-08).
</objective>

  <action>
    In `src/middleware.ts`, call `resolveOrganizerRedirect(request.nextUrl.pathname)` as the
    **first statement** of `middleware()`. On a hit, clone `request.nextUrl`, set `pathname` to
    the destination, and return `NextResponse.redirect(url, REDIRECT_STATUS)`. `clone()`
    preserves the query string, which the Next.js redirects documentation confirms passes
    through to the destination.

    It must run **before** `updateSession(request)`. Pitfall 3: address translation has no
    subject. It must not read a session, must not vary by viewer, and must not carry a cause.
    A response that varies by viewer without a `Vary` is one a shared cache can serve to the
    wrong person. **The word `capabilities` must not appear anywhere in this code path** —
    that is the named warning sign.

    Leave `export const config.matcher` **exactly as it is**. Three reasons, all measured:
    Server Functions are handled as POST requests to the route where they are used, so a
    matcher change can silently remove proxy coverage from a path — and this phase moves the
    hosting routes of several server actions; the door's `/api/tickets/checkin` passes through
    this middleware on every scan and the file counts that round trip at `:136-140`; and
    `/membership-card` and `/attendance` are still judged here and are outside the collapsed
    tree.

    Do **not** rename `src/middleware.ts` to `proxy.ts`. Next 16.0.0 deprecated and renamed the
    convention, but this repository is on `next@16.1.6` and builds. Renaming the single most
    safety-critical file in the repo in the same plan that rewrites its logic produces two
    changes that look like each other in a diff. Record it in the SUMMARY as a finding for its
    own small plan, after Phase 39.

    Add a comment at the redirect block naming `REDIRECT_STATUS` as 307 **while the phase is in
    flight**, with the flip to 308 owned by plan 34-17 (D-34-15). A wrong 308 cannot be
    withdrawn from a client that has already cached it, and there is no error tracking to notice
    that it happened.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → middleware | `pathname` is attacker-controlled; the resolver and the redirect both read it |
| middleware → page | The middleware is UX. The page guard and RLS are the two real layers behind it |
| shared cache → viewer | A cached redirect is served to whoever asks for that address |
