Create the Phase 5 database migration SQL file at `supabase/migrations/20260225_phase5_events.sql` wrapped in BEGIN/COMMIT:

1. **Add `created_by` column** to the `events` table:
   - `ALTER TABLE public.events ADD COLUMN created_by uuid REFERENCES auth.users ON DELETE SET NULL;`

2. **Drop the overly-permissive existing policy** and replace with granular policies:
   - `DROP POLICY IF EXISTS events_all_admin ON public.events;`
   - Create `events_select_published`: published events readable by anyone (including anon) -- `FOR SELECT USING (is_published = true)`
   - Create `events_select_admin`: organizers and master can see ALL events (including drafts) -- `FOR SELECT USING ((SELECT public.is_admin_or_organizer()))`
   - Create `events_insert_admin`: organizers and master can create events -- `FOR INSERT WITH CHECK ((SELECT public.is_admin_or_organizer()))`
   - Create `events_update_own`: organizers update own events (`auth.uid() = created_by`), master updates any (`(SELECT public.is_master())`)
   - Create `events_delete_own`: organizers delete own events (`auth.uid() = created_by`), master deletes any (`(SELECT public.is_master())`)

3. **Create storage bucket** for event cover images. Include SQL for documentation:
   - `INSERT INTO storage.buckets (id, name, public) VALUES ('event-images', 'event-images', true) ON CONFLICT DO NOTHING;`
   - Create storage RLS policies:
     - Organizers can upload: `ON storage.objects FOR INSERT TO authenticated WITH CHECK (bucket_id = 'event-images' AND (SELECT public.is_admin_or_organizer()))`
     - Anyone can view: `ON storage.objects FOR SELECT USING (bucket_id = 'event-images')`
     - Organizers can update own: `ON storage.objects FOR UPDATE TO authenticated USING (bucket_id = 'event-images' AND (SELECT public.is_admin_or_organizer()))`
     - Organizers can delete: `ON storage.objects FOR DELETE TO authenticated USING (bucket_id = 'event-images' AND (SELECT public.is_admin_or_organizer()))`

4. **Update `supabase/schema.sql`** to reflect the new state:
   - Add `created_by uuid references auth.users on delete set null` to the events table definition
   - Replace old `events_all_admin` policy with the 5 new granular policies
   - Add storage bucket and storage policies

5. **Update `src/types/database.ts`**:
   - Add `created_by: string | null;` to the Event interface (after `capacity`)

Note: The storage bucket SQL may need to be run via Supabase Dashboard if the `storage.buckets` table is not accessible via SQL. Include it in the migration for documentation but note this caveat in a comment.

**1. Create `src/utils/slugify.ts`:**
Export a `slugify` function that converts a title to a URL-friendly slug:
- Lowercase
- Normalize NFD and remove diacritics (replace `[\u0300-\u036f]` with empty)
- Remove non-alphanumeric chars except spaces and hyphens
- Replace spaces/multiple hyphens with single hyphen
- Trim leading/trailing hyphens
- Limit to 80 characters

**2. Create `src/app/(organizer)/organizer/events/actions.ts`:**
Follow the established pattern from `src/app/(admin)/admin/members/actions.ts`. Add `"use server"` directive.

Include a `getServiceClient()` helper (same pattern as members/actions.ts) for operations where RLS blocks legitimate access.

Include a `verifyOrganizer` helper that:
- Gets authenticated user via `supabase.auth.getUser()`
- Checks profile role is "organizer" or "master"
- Returns `{ user, isMaster: boolean }`

**Server actions to implement:**

a) `createEvent(formData: FormData)`:
   - Verify organizer
   - Extract fields: title, description, date, time, location (nullable), location_secret (boolean), lineup (JSON string to parse), cover_image (string URL or null), capacity (number or null)
   - Generate slug from title using slugify. Check uniqueness against events table -- if exists, append `-${Date.now().toString(36)}`
   - Insert into events with `is_published: false`, `created_by: user.id`
   - Revalidate `/organizer/events`, `/admin/events`, `/events`
   - Return `{ success: true, id: insertedEvent.id }`
   - Use `.select().single()` on insert to get the created event ID back

b) `updateEvent(eventId: string, formData: FormData)`:
   - Verify organizer
   - If NOT master, verify event.created_by === user.id (fetch event first)
   - Extract same fields as create (except slug stays the same)
   - Update the event
   - Revalidate paths including `/events` and `/events/[slug]`
   - Return `{ success: true }`

c) `deleteEvent(eventId: string)`:
   - Verify organizer
   - If NOT master, verify event.created_by === user.id
   - Delete from events table
   - Revalidate paths
   - Return `{ success: true }`

d) `publishEvent(eventId: string)`:
   - Verify organizer
   - If NOT master, verify event.created_by === user.id
   - Update `is_published: true`
   - Revalidate paths
   - Return `{ success: true }`

e) `unpublishEvent(eventId: string)`:
   - Same as publish but sets `is_published: false`
   - Revalidate paths
   - Return `{ success: true }`

For update/delete/publish/unpublish: use the service-role client for master users (to bypass RLS ownership check), and regular client for organizers (RLS will enforce ownership).

Validation rules (Claude's discretion):
- Title: required, 3-100 characters
- Description: required, 10-5000 characters
- Date: required, must be valid date string
- Time: required, must be valid time string
- Capacity: optional, if provided must be positive integer
