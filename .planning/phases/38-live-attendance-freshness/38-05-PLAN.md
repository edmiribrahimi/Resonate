<objective>
Subscribe the door to its night, and treat every way the connection can come back
as the same signal.

Purpose: this is the plan that makes LIVE-01 true, and the plan most able to break
LIVE-02 while doing it. The subscription is fire-and-forget by construction —
nothing awaits `SUBSCRIBED` before a scan is allowed, the camera effect is
independent of it, and the status callback writes to exactly one piece of state.
The structural greps that plan 38-03 ran and pasted are the before-figure; this
plan re-runs them, and they must still print nothing.

The hard part is not the subscription. It is the eight-hour night on a phone in a
pocket. The access token lives 3600 seconds; auth-js stops its refresh ticker
while the document is hidden; Realtime disconnects a client whose JWT expires
without a replacement; and the browser's `online` event never fires, because the
radio never went away. Safari and iOS Safari implement neither `freeze` nor
`resume`, so the wake signal has to be assembled by hand from `visibilitychange`,
`pageshow` and `online` — and the correct behaviour is identical for all three,
which is why they are not distinguished.

Output: `ScannerClient.tsx` gains one subscription effect, three resume listeners
inside the block that already exists, the heartbeat wiring, and `channelLive`.
Nothing is rendered yet — plan 38-06 renders it.

### Decisions this plan records

- **D-38-14.** `worker: true` is **not** adopted. It can only be set at client
  construction, `createBrowserClient` is a module-level singleton, so the change
  would land in `src/lib/supabase/client.ts` — a file governed by
  `access-gating.md` and shared by every browser client in the product. And on the
  device that matters it buys little: an iOS home-screen PWA is *suspended*, not
  throttled, so its workers do not run either. `onHeartbeat` is taken instead; it
  needs no construction change. The worker is recorded as an option, not taken.
- **D-38-15.** `private_only` is **not** applied to the project. It is defence in
  depth rather than the boundary — the database sends `private = true`, so a public
  subscriber to the same topic receives nothing anyway — it disconnects every
  connected client when changed, and `GET` does not echo it back, so applying it
  and believing it is not the same as proving it. Recorded as a hardening item with
  its own precondition (never during a night) and its own behavioural proof (a
  public join must answer `PrivateOnly`).
- **D-38-16.** No second Supabase browser client, and no per-call `realtime`
  options. `@supabase/ssr` caches a module-level singleton in the browser, so
  `createClient()` returns the same client every time and the first caller's
  options win silently. With refresh-token rotation on and a 10-second reuse
  window, two clients racing a refresh can put one into a failed refresh and, at
  worst, a sign-out — at the door.
</objective>
