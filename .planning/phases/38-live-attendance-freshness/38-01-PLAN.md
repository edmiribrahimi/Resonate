<objective>
Capture the before-figure and write the evidence procedures, both **before** the
migration file of this phase exists on disk.

Purpose: two of this phase's claims are only meaningful against a baseline. "One
SELECT policy now exists on `realtime.messages`" says nothing unless the zero is
recorded first, and it must be recorded while nothing of this phase has been
written — a baseline taken after the change is not a baseline. The same ordering
constraint was `[BLOCKING]` in phase 36 and it held.

There is a second, sharper reason this plan runs first. The migration's
`SECURITY DEFINER` clause is not a style choice: if the four trigger wrappers run
as the writing session's role, their `INSERT` into `realtime.messages` meets RLS
with no `INSERT` policy, `realtime.send` swallows the refusal in its own
`EXCEPTION WHEN OTHERS THEN RAISE WARNING`, and the emit **silently never
happens** — LIVE-01 degrades into LIVE-04 and every screen still looks right.
That clause is decided by a measurement taken here, under the owner's own working
rule: a check whose outcome changes *what we write* is not deferrable.

Output: one baseline JSON, one procedures document. Nothing is written to
production; every probe is `read_only: true`.
</objective>
