# Plan 29-03: Scan History & Undo Check-in

## Goal
Last 5 scans visible below the scanner viewfinder. Staff can tap any scan in the history to undo the check-in.

## Requirements
- SCAN-09: Undo check-in from scan history
- SCAN-10: Last 5 scans history below viewfinder

## Context

### Current State
- No scan history — each scan shows a single result card that gets replaced on next scan
- No undo capability — once checked in, only admin can manually undo via database
- `resetScanner()` clears all scan state

### Dependencies
- Plan 29-01 (party selection + scoped attendees)
- Plan 29-02 (flash feedback + scan flow)

### Key Files
- `src/app/(admin)/admin/scanner/ScannerClient.tsx` — modified by Plans 29-01 and 29-02
- `src/app/api/tickets/checkin/route.ts` — needs undo endpoint

## Tasks

### Task 1: Undo Check-in API Endpoint

**New route:** `src/app/api/tickets/checkin/undo/route.ts`

**POST handler:**
1. Accept `{ ticketId: string }` in body
2. Require authenticated user with role `master` or `organizer`
3. Look up ticket, verify it's currently `checked_in = true`
4. Set `checked_in = false`, `checked_in_at = null`, `checked_in_by = null`
5. Return `{ success: true }`

**Also handle guest list undo:**
- Accept `{ guestListEntryId: string }` as alternative
- Set `guest_list_entries.status` back to previous state (`ticket_issued` or `invited`)

### Task 2: Scan History State & UI

**File:** `src/app/(admin)/admin/scanner/ScannerClient.tsx`

**State:**
```typescript
interface ScanRecord {
  id: string;           // ticketId or guestListEntryId
  type: 'ticket' | 'membership' | 'guest';
  name: string;
  ticketType?: string;  // tier name
  status: 'success' | 'error';
  reason?: string;      // error reason
  timestamp: number;    // Date.now()
  undone?: boolean;     // true if undo was performed
  canUndo: boolean;     // only successful check-ins can be undone
}

const [scanHistory, setScanHistory] = useState<ScanRecord[]>([]);
```

**After each scan (success or error):**
1. Create `ScanRecord` from the scan result
2. Prepend to `scanHistory` (newest first)
3. Keep only the last 5 entries: `scanHistory.slice(0, 5)`

**History UI — below scanner viewfinder, above attendee list:**
```
┌─────────────────────────────┐
│  📷 Camera viewfinder       │
│  [Flash overlay when active]│
└─────────────────────────────┘
│ Recent Scans                │
│ ✓ Mario Rossi  VIP  22:15  │ ← tap to undo
│ ✗ Already in   —    22:14  │
│ ✓ Anna Verdi   Reg  22:13  │ ← tap to undo
│ ↩ Luigi B.     VIP  22:12  │ ← undone (grayed out)
└─────────────────────────────┘
```

**Each history item shows:**
- Status icon: ✓ green (success), ✗ red (error), ↩ gray (undone)
- Attendee name
- Ticket type (if available)
- Time (HH:MM format)
- For successful (non-undone) scans: tappable to trigger undo

**Undo flow:**
1. Tap a successful scan → confirm prompt: "Undo check-in for [name]?"
2. On confirm: POST to `/api/tickets/checkin/undo` with ticketId
3. On success: mark `undone = true` in scan history, refresh attendee list
4. Show brief toast: "Check-in undone for [name]"
5. Vibrate with error pattern (to distinguish from scan)

## Acceptance Criteria
- [ ] Last 5 scans appear below the viewfinder in real-time
- [ ] Successful scans show green icon + name + ticket type + time
- [ ] Failed scans show red icon + reason + time
- [ ] Tapping a successful scan triggers undo confirmation
- [ ] Undo reverts the check-in (ticket.checked_in = false)
- [ ] Undone scans appear grayed out with ↩ icon
- [ ] Guest list check-ins can also be undone
- [ ] Attendee list refreshes after undo
- [ ] History resets when changing party
