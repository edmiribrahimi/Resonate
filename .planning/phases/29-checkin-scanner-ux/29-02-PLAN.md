# Plan 29-02: Scanner UX — Flash Feedback, Vibration, Continuous Scanning

## Goal
QR scanning becomes instant and continuous: point camera → green/red flash overlay with attendee info → auto-return to scanning. Haptic vibration on every scan. Torch toggle for dark venues.

## Requirements
- SCAN-01: Continuous camera scanning
- SCAN-02: Green flash + name + ticket type on valid scan
- SCAN-03: Red flash + reason on invalid scan
- SCAN-04: Auto-return after flash (~1.5s)
- SCAN-05: Cross-event validation
- SCAN-06: Duplicate shows previous check-in time
- SCAN-08: Flashlight/torch toggle

## Context

### Current State
- Scanner uses `Html5QrcodeScanner` with `{ fps: 10, qrbox: 250x250 }`
- After scan: shows result card + "Scan another QR" button (manual reset)
- No vibration, no flash overlay, no torch
- Scanner doesn't stop after scan (continuous), but UI blocks with result display

### Research Findings
- **Torch**: html5-qrcode has built-in `showTorchButtonIfSupported: true` (works on Android, hidden on iOS)
- **Vibration**: `navigator.vibrate(200)` for success, `navigator.vibrate([100, 50, 100])` for error (Android). iOS needs workaround — use with graceful degradation
- **html5-qrcode**: Supports `.pause()` / `.resume()` for scan control
- **Ticket check-in API** returns `status`: `checked_in`, `already_checked_in`, `not_found`, `invalid_signature`
- API will return `party_id` after Plan 29-01 changes

### Key Files
- `src/app/(admin)/admin/scanner/ScannerClient.tsx` — scanner component (modified by Plan 29-01)
- `src/app/api/tickets/checkin/route.ts` — returns check-in result + party_id

## Tasks

### Task 1: Flash Overlay Component

**New file:** `src/components/scanner/ScanFlash.tsx`

**Component: `ScanFlash`**
- Full-screen overlay (absolute, z-[70] above everything)
- Props: `type: 'success' | 'error'`, `message: string`, `subtitle?: string`, `onDismiss: () => void`
- **Success (green):**
  - Background: `bg-green-500/90` with large checkmark icon
  - Shows attendee name (large) + ticket type (small)
  - Auto-dismiss after 1.5s via `setTimeout`
- **Error (red):**
  - Background: `bg-red-500/90` with X icon
  - Shows reason text (large) + detail (small, e.g. "Checked in at 22:15")
  - Auto-dismiss after 2s (slightly longer for reading error reason)
- Entrance animation: scale from 0.8 to 1 + opacity 0 to 1 (150ms, use motion/react-m)
- Exit: opacity to 0 (100ms)
- Tap anywhere to dismiss early

### Task 2: Vibration Utility

**New file:** `src/utils/haptics.ts`

```typescript
export function vibrateSuccess() {
  if ('vibrate' in navigator) navigator.vibrate(200);
}

export function vibrateError() {
  if ('vibrate' in navigator) navigator.vibrate([100, 50, 100]);
}
```

Keep it simple — graceful degradation on iOS (no-op if not supported).

### Task 3: Rewrite Scanner QR Handling in ScannerClient

**File:** `src/app/(admin)/admin/scanner/ScannerClient.tsx`

**Scanner Initialization Changes:**
1. Switch from `Html5QrcodeScanner` (UI-heavy) to `Html5Qrcode` (headless) for full control:
   ```typescript
   const html5Qrcode = new Html5Qrcode("qr-reader");
   await html5Qrcode.start(
     { facingMode: "environment" },
     { fps: 15, qrbox: { width: 280, height: 280 } },
     onScanSuccess,
     () => {} // ignore errors
   );
   ```
2. Add `showTorchButtonIfSupported: true` — OR use custom torch toggle via `html5Qrcode.applyVideoConstraints({ advanced: [{ torch: true }] })`
3. Store `html5Qrcode` instance in ref for pause/resume control

**Scan Flow (onScanSuccess callback):**
1. **Debounce**: Ignore if a flash is currently showing (prevent rapid re-scans of same QR)
2. **Pause scanner** during verification: `html5Qrcode.pause(true)` (keep camera stream, stop decoding)
3. **Verify QR** via existing API calls (ticket / membership)
4. **Cross-event validation** (SCAN-05):
   - API returns `party_id` with check-in response
   - Compare `response.party_id` with `selectedPartyId`
   - If mismatch: show red flash "Ticket for [party name]" instead of checking in
   - Note: The checkin API should NOT check-in if party doesn't match — add `partyId` param to POST
5. **Show ScanFlash** with appropriate type:
   - `checked_in` → green flash, name + ticket type, `vibrateSuccess()`
   - `already_checked_in` → red flash, "Already checked in" + time (SCAN-06), `vibrateError()`
   - `not_found` → red flash, "Ticket not found", `vibrateError()`
   - `invalid_signature` → red flash, "Invalid QR code", `vibrateError()`
   - Party mismatch → red flash, "Ticket for [other party]", `vibrateError()`
6. **Auto-return**: After flash dismisses (1.5-2s), resume scanner: `html5Qrcode.resume()`
7. **Refresh attendee list** after successful check-in

**Torch Toggle:**
1. Add torch state: `const [torchOn, setTorchOn] = useState(false)`
2. Torch button visible only when scanner is active
3. Toggle via `html5Qrcode.applyVideoConstraints({ advanced: [{ torch: !torchOn }] })`
4. If torch not supported (iOS), hide the button — check via `getRunningTrackSettings()`

### Task 4: Update Check-in API for Party Validation

**File:** `src/app/api/tickets/checkin/route.ts`

**Changes:**
1. Accept optional `partyId` in POST body alongside `token`
2. After HMAC verification and ticket lookup, if `partyId` is provided:
   - Compare ticket's `party_id` (or `event_id` for event passes) with the provided `partyId`
   - If mismatch: return `{ valid: false, status: "wrong_event", event_title, party_title }` WITHOUT checking in
3. Include `checked_in_at` in `already_checked_in` response (for SCAN-06)
4. Include `party_id`, `event_id` in all responses
