# Plan 29-04: Offline Check-in Support

## Goal
Check-in works without internet connectivity. Attendee data is pre-cached when selecting a party. Offline check-ins are queued and synced when back online.

## Requirements
- SCAN-07: Offline support — check-in works without connectivity, syncs when back online

## Context

### Research Findings
- **IndexedDB wrapper**: `idb` by Jake Archibald (~1.2kB brotli) — lightweight, promise-based
- **Service Worker**: Serwist + @serwist/next (recommended by Next.js docs, successor to next-pwa)
- **Sync strategy**: Manual `online`/`visibilitychange` event listeners (Background Sync API not supported on iOS)
- **HMAC verification**: Cannot do client-side (would expose TICKET_SIGNING_SECRET) — must match by pre-cached ticket IDs

### Dependencies
- Plan 29-01 (party selection provides the pre-cache trigger)
- Plan 29-02 (scan flow needs offline/online branching)

### Key Files
- `src/app/(admin)/admin/scanner/ScannerClient.tsx` — scan flow
- `src/app/api/tickets/attendance/route.ts` — attendee data source
- `src/app/api/tickets/checkin/route.ts` — check-in endpoint (sync target)

### Known Limitations
- Tickets purchased while device is offline won't appear until sync
- Multi-device: two staff scanning the same ticket offline on separate phones will both see green; duplicate detected on sync
- Membership QR offline: can only verify if member data was pre-cached

### Task 2: IndexedDB Schema & Offline Store

**New file:** `src/lib/offline/checkin-store.ts`

**Schema:**
```typescript
import { openDB, DBSchema } from 'idb';

interface CheckinDB extends DBSchema {
  attendees: {
    key: string; // ticketId
    value: {
      ticketId: string;
      partyId: string;
      name: string;
      email?: string;
      tierName?: string;
      ticketType: 'purchased' | 'guest_list';
      checkedIn: boolean;
      checkedInAt?: string;
      isGuestListEntry?: boolean;
      guestListEntryId?: string;
    };
    indexes: {
      'by-party': string;
    };
  };
  pendingCheckins: {
    key: string; // ticketId or guestListEntryId
    value: {
      id: string;
      type: 'ticket' | 'guest';
      checkedInAt: string;
      partyId: string;
    };
  };
}
```

**Functions:**
- `cacheAttendees(partyId, attendees[])` — bulk write attendees for a party (called on party selection)
- `findAttendee(ticketId)` — lookup by ticket ID
- `checkInLocally(ticketId)` — mark checked_in=true, add to pendingCheckins
- `undoCheckInLocally(ticketId)` — revert, remove from pendingCheckins
- `getPendingCheckins()` — get all unsynced check-ins
- `markSynced(ticketId)` — remove from pendingCheckins after server confirms
- `clearPartyCache(partyId)` — cleanup when switching parties

### Task 5: Sync Manager

**New file:** `src/lib/offline/sync-manager.ts`

**Sync logic:**
```typescript
export async function syncPendingCheckins() {
  if (!navigator.onLine) return;
  const pending = await getPendingCheckins();
  for (const checkin of pending) {
    try {
      if (checkin.type === 'ticket') {
        // Re-do the check-in via API (server is idempotent)
        await fetch('/api/tickets/checkin', {
          method: 'POST',
          body: JSON.stringify({ token: checkin.id, partyId: checkin.partyId })
        });
      } else {
        await fetch('/api/tickets/attendance', {
          method: 'POST',
          body: JSON.stringify({ guestListEntryId: checkin.id })
        });
      }
      await markSynced(checkin.id);
    } catch {
      // Keep in queue for next sync attempt
    }
  }
}
```

**Sync triggers:**
1. `window.addEventListener('online', syncPendingCheckins)`
2. `document.addEventListener('visibilitychange', ...)` — sync when app returns to foreground
3. After every successful online check-in — piggyback sync of any pending items
4. On party selection (when fetching fresh attendee data)

**Conflict handling:**
- Server check-in API is idempotent (already_checked_in is not an error)
- If server returns `already_checked_in` for a pending sync, just mark as synced

### Task 6: Checkin API — Idempotency

**File:** `src/app/api/tickets/checkin/route.ts`

**Changes:**
1. When a ticket is already checked in AND the `checked_in_by` matches the current user, return success (not error)
2. This makes the sync replay safe — re-sending the same check-in doesn't cause issues
3. Only return `already_checked_in` when a DIFFERENT user/device checked it in
