Create migration `supabase/migrations/20260310100000_discount_codes.sql` with:

1. **discount_codes table:**
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
   - `party_id uuid NOT NULL REFERENCES public.event_parties ON DELETE CASCADE`
   - `code text NOT NULL`
   - `discount_type text NOT NULL CHECK (discount_type IN ('percentage', 'fixed'))`
   - `discount_amount numeric(10,2) NOT NULL CHECK (discount_amount > 0)`
   - `max_uses integer` (NULL = unlimited)
   - `is_active boolean NOT NULL DEFAULT true`
   - `created_at timestamptz DEFAULT now()`
   - `updated_at timestamptz DEFAULT now()`
   - Case-insensitive unique constraint: `CREATE UNIQUE INDEX discount_codes_party_code_unique ON public.discount_codes (party_id, LOWER(code));`

2. **discount_code_tiers junction table:**
   - `discount_code_id uuid NOT NULL REFERENCES public.discount_codes ON DELETE CASCADE`
   - `tier_id uuid NOT NULL REFERENCES public.ticket_tiers ON DELETE CASCADE`
   - `PRIMARY KEY (discount_code_id, tier_id)`

3. **Column additions:**
   - `ALTER TABLE public.tickets ADD COLUMN discount_code_id uuid REFERENCES public.discount_codes ON DELETE SET NULL;`
   - `ALTER TABLE public.pending_purchases ADD COLUMN discount_code_id uuid REFERENCES public.discount_codes ON DELETE SET NULL;`

4. **RLS policies for discount_codes:**
   - SELECT: `USING (true)` -- buyers need to read for validation (codes are distributed via passaparola, so open SELECT is fine)
   - INSERT: `WITH CHECK ((SELECT public.is_admin_or_organizer()))`
   - UPDATE: `USING ((SELECT public.is_admin_or_organizer()))`
   - DELETE: `USING ((SELECT public.is_admin_or_organizer()))`

5. **RLS policies for discount_code_tiers:**
   - Same pattern as discount_codes (SELECT open, INSERT/UPDATE/DELETE admin_or_organizer)

6. **Updated reserve_ticket() RPC** -- Add `p_discount_code_id uuid DEFAULT NULL` parameter. Inside the function, BEFORE the ticket INSERT:
   - If `p_discount_code_id IS NOT NULL`, SELECT the discount_codes row with `FOR UPDATE` lock
   - Verify `is_active = true`, raise exception if not found or inactive
   - If `max_uses IS NOT NULL`, count existing tickets with that `discount_code_id`, raise exception if `count >= max_uses`
   - Add `discount_code_id` to the INSERT INTO tickets statement
   - Use `DEFAULT NULL` for the parameter to preserve backward compatibility with existing calls

Also update `supabase/schema.sql` to reflect the new tables and column additions (append discount_codes and discount_code_tiers table definitions, add discount_code_id columns to tickets and pending_purchases, add RLS policies). Do NOT modify existing schema.sql entries -- only append new content.

**2. Update `src/app/(organizer)/organizer/events/[id]/tickets/actions.ts`** -- Add 4 new server actions following the EXACT pattern of existing `createTier`/`updateTier`/`deleteTier`:

**`createDiscountCode(eventId: string, partyId: string, formData: FormData)`:**
- Calls `verifyOrganizer()` + `verifyEventOwnership()`
- Extracts from FormData: `code` (string, required, trim), `discount_type` (percentage|fixed), `discount_amount` (number >0), `max_uses` (number|null), `is_active` (boolean, default true), `tier_ids` (JSON string of tier IDs or empty for all tiers)
- Validates: code not empty, discount_type is 'percentage' or 'fixed', discount_amount >0, if percentage then discount_amount <=100
- Uses service client for master, user client for organizer (same pattern as createTier)
- Inserts into `discount_codes` table
- If `tier_ids` is provided and non-empty, inserts rows into `discount_code_tiers` junction table
- Calls `revalidatePath(/organizer/events/${eventId}/tickets)`
- Returns `{ success: true }`

**`updateDiscountCode(discountCodeId: string, eventId: string, formData: FormData)`:**
- Same auth pattern as updateTier
- Updates: code, discount_type, discount_amount, max_uses, is_active, updated_at
- Handles tier_ids: delete existing junction rows, re-insert new ones (if provided)
- Revalidates path, returns `{ success: true }`

**`deleteDiscountCode(discountCodeId: string, eventId: string)`:**
- Same auth pattern as deleteTier
- Check ticket count with this discount_code_id -- if >0, throw "Cannot delete a discount code that has been used"
- Deletes from discount_codes (cascade handles junction table)
- Revalidates path, returns `{ success: true }`

**`validateDiscountCode(partyId: string, code: string)`:**
- This is a PUBLIC action (no organizer verification) -- any authenticated user can validate
- Creates supabase client, queries discount_codes with `.eq("party_id", partyId).ilike("code", code.trim()).single()`
- Checks `is_active`, throws "Codice non piu attivo" if false
- Checks usage limits: count tickets with `discount_code_id`, throw "Codice esaurito" if count >= max_uses
- Queries discount_code_tiers junction table for tier restrictions
- Returns `{ id, discount_type, discount_amount, applicable_tier_ids }` where applicable_tier_ids is `string[] | null` (null = all tiers)
- Error messages in Italian: "Codice non valido", "Codice non piu attivo", "Codice esaurito"
