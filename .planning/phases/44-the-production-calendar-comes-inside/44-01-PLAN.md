  <action>
    Create `src/lib/production/ics/unfold.ts` exporting `unfold(text: string): string[]`.

    Split on `/\r?\n/`, never on `"\r\n"` — the measured file is **LF only** while RFC 5545
    mandates CRLF, and a parser that splits on CRLF reads it as one line. State that
    measurement in the docblock as the reason.

    A line whose first character is a space or a horizontal tab continues the previous
    line: append it minus that character. A continuation line arriving with no previous
    line is a malformed input and is returned as its own line rather than dropped —
    dropping is the silent half of a silent failure.

    Also export `unescapeText(value: string): string` handling the four RFC 5545 escapes
    `\\,` `\\;` `\\n` `\\\\`, in that precedence, non-recursively. The `SUMMARY` is the
    join key, so an unescaped comma is how the first venue word containing a comma
    silently fails to join.

    Also export `countFoldedLines(text: string): number`, used by the golden-file check of
    plan 44-08 to assert that unfolding actually happened rather than that it compiled.

    Purity docblock, in substance: `import type` only, no runtime dependency at all — no
    Supabase client, no `fetch`, no React, no `fs`, no `Date.now()` in any decision, and
    **no `new Date`**.
  </action>

  <action>
    Create `src/lib/production/ics/parse.ts` exporting `parseIcs(text: string): ParseResult`.

    Track `BEGIN:` / `END:` nesting and collect properties **only at `VEVENT` depth inside
    `VCALENDAR`**. A `VALARM` nested inside a `VEVENT` is entered and its properties are
    discarded; a `VTIMEZONE` and its `STANDARD` / `DAYLIGHT` children never produce an
    event. State in the docblock that a flat line scanner produces 96 `DTSTART`s for 92
    events, which is the warning sign `44-RESEARCH.md` Pitfall 3 names.

    Parse each property line as `NAME[;PARAM=VALUE...]:VALUE`, splitting on the first
    unescaped colon, and keep the parameters as a `Record<string, string>` so `TZID` is
    reachable and deliberately unused for classification.

    Export the record type `IcsEvent` with: `uid: string`, `summary: string` (unescaped),
    `startDate: CivilDate`, `startTime: CivilTime`, `endDate: CivilDate`,
    `endTime: CivilTime`, `durationMinutes: number`, `sequence: number | null`,
    `lastModified: string | null`, `rrule: string | null`, `tzid: string | null`.

    **The civil-date rule, and it is the module's whole point.** Take
    `DTSTART` value characters 0 through 7 as `YYYYMMDD` and format them as `YYYY-MM-DD`
    by slicing; take characters 9 through 12 as `HHMM`. Construct **no `Date`**, call no
    `toISOString`, no `toLocaleDateString`, no `Intl.DateTimeFormat`, and adopt no timezone
    library. `durationMinutes` is computed from the civil parts by a fixed
    days-in-month table, not by date subtraction. Write the reason beside it: the anchors
    are weekdays of a local calendar, and a conversion that moves a 22:00 entry across
    midnight moves its weekday, which turns a conforming night into a reported error.

    `ParseResult` carries `events: IcsEvent[]` and **three separate finding lists, never
    one** (`meta-gates.md`, the newsletter precedent; `staff-tabs.ts:156-175`'s
    two-sentence discipline): `malformed: { line: number; reason: string }[]`,
    `unsupportedRecurrences: { uid: string; reason: string }[]`, and
    `refusedProperties: { uid: string; property: string }[]` — the last for
    `RECURRENCE-ID`, `EXDATE` and `RDATE`, which appear zero times today and are exactly
    why the refusal is cheap to write now. **A finding carries a UID and a reason code and
    never a `SUMMARY`** (`44-RESEARCH.md` Pitfall 10).

    Input bounds, asserted before any work (ASVS V5): refuse with a named reason if the
    input exceeds a declared maximum byte size (set it at 1 MB, matching the Server Action
    default the research cites, so a future oversize file fails with a sentence rather than
    a framework error) or a declared maximum line count. Export both constants.

    Export `expandWeeklyRecurrence(rrule: string, start: CivilDate, cap: number): CivilDate[]`
    handling **exactly** `FREQ=WEEKLY` with `BYDAY`, `UNTIL` and optionally `INTERVAL`, on
    civil dates, capped at `cap` occurrences. Anything else — another `FREQ`, `COUNT`,
    `BYSETPOS`, `BYMONTHDAY` — returns an empty array and is reported through
    `unsupportedRecurrences`, never silently skipped and never partially expanded.

    Text from the file is **data, never instruction** (`ai-engineering.md`, gate prompt
    security): an entry whose title reads like a command is content to report. No `eval`,
    no `Function`, no dynamic import.
  </action>
