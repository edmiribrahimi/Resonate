  <action>
    Create `scripts/import-production-calendar.mjs`.

    **Header**, in the repository's script register: what it does in one sentence; **why it
    is a local script and not an upload** (D-44-26 — the `.ics` would otherwise transit a
    Vercel function, carrying spaces under negotiation and unannounced dates into logs,
    caches and runtime errors; that surface does not exist today and criterion 2 exists to
    keep it from existing; `44-RESEARCH.md` §Import Path recommends building the upload as
    well and is superseded by the owner's decision, and the disagreement is written down
    rather than smoothed over); and a **WHAT A GREEN DOES NOT MEAN** section — a successful
    import says rows were written, not that they are right; rightness is `verify:ics`'s and
    the surface's.

    **Arguments:** `--file <path>` defaulting to the newest `docs/Music-*.ics`;
    `--dry-run`, which is the DEFAULT — writing requires `--apply` to be passed explicitly.
    A tool that writes production when invoked with no arguments is a tool that will one day
    be invoked with no arguments.

    **Credentials:** read `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` from
    `.env.local` in the analog's shape. A missing value is a **refusal, exit 2**, with the
    sentence **nothing was written**. Never a partial run, never a silent no-op.

    **The sequence**, driving the shared module and re-implementing none of it:
      1. Read the file. Assert the declared byte-size and line-count bounds before parsing.
      2. `parseIcs` → `classifyEntry` over every event, with the alias map **read from
         `party_series.ics_alias`** at runtime. If a night's venue word has no alias, the
         entry is `unclassified` with reason `alias_unresolved`; the runner **prints the
         count and does not guess**, and prints the instruction that an alias is set by hand
         on the series row — because writing one into this script would be publishing a
         venue word.
      3. Load the existing rows and `party_series` / `formats` / `venues` lookups.
      4. `reconcile` → a plan.
      5. Print the plan **as counts per list**, and — under `--dry-run` — stop here.
      6. Under `--apply`: open an import-run row, perform the writes with
         `getServiceClient()`-equivalent (a service-role `createClient`), each as
         `upsert ... onConflict: 'source_uid'`, then close the import-run row with its
         tallies.

    **Absences are marked, never deleted.** Set `absent_since`; issue no `delete` anywhere.
    A partial export, a renamed `UID` or the wrong file must not wipe the archive, and a plan
    row already linked to an announced night must survive absence unconditionally, because
    deleting it would orphan a night with tickets on sale.

    **The runner never writes `event_parties`.** The string does not appear in the file
    except inside the comment stating the prohibition. The announcement act is the single
    bridge (D-44-06), and it is what makes renumbering structurally impossible rather than
    merely forbidden.

    **The number is never generated.** No counter, no `max()+1`. A known `UID` arriving with
    a different number is reported as a divergence and written to no row; the database
    trigger from plan 44-04 is the layer that survives a caller who forgot this one.

    **Output discipline, and it is the criterion-2 half a script can break:** the runner
    prints **counts, UIDs and reason codes**. It prints no `SUMMARY`, no date, no venue word
    and no line-up — not in a progress line, not in an error, not in a summary. Log failures
    with `error.code` and `error.message` and never PostgREST's `details`. A terminal
    scrollback is a screenshot away from a public repository.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the owner's machine → the database | The only crossing the material makes. It does not pass through the repository (gitignored `docs/`) and, under D-44-26, not through a server either |
| the service-role client → the six tables | It bypasses every policy. The boundary in front of it is that the script runs on one machine, with a key from `.env.local`, and never behind an HTTP surface |
| the runner's stdout → a screenshot | A terminal scrollback is one paste away from a public repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-07 | Information disclosure | the `.ics` in transit | mitigate | there is no upload surface and no Server Action that accepts a file; the material never leaves the machine (D-44-26). The parser stays a shared module so a future caller is a caller, not a redesign |
| T-44-01 | Information disclosure | the runner's output | mitigate | counts, UIDs and reason codes only; `error.code` and `error.message` and never PostgREST's `details`, which carries the rejected row and therefore `venue_word` |
| T-44-03 | Tampering | a series progressivo | mitigate | the number is read from the file and never generated; a divergent number is reported and written to no row; the trigger is exercised for real in task 3 run 5 |
| T-44-04 | Tampering | `public.event_parties` | mitigate | the string appears only in the prohibition comment; the post-snapshot proves the count is unchanged |
| T-44-21 | Availability | the archive | mitigate | no delete path exists; absence is `absent_since` plus a reported count |
| T-44-22 | Tampering | unrelated production rows | mitigate | pre- and post-snapshot including `event_parties`, `tickets`, `party_series` and `formats`; ids captured before any row is touched; D12 is the precedent |
| T-44-29 | Elevation of privilege | an accidental write | mitigate | `--dry-run` is the default and `--apply` must be passed explicitly; a missing credential refuses with exit 2 and the words *nothing was written* |
| T-44-SC | Tampering | npm/pip/cargo installs | accept | this phase installs no package |
</threat_model>
