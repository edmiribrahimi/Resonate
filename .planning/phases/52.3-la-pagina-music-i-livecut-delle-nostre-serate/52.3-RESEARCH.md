## Summary

La pagina e' tecnicamente semplice e politicamente densa. Il codice dice tre
cose che il ROADMAP non sapeva. **Primo: non esiste un'entita' slot a cui un
LiveCut possa puntare.** L'unica tabella di slot, `production_lineup_slot`, e'
uno specchio del calendario privato che il cron **cancella e reinserisce a ogni
corsa** (`src/app/api/cron/production-mirror/route.ts:1271` delete, `:1476`
insert), e' leggibile solo con `production.calendar.manage`
(`20260822120000_production_lineup_slot.sql:159-162`) e porta nomi di artisti su
date non annunciate. Un FK verso di lei o verrebbe cancellato in cascata a ogni
corsa o bloccherebbe lo specchio. Quindi **il LiveCut porta la fascia oraria
denormalizzata** e si lega alla **serata** (`event_parties`) e agli **artisti**
(`artists`) per FK, esattamente come `party_credits`
(`20260809003000_party_credits.sql`). **Secondo: nella barra pubblica non c'e'
nessuna voce «Artists».** L'anonimo vede `Events · Account` (`roles.ts:500`), e
non esiste una pagina indice degli artisti, solo `/artists/[slug]`. «Accanto a
Events e Artists» e' un'inesattezza del ROADMAP: Music sara' la seconda voce
pubblica, e per chi lavora una quinta voce che **sposta Check-in** sulla barra
della porta (`DoorSurface.tsx` monta `AppNav`). **Terzo: la pagina puo' essere
una superficie «mai»** come la pagina d'ordine dell'ospite: non mostra nessun
luogo in nessun momento, quindi non consulta il predicato di rivelazione e si
verifica con una allow-list positiva delle colonne selezionate, la forma del
check G di `verify-venue-surfaces.mjs:946-1235`.

Per il player, la Widget API di SoundCloud e' documentata
([developers.soundcloud.com/docs/api/html5-widget](https://developers.soundcloud.com/docs/api/html5-widget)):
`SC.Widget(iframe)`, `load(url, options)` che ricarica lo stesso iframe
mantenendo i listener, eventi `READY`/`PLAY`/`PAUSE`/`FINISH`/`PLAY_PROGRESS`/`ERROR`.
L'oEmbed, **sondato dal vivo in questa sessione**, restituisce `title`,
`thumbnail_url`, `author_name` e un `html` che contiene l'URL
`api.soundcloud.com/tracks/<id>` — **non restituisce la durata** — e risponde
**404** per un brano inesistente. Il rischio vero non e' l'API: e' **iOS Safari**,
dove un `play()` chiesto dalla pagina madre a un iframe di un'altra origine puo'
non contare come gesto dell'utente. Va provato in un'onda 0 sul laboratorio, con
un ripiego disegnato (iframe compatto visibile nella barra), prima di costruire il
resto.

Sul calendario: il primo LiveCut reale non puo' esistere prima della notte del 10
ottobre e MUS-10 vieta comunque i LiveCut reali in produzione prima delle tre
risposte legali. **Raccomandazione:** la fase si chiude sul laboratorio prima del
10 ottobre (pagina vera, dati dichiarati, giudizio del proprietario), e il codice
che arriva in produzione col deploy dell'8 ottobre — se ci arriva — e' **spento**
da un interruttore (`NEXT_PUBLIC_MUSIC_PAGE_ENABLED`): nessuna voce in barra, la
rotta risponde 404, la barra della porta resta identica a stanotte. Si accende su
«vai», dopo le risposte legali e col primo LiveCut pronto.

**Primary recommendation:** tabella `livecuts` (serata + fascia denormalizzata +
URL SoundCloud verificato via oEmbed in admin + durata + cover nel bucket
pubblico gia' esistente sotto chiave opaca) piu' `livecut_artists` per il b2b;
pagina `/music` dinamica, superficie «mai» sorvegliata da un check H nuovo;
un iframe SoundCloud creato al primo play e riusato con `load()`; tutto dietro un
interruttore spento in produzione fino a «vai».

solo (spazza ogni `"use client"` sotto `src/app/(public)/`,

### Pattern 1: superficie «mai» con allow-list positiva (MUS-05)

**Cosa:** la pagina non mostra un luogo in nessun momento, quindi **non importa il
predicato di rivelazione** e **non seleziona nessuna colonna di luogo**. Si
verifica misurando l'insieme chiuso delle colonne selezionate, non cercando nomi.

**Quando:** `/music`, i suoi metadata, la barra del player, la scheda, il modulo
`src/lib/livecuts/queries.ts`, e il form/le action admin (che leggono il venue
**solo** per la guardia sull'URL, vedi sotto — quindi l'admin sta in una lista a
parte, con il venue dichiarato).

**Forma (dal check G, `verify-venue-surfaces.mjs:1045-1170`):**
- H1 sweep negativa sul codice vivo (stripper `scripts/lib/comments.mjs`), termini
  `venue`, `address`, `latitude`, `longitude`, `google_maps`, `coordinate`, piu'
  `secret` (la pagina non ha ragione di nominarlo);
- H2 allow-list positiva di ogni letterale `.select("…")` e del loro **numero**;
- H3 nessun import di `venue-disclosure`;
- H4 forma: rotta dinamica dichiarata, interruttore letto, nessun `next/script`
  che carichi `api.js` a caricamento;
- H5 **sweep delle parole di genere** (vedi §Parole vietate) sui letterali di
  stringa dei file della pagina e sul file di semina del laboratorio.

### Pattern 2: titolo calcolato, mai salvato (MUS-04, D-52.3-03)

**Cosa:** `<artista> @ <format>, <data>` si **calcola** da `artists.name` (in
ordine, b2b uniti), `party_series.name` e `event_parties.date`. Nessuna colonna
`title`, nessuna colonna `description` sulla tabella: **un campo di testo libero
non c'e', quindi non puo' portare un luogo ne' un aggettivo**.

**Perche' `party_series.name`:** e' «il nome pieno come sta sull'app» —
`re:sonate`, `re:sonate x Perlone`, `RamaDub x Booze`, `RamaDub x Muro`
(`20260810120000_formats_and_series.sql:534-537`). Il locale compare solo dove la
serie lo porta gia'. Precedente da conoscere: `composeNightTitle` del calendario
usa il **format** e non la serie, proprio per non pubblicare una parola di luogo
interna (`src/app/(admin)/admin/calendar/actions.ts:515-535`) — qui la serie e'
corretta perche' una serie la crea il catalogo per una sede gia' in rotazione, ma
una serata segreta della notte ha serie `re:sonate`, senza luogo.

```typescript
// src/lib/livecuts/title.ts — puro, nessun import (come src/lib/capabilities/keys.ts)
const MONTHS = ["Jan","Feb","Mar","Apr","May","Jun","Jul","Aug","Sep","Oct","Nov","Dec"] as const;
/** Anno: DUE cifre oggi, punto aperto dal 2026-08-15 (D-52.3-03). Una costante, una casa. */
export const LIVECUT_TITLE_YEAR_DIGITS: 2 | 4 = 2;

export function liveCutTitle(artistNames: readonly string[], seriesName: string, civilDate: string): string {
  // civilDate "YYYY-MM-DD": si legge a pezzi, MAI con new Date(), che sposta il giorno fuori fuso
  const [y, m, d] = civilDate.split("-");
  const year = LIVECUT_TITLE_YEAR_DIGITS === 2 ? y.slice(2) : y;
  const artists = artistNames.join(" b2b ");          // [ASSUMED] la congiunzione del b2b non e' decisa
  return `${artists} @ ${seriesName}, ${Number(d)} ${MONTHS[Number(m) - 1]} ${year}`;
}
```

Due punti **non decisi** emergono scrivendo la funzione, e vanno al proprietario
(non si inventano): l'anno a 2 o 4 cifre (gia' aperto), **la congiunzione del
b2b** (`A b2b B`? `A & B`?) e **settembre** (`Sep` come `formatTime.ts:7` o
`Sept` come il gate *lingua dei materiali* di `brand-visual-system.md`).

### Pattern 3: un iframe, creato al primo play, riusato con `load()` (MUS-06)

```tsx
"use client";
// src/app/(public)/music/MusicPlayer.tsx — schizzo, non codice finale
// Fonte API: https://developers.soundcloud.com/docs/api/html5-widget
// VIETATO useSyncExternalStore, matchMedia, innerWidth (verify:no-viewport-read, zero eccezioni)
type Current = { trackId: string; permalink: string; title: string; slot: string } | null;

function widgetSrc(trackId: string) {
  const url = encodeURIComponent(`https://api.soundcloud.com/tracks/${trackId}`); // forma dell'html oEmbed, sondata
  // parametri documentati: auto_play, color, buying, sharing, download, show_artwork, show_user, show_playcount
  return `https://w.soundcloud.com/player/?url=${url}&auto_play=true&color=%23FF5C93` +
         `&show_artwork=false&show_user=true&buying=false&sharing=false&download=false&show_playcount=false`;
}

async function loadApi(): Promise<void> {           // iniettato al gesto, mai con next/script
  if ((window as any).SC?.Widget) return;
  await new Promise<void>((resolve, reject) => {
    const s = document.createElement("script");
    s.src = "https://w.soundcloud.com/player/api.js";
    s.onload = () => resolve();
    s.onerror = () => reject(new Error("music_player.api_unreachable"));
    document.head.appendChild(s);
  });
}
// Al primo play: loadApi() → render <iframe src={widgetSrc(id)} allow="autoplay; encrypted-media">
// → SC.Widget(iframe).bind(READY, …).bind(PLAY, …).bind(PAUSE, …).bind(FINISH, …).bind(ERROR, …)
// Ai play successivi: widget.load(url, { auto_play: true, callback: () => … })
// Timeout READY (es. 10 s) → categoria music_player.ready_timeout, frase visibile + link SoundCloud
// PLAY non arrivato entro ~3 s dopo il tocco → music_player.play_refused: mostra l'iframe compatto
```

### Pattern 4: la voce in barra dietro un interruttore pubblico

`getNavigation` e' una funzione pura che gira **anche sul client**
(`src/components/layout/AppNav.tsx:1,7,348`), quindi un interruttore letto li'
deve essere `NEXT_PUBLIC_*` (inlinato al build; cambiarlo chiede un redeploy).
Precedente di interruttore per ambiente: `ORDER_RESUME_EMAIL_ENABLED`
(`comms-analytics.md`). La barra si filtra su sessione, ruolo e capability
(`roles.ts:533-538`): un interruttore di **deploy** non e' un quarto criterio sul
soggetto, ma va dichiarato nel docblock come tale.

**Posizione — decisione del proprietario, con una raccomandazione di dominio.**

(`roles.ts:502-505`) ed e' montata anche dalla **porta**
(`src/app/(admin)/admin/scanner/DoorSurface.tsx`). Mettere Music seconda per
tutti **sposta Check-in al terzo posto sul telefono della porta** e mette una
voce che porta via dallo scanner accanto a quella che lo apre — al buio, con una
mano (`nextjs-architecture.md`, gate *accessibilita' al buio*).
**Raccomandazione:** `Events · Music · Account` per anonimo e attendee;

seconda. Con `flex-1` (`AppNav.tsx:500,550`) cinque voci stanno su 375 px.

### Anti-Patterns to Avoid

- **Un FK verso `production_lineup_slot`**: cancellato e rifatto a ogni corsa
  (`production-mirror/route.ts:1271,1476`), privato, con nomi non annunciati.
- **Ordinare gli slot per orario**: una notte va 22:00 → 06:00, e `00:30` ordina
  prima di `22:00` (`database.ts`, commento su `end_time` di
  `ProductionLineupSlot`). Si ordina per `part_number`.
- **Iniettare l'`html` dell'oEmbed**: e' markup di terzi (contiene anche la
  descrizione del brano). Si estrae l'id e si costruisce l'`src` da noi.
- **Mostrare la `description` dell'oEmbed**: testo libero scritto su SoundCloud,
  puo' contenere generi o luoghi. Mai sulla pagina.
- **`next/script` per `api.js`**, anche `lazyOnload`: carica senza play, contro
  MUS-06 e contro l'informativa.
- **Una colonna `description` o `title` sulla tabella**: testo libero = uscita
  che nessun predicato vede (`venue-secrecy.md`, *naming a night*).
- **Un contatore «N slot» per serata**: un dj che nega il consenso (MUS-10) lascia
  uno slot senza LiveCut. Si conta cio' che e' pubblicato, mai la timetable.
- **`useSyncExternalStore` per lo stato del player**: vietato senza eccezioni da
  `verify:no-viewport-read` (`scripts/verify-no-viewport-read.mjs:6-12`). Si usa
  un contesto React con `useState`/`useReducer`.
- **`<table>` per la timetable**: `verify:tables` ammette solo `DataTable` o la
  lista dichiarata; una lista di schede non ne ha bisogno.

### 7. Prestazioni e cache

- **Regione**: `vercel.json` → `"regions": ["dub1"]`, accanto a Supabase
  `eu-west-1` (`privacy/page.tsx:14-17`).
- **Rendering**: ogni pagina pubblica e' dinamica per costruzione
  (`getAccessContext()` legge i cookie); una «pagina pubblica in cache» non e'
  possibile senza togliere la barra dipendente dalla sessione. **Raccomandazione:**
  `/music` dichiara `force-dynamic` con una ragione propria — **un ritiro (consenso
  revocato, richiesta legale) deve sparire subito**, non a una scadenza.
- **Root layout**: carica lo SDK SumUp su **ogni** pagina con
  `strategy="afterInteractive"` (`src/app/layout.tsx:136-139`) — un costo che
  anche `/music` paga; fuori perimetro, ma va saputo quando si misura il peso.
- **CSP**: **nessuna** — nessun `headers()` in `next.config.ts`, nessun
  `Content-Security-Policy` in `src/`, `vercel.json` o `public/` (grep del
  2026-10-03). Il widget non e' bloccato da nulla del nostro lato.
- **Service worker**: `/music` oggi cadrebbe nella regola di default delle pagine
  (NetworkFirst, 24 h) di `@serwist/next` 9.5.6
  (`node_modules/@serwist/next/dist/index.worker.js:225-255`), quindi una copia
  di un LiveCut **ritirato** potrebbe essere servita offline. **Raccomandazione:**
  regola `NetworkOnly` per `/music` accanto a quella di `/events/*`
  (`src/app/sw.ts:115-118`). `api.js` di terzi cade nella regola `cross-origin`
  (NetworkFirst, 1 h): innocuo. L'audio corre dentro l'iframe di un'altra origine,
  che il nostro worker non controlla.

## Common Pitfalls

### Pitfall 1: iOS Safari rifiuta il play comandato dalla pagina
**Cosa va storto:** il tocco avviene sulla nostra pagina, il `play()` arriva
all'iframe di un'altra origine via `postMessage`; Safari puo' non considerarlo un
gesto dell'utente e non suonare. **Perche':** politiche di autoplay e
attivazione utente per iframe cross-origin ([ASSUMED], non documentato da
SoundCloud). **Come evitarlo:** onda 0 sul laboratorio, telefono vero; ripiego
disegnato: iframe compatto **visibile** nella barra e frase *«Tap play in the
player»* se `PLAY` non arriva. **Segnale:** su desktop funziona, su telefono no.

### Pitfall 2: lo stato del player con `useSyncExternalStore`
**Cosa va storto:** `verify:no-viewport-read` diventa rosso, senza eccezioni.
**Come evitarlo:** contesto React + `useReducer`; adattamento al telefono solo in
CSS (`md:`).

### Pitfall 3: la barra del player copre l'ultima scheda e la barra di navigazione
**Come evitarlo:** posizionare la barra con `bottom: var(--nav-inset-block-end)`
su telefono e `inset-inline-start: var(--nav-inset-inline-start)` da `md`
(`globals.css:340,368`; wrapper `md:[--nav-inset-inline-start:14rem]`); quando la
barra e' aperta, aggiungere padding in fondo al contenuto della stessa altezza.
**Segnale:** l'ultima scheda non si tocca su iPhone.

### Pitfall 4: ordinare gli slot per orario
`00:30` viene prima di `22:00`. Ordinare per `part_number`. Per la durata della
fascia, attraversare la mezzanotte (`slot_end < slot_start` → +24 h).

### Pitfall 5: la data del titolo spostata di un giorno
`formatTime.ts` usa `new Date(...)`; su un client a ovest di UTC la data civile
`2026-10-17` diventa il 16. Il titolo si costruisce spezzando la stringa.

### Pitfall 6: `api.js` caricato prima del play
Un `<Script>` di Next, anche `lazyOnload`, lo scarica senza gesto: viola MUS-06 e
la frase dell'informativa. Iniettarlo dentro il gestore del tocco.

### Pitfall 7: `revalidatePath("/music")` senza `PUBLIC_ALLOW`
`verify:routes` check 1 diventa rosso (`verify-routes.mjs:190-202`). Con la
pagina dinamica non serve: non chiamarlo, oppure aggiungere la riga.

### Pitfall 8: una rotta admin nuova senza la riga nella mappa
`verify:routes` check 2 (censimento) rosso, e il middleware risolve `null`
(`nextjs-architecture.md`, *il gruppo non autorizza*). Aggiungere
`"/admin/events/[id]/livecuts"` a `capability-routes.ts:368-384` nello stesso
commit della pagina, e la voce in `ROW_CONTROLS`.

### Pitfall 9: un secondo scrittore di `event-images`
`verify:media-strip` rosso. Passare da `finalize-cover` con `purpose`, ed estendere
il controllo ai due letterali.

### Pitfall 10: la sweep del genere su «technology» o «RamaDub»
Senza confini di parola il gate grida al lupo e viene spento
(`production-calendar.md`, precedente del controllo che segnalava `RSNT-003`).
Provare la sweep per mutazione: una stringa `"deep house"` nella scheda deve far
rosso, `"assistive technology"` no.

### Pitfall 11: il nome del venue nell'URL SoundCloud
Il permalink lo sceglie chi carica: `soundcloud.com/<account>/<slug>`. Uno slug
che porta il luogo esce dal backlink «Open on SoundCloud» di una serata segreta.
Guardia nell'action (token del nome del venue) e riga nel brief di caricamento.

### Pitfall 12: dati di prova reali sul laboratorio
Il laboratorio non ospita dati reali (`v1.6-LAB-DESIGN.md`, «Cosa cambia», punto
2). Artisti di prova fittizi nel catalogo del lab; serate del seme gia' esistenti
(compresa la serata segreta `PRE-SECRET`); come URL di prova un brano **pubblico
dichiarato** (es. la traccia d'esempio della documentazione SoundCloud, id 293) —
mai un LiveCut nostro non ancora autorizzato. Rimozione per chiave primaria sugli
id catturati.

### Pitfall 13: lo stesso iframe dopo una navigazione
Il player e' «per pagina» (MUS-06): toccare l'artista smonta la pagina e
**ferma l'audio**. Non e' un difetto da correggere con un player nel layout
radice (fuori perimetro, e trascinerebbe un client component su ogni pagina);
va dichiarato al proprietario nella prova.

### Validazione del link in admin
```typescript
// src/lib/livecuts/soundcloud.ts — solo server
const SC_PERMALINK = /^https:\/\/soundcloud\.com\/[A-Za-z0-9_-]+\/[A-Za-z0-9_-]+$/;
export async function verifySoundCloudLink(raw: string) {
  const url = raw.trim();
  if (!SC_PERMALINK.test(url)) return { ok: false, reason: "livecut.url_not_soundcloud" } as const;
  // host fisso costruito da noi: nessun SSRF, l'utente sceglie solo il parametro
  const res = await fetch(`https://soundcloud.com/oembed?format=json&url=${encodeURIComponent(url)}`,
                          { cache: "no-store", signal: AbortSignal.timeout(8000) });
  if (res.status === 404) return { ok: false, reason: "livecut.track_not_found_or_private" } as const;
  if (!res.ok) return { ok: false, reason: "livecut.oembed_unavailable" } as const;   // NON e' «non esiste»
  const body = (await res.json()) as { title?: unknown; html?: unknown };
  const m = typeof body.html === "string" ? body.html.match(/api\.soundcloud\.com%2Ftracks%2F(\d+)/) : null;
  if (!m) return { ok: false, reason: "livecut.track_id_unreadable" } as const;
  return { ok: true, trackId: m[1], soundcloudTitle: typeof body.title === "string" ? body.title : null } as const;
}
```

### Known Threat Patterns

| Pattern | STRIDE | Mitigazione |
|---|---|---|
| Indirizzo di una serata segreta su `/music` (colonna, cover, URL, titolo) | Information disclosure (irreversibile) | Nessuna colonna di luogo selezionata (H2), nessun testo libero, guardia sullo slug dell'URL, cover dallo stripper, titolo da `party_series.name` |
| Line-up non annunciata letta da anonimo tramite righe bozza | Information disclosure | RLS: pubblicato **e** evento pubblicato; pubblicazione solo a serata avvenuta |
| SSRF dalla verifica oEmbed | Tampering | host fisso `soundcloud.com/oembed`, l'utente fornisce solo il parametro, timeout |
| XSS dall'`html` dell'oEmbed | Tampering | mai iniettato; si estrae l'id con una regex e si costruisce l'`src` |
| URL `javascript:` o di terzi nel link | Tampering | CHECK SQL + regex nell'action; anchor `target="_blank" rel="noopener noreferrer"` |
| Scrittura da `staff` o `attendee` | Elevation | `staff.manage` (zero concessioni a `staff` e `attendee`, `access-gating.md`) |
| Genere nella pagina | — (dominio) | H5 con confini di parola, nessun campo libero, brief di caricamento |
| GPS nella cover | Information disclosure | stripper `cover-jpeg` |
| Copia offline di un LiveCut ritirato | Information disclosure | `force-dynamic` + `NetworkOnly` per `/music` nel service worker |
