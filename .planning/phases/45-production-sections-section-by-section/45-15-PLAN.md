<objective>
The two authored sections become writable, each behind its own key — and a void stays a
void unless somebody decides otherwise.

Purpose: this is criterion 3 on the write side. The three states are a decision the author
takes, and the one thing a form must never do here is take it for them: a default of
*written* fills the void, and a default of *not decided* answers for a coordinate that
exists.
Output: two Server Action modules, two forms, two pages wired.
</objective>

  <action>
    **Two modules, not one, and the reason is the key.** D-45-06 makes the key that reads a
    section the key that writes it, so a single shared module would publish the manifesto's
    write endpoints to a holder of the visual key — and every export of a `"use server"`
    module is a public endpoint. Each module has its own **unexported** gate asking its own
    key, and neither imports the other's.

    Factor the shared shape into a **plain, unexported-from-`"use server"` helper module**
    under `src/lib/production/sections/` if the duplication is real; do **not** export a
    predicate from either action file. `may-upload.ts:27-34` records why: leaving a predicate
    in a `"use server"` file publishes an oracle.

    Exports per module:
    · `saveSection(id | null, { title, formatId, state, body, missing, decisionOwner })` —
      **`state` is a required argument with no default.** Refuse `written_without_body` and
      `not_decided_without_gap` **by name**, before the query, and let the constraint refuse
      again after: the code is the sentence, the constraint is the boundary.
      **Nothing here infers a state.** A body that is empty does not make a row
      `not_decided`, and a body that is full does not make it `written` — that inference is
      exactly the *"answering where a coordinate has been declared"* error the middle state
      exists to prevent.
    · `openQuestion({ question, decisionOwner, section, formatId })` — both text fields
      required, refused by name when blank.
    · `closeQuestion(id, resolution)` — **the resolution is required.** A question closed
      without its answer is a question that will be reopened, and the XOR constraint refuses
      the row anyway. Closing is not deleting, and **there is no delete export**.

    `SectionRefusal` — one member per distinguishable cause, each with a JSDoc saying why it
    is not folded into its neighbour: `invalid_id`, `title_missing`, `invalid_state`,
    `written_without_body`, `not_decided_without_gap`, `question_missing`,
    `decision_owner_missing`, `resolution_missing`, `already_closed`, `write_failed`.

    **The log form on every branch:** `[manifesto.<cause>] section=<id>: code=… message=…`
    (and `[visual.…]`). Never the error object, never PostgREST's third field, and never the
    body — a manifesto body can quote a line-up.

    **Zero silent failures:** every refusal is rendered by the surface, not only logged. With
    no error tracking, a log is a place nobody looks.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a `"use server"` export → the public internet | Two modules and not one, because a shared module would publish one section's writes to the other section's key |
| a form default → a decision the owner never took | The sharpest boundary on this surface, and it has no error message |
| a manifesto body → a server log | A body can quote a line-up nobody has announced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-13 | Spoofing | the section state | mitigate | no default in the column, no default in the argument, no preselection in the control, and no inference anywhere in either module. Both conditional requirements are refused by the action **and** by a named constraint |
| T-45-04 | Elevation of privilege | the two write surfaces | mitigate | one module per key, each gate unexported and asked first; any shared predicate lives in a plain module, never in a `"use server"` file |
| T-45-02 | Information disclosure | the failure branches | mitigate | `code=… message=…`; the error object and the section body never reach a log |
| T-45-17 | Repudiation | a closed question | mitigate | closing requires the answer, refused by the action and by the XOR constraint; there is no delete path, so a question that was asked stays asked |
| T-45-SC | Tampering | npm/pip/cargo installs | accept | no package is installed; no validation library is added |
</threat_model>
