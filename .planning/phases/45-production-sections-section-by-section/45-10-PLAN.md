  <action>
    A Node script under `scripts/`, `seed:spaces` in `package.json` — **outside** the
    `verify:` prefix, for the reason the calendar importer states about itself.

    **Four things it cannot do, by construction, each written in the header:**

    1. **It writes nothing unless `--apply` is passed.** A dry run is the default. A tool
       that writes production when invoked with no arguments is a tool that will one day be
       invoked with no arguments.
    2. **It removes nothing, ever.** There is no removal statement in the file and no list
       that could carry one. This is D-45-13 made structural for the seed.
    3. **It never writes `stage`.** The column's `DEFAULT 'mapped'` does it. A script that
       derived a stage from an attribute would be *ranking-is-not-availability* encoded into
       data, and **no CHECK would catch it** — only the omission does. Nobody has been
       called; the whole archive is desk work.
    4. **It never writes a score, because there is none.** The source carries no score field
       and the schema has no score column. What it writes are **attributes**, and a score is
       computed from them at render time by `src/lib/production/sections/score.ts`.

    **A fifth, added by D-45-24 and just as structural: it never writes
    `extended_hours_stance`.** That column is the answer to a phone call and to nothing
    else. No crawl, no inference and no default may move it off `not_asked` — a derived
    value there is *derived is not verified* committed in the one column built to prevent
    it. `published_hours` is likewise left at its default: it is absent from all 184 records,
    measured, and a value assembled from a note would be a fact nobody established.

    **Provenance is `derived` on every seeded attribute, without exception.** Nobody has
    been called, so nothing in this archive is field-verified. The script does not accept a
    flag to say otherwise.

    **The field mapping is declared, not discovered.** `45-CONTEXT.md` `<code_context>`
    records the source's 27 fields and their shapes, so write the mapping as a constant
    table at the top of the file — source field → target column or attribute key, with the
    value mapping beside it. Three rules govern it:
    · a source value with **no declared target** is a refusal for that row, counted and
      reported by field name and reason code, never silently dropped and never defaulted;
    · `regime` is **read and discarded** — D-45-22 keeps it out of the product, and the
      script names it once, in the sentence that excludes it, so the exclusion is visible
      rather than an omission;
    · the source's five (or more) attributes carrying the literal unanswered marker map to
      `not_asked`, which is a **value** in the target vocabulary and not an absence.

    **`address` is written.** D-45-24 settled it, over the researcher's narrower
    recommendation, and the structural guarantees of D-45-21 are what carry the risk. So the
    script writes it into the one column built for it — and **never into a log line, a
    reason code, an error message or the transcript.**

    **Re-runnability.** The natural key is `source_key`, derived from the source's own stable
    per-record identity if it has one and from a normalised name if it does not. **Say which,
    in the header, having read the file** — because if it is a normalised name, a renamed
    space arrives as a new row, and whoever renames one has to know that. The write is an
    upsert on that key; the attributes are upserted on `(space_id, attribute)`.

    **Credentials from the environment, refused by name when absent** — a missing variable
    is a refusal with the sentence *nothing was written*, never a silent no-op.

    **The transcript audit, extended.** The calendar importer audits its own transcript for
    parsed title tokens and four-digit years. This one audits for those **and for a street
    token** — the source's address field is populated on every record, and 124 of them match
    a street pattern. The audit runs last, and a transcript that fails it makes the run
    report a failure even if every write succeeded: a run that printed an address has already
    done the harm the column exists to contain.

    **The run row.** Report what it read and what it wrote — counts, per-reason-code
    refusals, and the number of attributes written — and **do not write an expected total
    into an acceptance criterion**. The domain module says 184 and a working note once said
    183; neither is a measurement of the file, and the file is the fact.
  </action>
