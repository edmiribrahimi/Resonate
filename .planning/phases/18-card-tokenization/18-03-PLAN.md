**1. Create `src/app/(members)/dashboard/actions.ts`** with three server actions:

```typescript
"use server";

import { createClient } from "@/lib/supabase/server";
import { listSavedCards, deactivateCard, processWithSavedCard, createCheckout } from "@/lib/sumup";
```

**a. `getSavedCards()`:**
- Authenticate user via `supabase.auth.getUser()`
- Fetch profile `sumup_customer_id` from `profiles` table
- If no `sumup_customer_id`, return empty array `[]`
- Call `listSavedCards(sumup_customer_id)` and return the result
- Return type: `{ token: string; last4: string; cardType: string }[]`

**b. `deleteSavedCard(token: string)`:**
- Authenticate user
- Fetch profile `sumup_customer_id`
- If no `sumup_customer_id`, throw "No saved cards"
- Call `deactivateCard(sumup_customer_id, token)`
- Revalidate `/dashboard` path
- Return `{ success: true }`

**c. `payWithSavedCard(params: { token: string; amount: number; currency: string; description: string; returnUrl: string; redirectUrl?: string })`:**
- Authenticate user
- Fetch profile `sumup_customer_id`
- If no `sumup_customer_id`, throw "No saved card on file"
- Create a standard checkout first (via `createCheckout`) to get a checkout ID. Use `crypto.randomUUID()` for checkoutReference.
- Then call `processWithSavedCard({ checkoutId: checkout.id, token: params.token, customerId: sumup_customer_id })`
- If result has `redirect_url` (3DS challenge), return `{ status: "redirect", redirectUrl: result.redirect_url, checkoutId: checkout.id }`
- If result status is PAID, return `{ status: "paid", checkoutId: checkout.id }`
- Otherwise return `{ status: "pending", checkoutId: checkout.id }` (let webhook handle)
- Return type: `{ status: "paid" | "redirect" | "pending"; checkoutId: string; redirectUrl?: string }`

**2. Add `purchaseTicketWithSavedCard` server action to `src/app/(organizer)/organizer/events/actions.ts`:**
- New exported function: `purchaseTicketWithSavedCard(partyId: string | null, tierId: string, cardToken: string)`
- Same validation logic as existing `purchaseTicket` (auth check, profile check, tier check, chain validation, duplicate check, etc.) -- extract or copy
- After validation, create checkout via `createCheckout` with same params as normal ticket purchase
- Create `pending_purchases` record with the checkout ID
- Then call `processWithSavedCard({ checkoutId, token: cardToken, customerId: profile.sumup_customer_id })`
- If process returns redirect (3DS), return `{ success: true, checkoutId, redirectUrl, status: "redirect" }`
- If process returns paid, return `{ success: true, checkoutId, status: "paid" }` -- webhook will handle ticket creation
- If process returns other, return `{ success: true, checkoutId, status: "pending" }`
- Import `processWithSavedCard` and `createCheckout` from `@/lib/sumup`

**3. Add `purchaseDrinksWithSavedCard` server action to `src/app/(organizer)/organizer/events/actions.ts`:**
- New exported function: `purchaseDrinksWithSavedCard(eventId: string, partyId: string, items: { drinkItemId: string; quantity: number }[], cardToken: string)`
- Same validation logic as existing `purchaseDrinks` (auth, items, drink availability, total calc)
- After validation: create checkout, create drink_orders record, then process with saved card
- Same return type pattern as purchaseTicketWithSavedCard

Note: These "WithSavedCard" actions keep the separation clean -- original actions stay untouched for Card Widget flow, new actions handle server-side token flow. This avoids making the original functions more complex.

Note on 3DS redirect: When `processWithSavedCard` returns a redirect_url, the client should redirect the user to that URL for 3DS verification. After 3DS, they'll come back to `/payment/callback` (already built in Phase 17). The webhook handles the rest.
