  <name>Task 2: SumUp SDK wrapper functions for customer and tokenization operations</name>
  <files>src/lib/sumup.ts</files>
  <action>
Add 5 new exported functions to `src/lib/sumup.ts` BELOW the existing `refundTransaction` function. Do NOT modify any existing functions (`createCheckout`, `getCheckout`, `refundTransaction`) or the singleton setup.

1. `getOrCreateCustomer(params: { userId: string; firstName: string; lastName: string; email: string })`:
   - Uses the Supabase profile UUID as the SumUp `customer_id` (direct 1:1 mapping, no separate ID needed)
   - First tries `sumup.customers.get(params.userId)` -- if found, return it
   - If get throws APIError with status 404, call `sumup.customers.create({ customer_id: params.userId, personal_details: { first_name, last_name, email } })`
   - If create throws APIError with status 409 (conflict = already exists), call get again and return
   - Return shape: `{ customer_id: string }`
   - Catch other APIError and rethrow as standard Error

2. `createTokenizationCheckout(params: { amount: number; currency: string; description: string; checkoutReference: string; returnUrl: string; redirectUrl?: string; customerId: string })`:
   - Same structure as existing `createCheckout` but adds `customer_id: params.customerId` and `purpose: "SETUP_RECURRING_PAYMENT"` to the SDK call
   - Return same shape as createCheckout: `{ id: string; status: string; checkout_reference: string }`

3. `processWithSavedCard(params: { checkoutId: string; token: string; customerId: string })`:
   - Calls `sumup.checkouts.process(params.checkoutId, { payment_type: "card", token: params.token, customer_id: params.customerId })`
   - Return the result (can be CheckoutSuccess or CheckoutAccepted for 3DS)
   - Return type: `{ id?: string; status?: string; redirect_url?: string }` to handle both cases
   - APIError caught and rethrown as standard Error

4. `listSavedCards(customerId: string)`:
   - Calls `sumup.customers.listPaymentInstruments(customerId)`
   - Filters to only `active === true` items
   - Returns array of `{ token: string; last4: string; cardType: string }` (mapped from PaymentInstrumentResponse)
   - If no active cards, returns empty array
   - Handle fields being optional in SDK types with fallbacks

5. `deactivateCard(customerId: string, token: string)`:
   - Calls `sumup.customers.deactivatePaymentInstrument(customerId, token)`
   - Returns `{ success: true }`
   - APIError caught and rethrown as standard Error

All functions follow the existing error handling pattern: catch `APIError` from `@sumup/sdk`, rethrow as plain `Error` with descriptive message.

After adding functions, run `npx tsc --noEmit` to verify type correctness.
