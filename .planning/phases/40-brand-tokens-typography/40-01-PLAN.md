  <action>
Create `scripts/verify-tokens.mjs` — Node built-ins only, ESM, zero dependencies,
executable shebang, deliberately **not** wired into `next build`.

Constants at the top, each an exact value compared for equality:
  - `TOKEN_FILE = 'src/app/globals.css'`
  - `SRC_DIR = ${ROOT}/src`
  - `UTILITY_PREFIXES` = the twelve: `bg text border ring from to via fill stroke
    shadow outline decoration`
  - `KNOWN_TOKEN_NAMES` — the union of every colour-ish token name this repository
    has declared in either generation, exactly these 28:
    `background foreground card card-border muted accent accent-hover ground
    surface raised sunk ink ink-2 faint line-soft line line-strong sem-crit
    sem-warn sem-info sem-done amber orange pink pink-soft violet violet-deep
    grad-sunset`.
    A comment above it states what the list **is**: the mechanical form of
    `40-UI-SPEC.md` §8.3 clause 3 — *a name any shipped document still reads is not
    deleted; it is emptied of consumers first and removed second.* Adding a name
    here is part of declaring a token; removing one is part of proving it has no
    readers.
  - `FONT_VARIABLES` = `--font-orbitron`, `--font-inter` — the two `next/font`
    variables. They are declared on the generated class that sits on `<html>`, not
    in `:root`, so check A must not demand a `:root` declaration for them
    (RESEARCH §3.1, verified: `.__variable_e087fb{--font-orbitron:…}`).

Parsing, conservatively (PATTERNS §4.1): read `TOKEN_FILE` with `readFileSync`,
drop comment lines with the `isCommentLine` heuristic **before** any counting —
this file's own prose names tokens repeatedly and would otherwise decide the
verdict. Extract a declaration only from a line shaped `--name: value;` inside the
`:root { … }` block, and a mapping only from a line shaped
`--color-<x>: var(--<y>);` (or `--font-<x>: …`) inside the `@theme inline { … }`
block. Never from anywhere the two hyphens merely appear.

The five checks, reported one line each as `✓ A` / `✗ A`:

  **A. Every `var(--x)` inside the token file resolves.** Collect every
  `var(--x)` reference anywhere in `TOKEN_FILE` (including `body`, `html`, any
  `@utility` and the `@theme inline` block) and fail on any `--x` that is neither
  declared in `:root` nor in `FONT_VARIABLES`. This is the half-rename caught at
  the source: the `@theme` mapping renamed and the `:root` declaration not, or the
  reverse.

  **B. Every `@theme inline` mapping is a one-to-one forward reference.** Each
  `--color-<name>` entry must have the form `var(--<name>)` — the same name on both
  sides, never a literal, never a chain to a differently-named token. This is the
  pattern `40-PATTERNS.md` §2.1 extracted from the file as it stands and the
  property RESEARCH §2.1 verified in the compiled output (`.bg-accent` emits
  `var(--accent)`, the raw `:root` property). Font entries under `--font-*` are
  exempt from the same-name rule and are checked by A instead.

  **C. Nothing is declared twice.** No token name is declared more than once in
  `:root`, and no `--color-*` name is mapped more than once in `@theme inline`. A
  duplicate is the shape a palette acquires a seventh colour nobody decided.

  **D. A name with no utility has no consumer.** For every name in
  `KNOWN_TOKEN_NAMES` that is **not exposed** — meaning either not declared in
  `:root`, or declared but carrying no `--color-<name>` mapping in `@theme inline`
  — the count of files under `src/` matching
  `(<prefix>)-<name>` followed by a character that is not `[a-z0-9-]` must be
  **zero**. Report every hit as `path:line: text`. The negative lookahead is
  mandatory and is the whole difficulty of this check: without it `bg-amber-500`
  counts as a consumer of `amber`, `bg-pink-soft` as a consumer of `pink`, and the
  gate goes red on 74 correct files and is switched off. Strip comment lines from
  the scanned files first.

  **E. No `var(--token, #hex)` fallback anywhere in `src/` or in the token file.**
  Match `var(--<name>, *#` and fail on any hit. This is G4 of `40-VALIDATION.md`
  given a permanent home instead of a grep somebody remembers to run.
  `40-UI-SPEC.md` §8.3 clause 2 states why: a hex fallback *looks like safety and
  is the half-state made permanent* — the one place that keeps working while
  everything around it changes generation. The single sanctioned exception is
  `var(--new, var(--old))`, which has no `#` in it and therefore does not match.

Preflight, before any check runs: `refuse()` (exit 2) if `src/` does not exist, if
`TOKEN_FILE` does not exist at its exact path, if the walk finds no scannable
file, if the `:root` block cannot be located, or if it yields **zero**
declarations. A green from a script that measured nothing is precisely the silent
failure `meta-gates.md` forbids, and there is no error tracking to notice it.

Banner before the checks: how many files were scanned under `src/`, how many
tokens were found declared, how many are exposed as utilities, how many names in
`KNOWN_TOKEN_NAMES` are currently unexposed and therefore under check D. A check
that is vacuous must say so out loud rather than print a tick.

The header carries all five mandatory sections in `verify-media-strip.mjs`'s
order — shebang, the one-sentence assertion, *why structural and not a test on one
file*, **WHAT A GREEN DOES NOT MEAN**, the enumerated checks, the trap specific to
this check (the negative lookahead, and that `--line` is a prefix of `--line-soft`,
`--ink` of `--ink-2`, `--accent` of `--accent-hover`), the comment-hygiene
paragraph, the secrecy paragraph, the zero-dependency / not-wired-into-build
statement, `Usage`, `Exit codes`.

**WHAT A GREEN DOES NOT MEAN** takes RESEARCH §7's wording: a `grep` reads
**declarations, not intent** — it cannot see a colour written as a raw hex, a
token reached through a variable renamed on the way, or a utility built by string
concatenation; it does not say a colour is **right**, because contrast is
arithmetic (`40-UI-SPEC.md` §4) and legibility at a dark door is an observation;
and it cannot see a consumer of a name that was renamed **and** never added to
`KNOWN_TOKEN_NAMES`, which is why editing that list is part of the rename and not
an afterthought.

Verdict sentinels: `TOKENS_OK` / `TOKENS_FAIL`, uppercase and greppable. The green
line repeats the limits of the green rather than letting the reader forget the
header. Exit `0` all checks passed, `1` at least one failed, `2` nothing was
measured.

Secrecy: the script reads only committed files, prints only paths, line numbers
and source lines, opens no network connection, reads no environment variable and
writes no artefact. This repository is PUBLIC.
