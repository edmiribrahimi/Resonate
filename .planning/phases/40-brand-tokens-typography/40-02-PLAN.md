<objective>
Adopt the artifact's token set, in the one file whose blast radius is the whole
product.

D-40-01, owner: *«i colori e i layout devono essere gli stessi dell'artifact
produzione»*. This plan does the colour half. It **adopts**; it designs nothing —
every value below is read out of `40-UI-SPEC.md` §3, which read it out of
`36-VISUAL-SOURCE.md`, which distilled it from the production tracker on
2026-08-10.

Purpose: give Phases 41, 42, 44 and 45 a layer to draw from, and retire
`#e5484d` — a red that appears in neither the brand palette nor the semantic set
and is currently the accent of 86 files.
Output: `src/app/globals.css` carrying the whole token set, the semantic set held
structurally apart, and SunSet's gradient declared once and applied nowhere.

**This plan converts no surface.** The 74 `.tsx` files using default Tailwind
colours are Phase 41's, one whole surface at a time (`40-UI-SPEC.md` §0 rule 5).
This plan does not open one of them.

**And it deletes no token name.** `bg-card` is read by 111 files, `text-muted` by
124, `text-foreground` by 93. A rename is a removal wearing a friendly word
(`40-UI-SPEC.md` §8.3 clause 3), and a removal here is **silent** — RESEARCH §5 P1
proved the build emits no error for a utility whose token is gone. The four legacy
names stay as declared aliases pointing at the new roles, so those files render in
the new colours **with no component edited**, and Phase 41 empties them of
consumers before anyone removes them.
</objective>
