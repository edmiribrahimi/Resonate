Keep the measuring instruments measuring, and turn FMT-03 into the one automated
proof this phase can honestly claim.

Purpose: `36-VALIDATION.md` marks this as the most likely silent failure of the
whole phase. `scripts/rls-baseline.mjs:1226-1229` inserts into `event_parties`
with three columns; the moment a fourth becomes `NOT NULL`, every persona fails
`23502` and `baseline:compare` reports a *permission movement* for a row that has
simply stopped measuring. And `scripts/container/seed.mjs:506-509` refuses to run
at all if an RLS table has no payload — so the two new tables are not optional
work.

The reward for doing it properly: the constraint probes run inside `captureB3`,
which **throws** if a probe does not refuse as declared. That makes FMT-03 the one
requirement of this phase with a real automated gate.

Output: an extended harness and a container capture that exercises the migration
written in plan 36-03 — before production is touched.

    Probe `FMT-03`: *two nights cannot share a format, a series and a number*.
    Table `event_parties`, sqlstate `23505`, constraint
    `event_parties_format_series_number_unique`. Build the row so that the only
    thing wrong with it is the duplicate: take `event_id`, `format_id`, `series_id`
    and `number` from an existing night — scalar subqueries reading them off
    `public.event_parties` for the id `{{event_parties}}` resolves to — and supply
    `title` and `time` as the ordinary payload does. Because the triple is copied
    from a real row, the composite foreign key is satisfied and the `CHECK` on the
    number is satisfied; the unique key is the only rule left to break.

    Probe `FMT-03-FK`: *a night's format cannot contradict the format of its own
    series*. Table `event_parties`, sqlstate `23503`, constraint
    `event_parties_series_format_fk`. Take `series_id` from `{{party_series}}` and
    `format_id` from a format that is **not** that series' format — a subquery over
    `public.formats` excluding the series' own `format_id`, with a `limit 1`. Give
    it a number that cannot collide with anything, so the unique key does not fire
    first and steal the measurement: one more than the highest number in that
    series. If `public.formats` were ever to hold a single row this probe would
    insert a null and measure `23502` instead — say so in the comment, because the
    migration seeds five formats and a future reader deleting four of them should
    read why the probe went quiet.

    Both probes run on the privileged connection and are wrapped `begin; …
    rollback;` by the runner, which `assertProbesRollBack` verifies before anything
    is sent.
