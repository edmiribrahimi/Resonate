<objective>
Build the two modals and the colour control the catalogue surface mounts.

Purpose: D-36-11 says a colour is mandatory at creation, that a deliberate neutral
must be among the choices, and that the sunset gradient is not selectable for
anything that is not SunSet. The way this plan honours the last part is by making
it inexpressible: the control offers flat swatches only, and a gradient has no
input to arrive through. A constraint that cannot be expressed cannot be violated.

Output: three client components, no data fetching of their own, mounted by plan
36-09.
</objective>

  <action>
    A client component taking the current value, a change handler, and the set of
    colours already held by other **active** formats. It renders a `radiogroup`:
    six swatches, each a 44 × 44px target containing a 24px `rounded-[2px]` square
    whose background is the colour, applied inline.

    Hold the six choices as a total `Record` from a colour key to a `{ hex, label }`
    — the discipline `EventForm.tsx:100-104` already uses and
    `assignments/actions.ts:72-82` states as a contract: a seventh choice cannot
    reach the interface without a label, and a removed choice leaves an unreachable
    one. Include the neutral grey; it is not a filler, it is the answer to
    "obligatory does not mean borrowed".

    The selected swatch carries a 2px ring **and a check glyph**. The glyph is not
    decoration and not optional: the selection of a *colour* control must not be
    signalled by colour. Arrow keys move within the group and Tab leaves it, which
    is what `radiogroup` semantics buy.

    A colour already held by another active format is `aria-disabled`, not
    focusable for selection, and labelled `used by {Name}` — the string from the
    copywriting contract. Six choices against four formats is deliberate slack;
    when it runs out, extending the palette is a decision, not a workaround, and the
    component should say so in a comment rather than silently offering a seventh.

    There is **no free hex input and no gradient option**. The sunset gradient
    `linear-gradient(94deg, #FFB25E, #FF7A2F, #FF5C93, #A874E8)` is SunSet's
    exclusive signature (`brand-visual-system.md`, gate *il colore non si eredita*),
    and rather than validate against it the surface offers flat swatches only, so
    there is no input through which another format could take it. Write that
    sentence into the component.

    Do not offer `#5B2A9E`. It measures 1.99:1 against the card ground and was
    excluded for that reason; record the figure in a comment so the next person does
    not rediscover it and add it back.
  </action>

    A client component in the `<dialog>` shape the repository already uses:
    `max-w-md`, `rounded-2xl`, backdrop click closes, the open/close effect copied
    from `CreateVenueModal.tsx:37-50`. It serves both creation and editing — the
    same fields, a different action and a different button label.

    Three fields. **Name**: text, rendered publicly and verbatim, so the
    placeholder shows CamelCase and nothing applies a transform. **Code**: text
    with an uppercase input filter, internal only, and the label should say so —
    it never reaches a public surface. **Colour**: the `ColorSwatchPicker` from
    task 1, required.

    Do **not** copy the error branch at `CreateVenueModal.tsx:119-123`. It renders
    `err.message` straight from a thrown error, and Next redacts the message of an
    error thrown out of a Server Action in a production build
    (`src/lib/capabilities/server.ts:59-63`) — so a client branching on message text
    works in `next dev` and stops working where it counts. Branch on the
    `CatalogueRefusal` **value** the action returns, and map each member to its own
    sentence from the copywriting contract: `Pick a colour. Every format needs one
    of its own.` · `{Colour} is already used by {Name}. Pick another.` · and a named
    reason for a failed save, never `Could not save. Something went wrong.` A
    network failure, a permission refusal and a duplicate code must produce three
    different sentences on this form.

    Attach the error to the field it belongs to with `aria-invalid` and
    `aria-describedby`, and preserve what the person typed. The error box uses the
    `red-500/10` fill and `red-400` ink already in the tree, which is the only place
    those two co-occur.

    Creating a format does **not** offer a "show this in the filter" toggle in this
    modal. Listing is a separate act with its own action (`setFormatListed`), and
    the catalogue surface in plan 36-09 is where it lives. Putting it on the create
    form would make announcing a format a side effect of saving one — the exact
    situation D-36-17 exists to prevent.

    No copy anywhere in this modal describes what a format sounds like. The
    placeholder for the name shows a spelling, not a genre.
  </action>

    nights. Editing an existing series shows the name and the code and no format

    helper-text pattern is introduced at all: it is the field's contract, and a

    duplicate code within the format is not the same failure as a retired format

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-08-01 | Information Disclosure | a series name carrying an unacquired venue | mitigate | Helper text stating the contract before the field, plus the § S2 fallback to the format name whenever any night is secret. No content filter, which would teach a workaround |
| T-36-08-02 | Information Disclosure | a format published by pressing save | mitigate | The create modal has no listing control; publication is `setFormatListed`, elsewhere (D-36-17) |
| T-36-08-03 | Information Disclosure | a raw error rendered on screen | mitigate | The refusal is a returned value mapped to a fixed sentence; no `err.message` is rendered, and the raw PostgREST error never reaches the DOM |
| T-36-08-04 | Tampering | the sunset gradient taken by another format | mitigate | The control offers flat swatches only and has no free input; the constraint is inexpressible rather than validated |
| T-36-08-05 | Repudiation | three failures reading as one | mitigate | One sentence per `CatalogueRefusal` member; no shared fallback string exists in these files |
| T-36-08-SC | Tampering | npm/pip/cargo installs | accept | No package is installed; shadcn is not initialised in this project and no registry is introduced (`36-UI-SPEC.md` § *Registry Safety*) |
