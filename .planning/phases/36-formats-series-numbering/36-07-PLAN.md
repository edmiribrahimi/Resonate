<objective>
Write the server actions that change the catalogue — and the guard that is the
only thing standing between them and anyone who can construct a POST.

Purpose: neither `public.formats` nor `public.party_series` carries a write
policy, and the migration says so in a paragraph. That is the correct design —
the writer is the service client, which bypasses every policy, so a write policy
would constrain nothing on the only path that writes — but it has a consequence
this plan must not soften: **`assertCatalogueManage()` is the entire boundary.**
A server action is a public endpoint with a convenient signature.

Output: one module, every export guarded, every refusal a returned value.
</objective>
