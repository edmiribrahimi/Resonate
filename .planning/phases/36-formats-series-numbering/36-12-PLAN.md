<objective>
Move the time axis into the address without breaking the gesture, and put the
format where a visitor reads it: on the card and on each night.

Purpose: FMT-04 asks for a choice that survives navigation and can be shared. Today
the tab lives in `useState` (`EventTabs.tsx:117`), so it does neither. D-36-15 says
both axes move into the address together, because leaving one behind means two
mechanisms of state on the same page and one of them losing its value at the first
navigation.

The risk is specific and worth naming before the first line: `router.replace` on a
Request-time page is a real navigation, and a swipe that waits on the network is a
broken swipe on the page that is the shop window.

Output: a tab that is a link, a gesture that still feels local, and a marker on
every night.
</objective>

  <action>
    Take the active tab as a **prop** from the page, which derived it from `?tab=`.
    Keep `activeTab` as local state, initialised from that prop, because it is what
    drives `baseOffset` and therefore the animation — this is a conservation of an
    existing behaviour, not a new decision.

    Every change, by tap or by swipe, does **both** things: `setActiveTab`
    immediately, so the panel translates without waiting for anything, and
    `router.replace(href, { scroll: false })` inside a `useTransition`, so the
    address follows without the navigation blocking the gesture. `replace` and not
    `push` for the tab: a view toggle is not a destination, and `handleTouchEnd` can
    fire on every gesture, which would flood the history stack. The format chips
    push, because choosing a format is a deliberate act worth a Back.

    Add a `useEffect` that resyncs `activeTab` when the prop changes — that is what
    makes a shared link and the Back button work.

    Do **not** use `useSearchParams`. The value arrives as a prop from the Server
    Component; reading it in the client would force a `<Suspense>` boundary and move
    the read out of the single construction path D-36-16 requires. Both arrays stay
    props, so a navigation does not change what the component holds and the
    re-render costs nothing on the content.

    Preserve the format parameter in every tab href, and build each href as a
    template literal — a bare `string` variable does not compile under `typedRoutes`,
    and the ternary that makes each branch a literal is the measured workaround
    (`analytics/compare/page.tsx:49-60`).

    Add the marker row to the card, between the date line at `:71-73` and the title
    at `:75`, because the format is the source of the name and the title is free
    text beneath it. One `FormatMarker` per distinct format, in `sort_order`, joined
    by ` × ` (U+00D7) in `text-muted` and `aria-hidden` — the brand's own form for a
    double bill. The joiner is supplied by the UI; the lowercase `x` inside a series
    name comes from the stored name and is never synthesised here.

    Do not copy the adjacent tabs' `uppercase tracking-widest` (`:197`, `:207`) onto
    anything that renders a format or series name. Those classes on a format chip
    break `re:sonate` and the CamelCase names for every visitor at once.

    Write the four empty states with the copy from the contract: `No upcoming
    events` / `Check back soon.`; `Nothing announced for {Format}` with a
    `Show all events` link clearing `?format=`; `No past events yet`; `No past
    events for {Format}` with the same link. **`Nothing announced` is chosen word by
    word** — it states what is true without asserting anything about what exists,
    and it is the same string for every format, so it carries no information about
    which formats have hidden nights. Compute it from `length === 0` on the array
    already on screen, never from a second query: a separate *"does this format have
    anything?"* query is exactly the shape that would see a draft and turn it into a
    visible difference.
