    A server-safe presentational component taking `{ name, color }` and an optional
    `className`. No `"use client"`, no data fetching, and — this is D-36-12 and
    FMT-05 — **no format constant inside it**. The name and the colour arrive as
    props from a catalogue row, which is what makes changing either of them a
    change without a deploy.

    It renders an `inline-flex items-center gap-1.5`: first an 8px `rounded-[2px]`
    square whose background is the colour, applied through an inline `style`
    because Tailwind cannot generate a class from a runtime value; then the name.
    The square is `aria-hidden` — it adds nothing a screen reader needs and would
    read as noise before every name. Colour is never the only channel: the name is
    always present as text.

    The name element is the Label role — `text-xs`, `font-semibold`,
    `tracking-wide`, `text-foreground` — and it carries **`normal-case`
    explicitly**. That word is the whole point of the component and the reason it
    exists as a component at all: `text-transform` is an inherited property, so
    *"we did not add uppercase"* holds only until the marker is mounted inside an
    ancestor that applies it, and this phase adds an admin surface where an
    uppercase header is entirely plausible. `re:sonate` rendered as `RE:SONATE`
    breaks the brand for every visitor at once, and it is the one rule in the spec
    whose violation ships to all of them simultaneously. A rule kept only by
    remembering it is not kept.

    Do not use `tracking-widest`: at 12px it pulls `re:sonate` apart at the colon.
    Do not use the accent colour anywhere in this component — accent is reserved
    for the tab underline, the lineup pills, the venue link, the focus ring and the
    catalogue's primary button, and the moment the interaction accent borrows the
    identification channel a format stops being identifiable.

    Write nothing about what a format sounds like, in a prop name, a comment or a
    default.
