<objective>
Decide, with the owner, what the catalogue holds on day one and what each of the
three existing nights carries.

Purpose: D-36-04 says the nights already in the archive are assigned
**explicitly, inside the migration** — not by a constant default and not "later".
That means the migration needs three concrete assignments before it can be
written, and the mapping of a night to a format is a production-calendar fact
that lives with the owner, not in the repository. Getting it wrong writes a false
record of what a night *was*, and a night's format appears on a public card.

It also decides what the migration may **name**. `supabase/migrations/` is
tracked and this repository is public, so seeding a series called after a venue
that is not yet acquired would publish that venue — `venue-acquisition.md`, gate
*uno spazio non acquisito non si nomina*.

Output: a confirmed table in this plan's SUMMARY, which plan 36-03 transcribes.
</objective>
