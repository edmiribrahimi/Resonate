<objective>
Turn the measurement this phase rests on into a script, and find out which of two
disagreeing measurements is right by running the arithmetic instead of arguing
about it.

Purpose: the defect this phase exists to close **was already in production and
nobody saw it**, with **two** comments beside it declaring the opposite —
`ScanFlash.tsx:65-72` and `ScannerClient.tsx:2792-2798` both state that the
amber/yellow collision was avoided by choosing amber over yellow. Measured, the
two sit at **10,0 at normal vision and about 2 in deuteranopia**. A comment did
not prevent the defect; it asserted its absence. A gate makes it impossible to
reintroduce.

There is a second reason this comes first. **`42-CONTEXT.md` and `42-RESEARCH.md`
disagree about the numbers** — the context's table gives accept-versus-refuse
8,3 in deuteranopia and 32,6 in protanopia; the research's gives 8,1 in
deuteranopia and 31,7 in protanopia, and the two diverge further elsewhere
(`42-RESEARCH.md` §0, DISCORDANZE 1 and 2). Neither has been verified by a third
party, and **the decision that the refusal darkens rests on one of them**. The
gate is the third party. It runs the method D-42-05 names by name, and whichever
document it contradicts gets corrected in place with the date — corrected, not
deleted, which is how this repository handles being wrong.

**The gate is written here and registered later, on purpose.** On today's
unconverted colours the triple measures a minimum near 2, so a registered gate
would be red for the whole interval D-42-04 blocks — and *a gate that ships red
is a gate somebody switches off* is written three times in this gate family.
Registration travels with the colour (D-42-09).

Output: the gate, its four mutation proofs, and the arbitration written down.
</objective>

  <action>
Write `scripts/verify-scan-legibility.mjs`.

**What it reads, and from where.** Every colour comes out of a source file:

- the three outcome fills, from the three `bg:` properties of `FLASH_STATES`,
  anchored on the three state keys (`success`, `already_recorded`, `error`) and
  not on line numbers;
- the glyph ink, from the shared glyph element in the same file;
- the **Offline pill's fill**, from a **named module-level constant** in
  `ScannerClient.tsx`. That constant does not exist yet — plan 42-06 lifts it —
  so on today's tree this gate **refuses**, and that is correct. Fix the name
  here and write it into the findings so 42-06 introduces exactly what this gate
  looks for; a gate and the code it reads must not be two people guessing at each
  other;
- raw palette values from `node_modules/tailwindcss/theme.css`, parsed as
  `oklch`;
- token values from `src/app/globals.css`, parsed as hex.

**What it computes.** oklch to linear sRGB (the Ottosson matrices Tailwind v4
uses), the composite of each fill over `--ground` at its declared alpha — because
the number a person sees is the composite and not the token, and `42-RESEARCH.md`
§0 point 3 records that neither prior table considered it — then the
Brettel/Viénot/Mollon 1997 two-half-plane simulation for protanopia, deuteranopia
and tritanopia, then CIEDE2000 between each measured pair.

**Which pairs, and the exclusion written out.** The measured set is the one
`42-CONTEXT.md` D-42-01 tabulates: accept↔refuse, accept↔third state,
refuse↔third state, third state↔Offline pill, refuse↔Offline pill. **Accept
versus the Offline pill is excluded**, and the exclusion is declared in the
gate's docblock with its reason rather than left as an omission a reader has to
notice: the accept fill is a full screen and the pill is a badge in a header
which that screen covers, so the confusion the other pairs describe has no moment
in which to happen. An exclusion nobody wrote down is the exemption D-41-16 says
nobody trusts.

**A second check, in the same gate.** For each of the three composite fills,
compute the contrast of the glyph ink against it and report all three. The rule
being enforced is `globals.css:176-178` for the semantic fill; the two raw fills
are a declared derogation and carry their measured number instead. State the
threshold applied and why — the glyph is a large stroked graphic, not body text,
so the applicable floor is the graphics floor and not the text floor, and the
gate says which it used.

**`refuse()` versus `failures.push()`, and never the one for the other.**

| Refuse — exit 2, *nothing was measured* | Fail — exit 1, *measured and too close* |
|---|---|
| `theme.css` missing or unparseable | any measured pair below threshold in any of the four vision models |
| `FLASH_STATES` absent or with fewer than three entries | the glyph ink below the stated contrast floor on any composite |
| a `bg` value not recognisable as a utility with a known colour | |
| the Offline pill constant not found by name | |
| a token named in `globals.css` that the parser cannot read | |

The dangerous case is concrete: if the pill cannot be located and the gate
carries on measuring only the three outcomes, it prints a green over a
measurement it did not make. That is the exact defect it exists to prevent. It
**must refuse**.

**Print the numbers, always.** A gate that says only *OK* teaches nobody. Print
the full matrix — every pair, every vision model, the minimum, and the threshold
— on a pass as well as on a failure.

Do not register it. No `package.json` script, no `verify-all.mjs` entry. Both
travel with the colour, in plan 42-11 (D-42-09).
