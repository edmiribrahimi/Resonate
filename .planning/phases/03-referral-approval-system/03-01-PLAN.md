<objective>
Add the referred_by column to the profiles table, update the handle_new_user trigger to resolve referral codes and set status accordingly, update the registration page to capture the ?ref URL parameter and pass it through Supabase auth metadata, and update TypeScript types.

Purpose: This is the data foundation for the entire referral and approval system. The trigger is the atomic, tamper-proof mechanism that determines whether a new user gets instant access (valid referral) or enters the pending queue (no referral). Without this, none of the UI features in Plans 02 and 03 can function.

Output: Migration SQL, updated schema.sql, updated TypeScript types, referral-aware registration page.
</objective>

  <action>
  Create the migration SQL file at `supabase/migrations/20260225_phase3_referral.sql` as a single transaction (BEGIN/COMMIT) that:

  1. **Add referred_by column:** ALTER TABLE public.profiles ADD COLUMN referred_by UUID REFERENCES public.profiles(id) ON DELETE SET NULL. ON DELETE SET NULL means if the referrer's account is deleted, the referred member keeps their account but the referral link becomes NULL.

  2. **Update handle_new_user trigger:** CREATE OR REPLACE FUNCTION public.handle_new_user() that:
     - Generates membership_code (same RSN- prefix + 8 random chars logic as existing)
     - Reads `referral_code` from `new.raw_user_meta_data->>'referral_code'`
     - If `referral_code` is present and non-empty, looks up the referrer: `SELECT id INTO referrer_id FROM public.profiles WHERE membership_code = ref_code AND status = 'approved'`
     - If `referrer_id` is found (valid referral from approved member), sets `new_status := 'approved'`
     - If `referrer_id` is NULL (no referral, invalid code, or referrer not approved), sets `new_status := 'pending'`
     - Inserts the profile row with: id, email, full_name, membership_code, role='member', status=new_status, referred_by=referrer_id
     - Must remain SECURITY DEFINER
     - Add a comment in the trigger: `-- NOTE: DDL column default is 'approved' but this trigger body explicitly sets status. If this trigger fails to set status, the column default kicks in as a safe fallback.`

  **CRITICAL:** Do NOT change the column DEFAULT for status. Per user decision, it stays `DEFAULT 'approved'` in the DDL. The trigger body overrides it.

  Then update `supabase/schema.sql` to reflect the new state:
  - Add `referred_by uuid references public.profiles(id) on delete set null` to the profiles table definition (after the status column, before created_at)
  - Replace the handle_new_user function body with the new referral-aware version
  - Keep everything else unchanged (all other tables, policies, helper functions)

  **Update src/types/database.ts:**
  - Add `referred_by: string | null` to the Profile interface (after status, before created_at)
