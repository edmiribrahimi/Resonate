<objective>
The third occurrence of one defect family, in the one category the last round did
not add to the set.

`verify-dialogs.mjs` refuses when a `REMAINING` entry names a file check B never
opens — because the gate cannot tell a debt somebody **paid** from one it simply
never **read**, and left alone it reports the second as the first: `converted;
remove this entry`, and `REMAINING` falls by one. Round 3 keyed that refusal on
two of the three ways a file can go unopened. The third is structural and was
never on either list: **a path that is real, on disk, and outside the walk** —
outside `src/`, or carrying an extension the walk does not scan. It falls straight
through to the generic stale computation and produces the identical wrong report
on a file nobody opened. Proven by execution in `41-GAP-REVIEW-3.md` CR-03 with a
probe entry naming a real stylesheet: exit 0, one entry marked stale, `REMAINING`
down from 15 to 14.

And the docblock above the list says the two sets *"cannot drift apart by an edit
to either"*. They already have — by a category no edit ever added to either.

Two things to fix, and they land in one commit each because a false sentence in a
gate's header is what the next reader trusts without re-deriving it.

**Two other findings live in this same file and this plan does not take either
one.** Naming them is not throat-clearing: this phase exists because things were
declared closed that were not, and an item left out of a plan silently is
indistinguishable from an item nobody noticed.

- **WR-02** — `RUNG_FAMILY` is narrower than the sentence the report prints. The
  report promises every rung *written out* in a class string is seen, naming only
  two exclusions; Tailwind v4's CSS-variable shorthand is written out, is neither
  exclusion, and the matcher misses it. The delta was **measured at zero
  occurrences on this tree**, so nothing is hidden today — that is why it is
  deferred and not why it is closed. **Open, and out of scope for this round.**
- **WR-04** — `FULL_BLEED_VIEWER`'s exemption asserts, in prose, that the file
  *still carries a native shell*, and the gate never checks it: the exempt path is
  skipped **before** the shape measurement runs, so if that viewer converts or is
  deleted the exemption goes quiet with no notice and no on-disk check. It is the
  same proxy-goes-quiet family as CR-03, which this plan **does** take — the two
  are neighbours, and closing one is not closing the other. **Open, and out of
  scope for this round.**

The third open warning of the round, **WR-05**, is in `scripts/verify-conversion.mjs`
and is named in 41-26's objective; it is not closed by any plan in this round
either.

Purpose: DS-08's primitive is guarded by a debt list whose count means what it
says. **DS-08 does not close here** — the primitive exists and its behaviour has
never been observed on a device — and neither does DS-07, DS-09, RESP-01, RESP-02,
RESP-03 or RESP-04.

  <action>
    Three parts.

    1. **Derive the third category rather than declaring it.** Build a `walked` Set
    from the same `files` array check B's loop iterates — not from a second list, and
    not from a re-walk. The whole defect is that two lists said what is skipped while
    the refusal was keyed on one of them; a third list would be a fourth occurrence
    waiting. Deriving it from `files` makes the claim true by construction: the set that
    decides what the loop opens **is** the set the refusal is keyed on.

    2. **Add the branch to `neverOpenedReason()`, and put it first.** A path not in
    `files` never reaches the loop at all, so not-being-walked is the condition that
    acts before either of the other two — and this function's own docblock states the
    principle it must now follow: the categories are tested in the same order the loop
    skips them, so the reason a reader is given is the reason the loop would actually
    have acted on. A path that is both fenced and unwalked is not fenced in any
    operative sense; the fence never got the chance.

    The reason returned must be distinct and must say what the walk covers, so a reader
    can tell in one line whether they typed a path wrong or named a file that will never
    be scanned: under `src/` with one of the scanned extensions is the walk's whole
    scope; this path is neither, so check B never opened it and cannot tell a paid debt
    from an unread one. Print the scanned extensions from `SCANNED_EXTENSIONS` rather
    than repeating them in prose.

    **Guard it on the file existing, and this is the part the review's sketch does not
    have.** `unmeasurableRemaining` is computed and refuses **before** the `missing`
    failure is computed, so an unguarded membership test would turn a `REMAINING` entry
    with a typo — a path that does not exist — from today's `✗ B … names a path that
    does not exist` into a refusal. That is a failure laundered into "nothing was
    measured", which is the direction this whole round exists to remove. Return the new
    reason only when the path **exists on disk** and is not in `walked`; when it does
    not exist, return null and let the existing failure path handle it as it does today.

    3. **Correct the docblock, in this same commit.** The sentence claiming the two sets
    *"cannot drift apart by an edit to either"* is false, and it was false in the most
    instructive way: not by an edit, but by a category no edit ever added to either
    list. Record what was claimed, that it was false, what made it false, and what is
    true now — three mechanisms, the first two read from the same Map and fence the loop
    reads, the third derived from the walk itself so it cannot drift by construction.
    Do not edit the false sentence away without its reason: a claim withdrawn silently
    reads as a slip, and this file family has already decided to reverse in place rather
    than delete.

    Change nothing about `RUNG_FAMILY` and nothing about how `FULL_BLEED_VIEWER` is
    measured. Both carry open findings — WR-02 and WR-04 — and both are out of scope
    for this round; touching either here would mix an unclosed finding into a commit
    that claims a different closure, which is how this phase lost three rounds. If the
    docblock you are correcting sits next to the exemption, do not let the correction
    imply the exemption's own premise is now asserted: it is not.

    Write no measured line number into any prose you add. Round 3 recorded a header's
    three numbers going stale twice as lines were added above them, and this edit adds
    lines above them again. State the invariant, not the address.

    Every sentence you write into that docblock must be a claim you have measured.
  </action>
