<objective>
Close the third finding named in the gap-closure scope: `scripts/verify-touch-targets.mjs:1093`
exempts **every** raw `<button>`, `<a>`, `<Link>` and `<input>` in any file listed in
`PRIMITIVE_COMPONENTS`, unconditionally, and the premise that justifies it — *"the size lives
in the primitive"* — is asserted with `liveLines(path).some(...)`: **one** unprefixed height
of at least 44px anywhere in the file satisfies it for the whole file.

Purpose: the exemption is keyed per **file** and the premise is checked per **file**, so the
two mechanisms compound. A later edit that shrank one control in a primitive would still be
forgiven as long as one other line in the same file kept its minimum, and any raw element
added to such a file arrives pre-forgiven. Measured on this tree, exemption 2a is applied to
**10** elements across five files — `AppNav.tsx` 1, `Button.tsx` 3, `Chip.tsx` 2, `Input.tsx`
3, `Checkbox.tsx` 1 — against **9** elements measured in total. A blanket covering more
elements than the gate measures is most of what the gate could be saying.

Output: exemption 2a becomes a **declared, per-element list**, each entry carrying the reason
that element's size cannot be read at its tag; anything in a primitive file that is not on the
list is measured; and a list entry that stops matching refuses the run.

**A correction to `41-REVIEW.md` WR-04, which this plan must not copy.** WR-04 proposes
narrowing 2a to elements whose class attribute is a template literal — `class(Name)?=\{\`` —
and claims that this makes `AppNav`'s and `StaffNav`'s entries measured. **It does the
opposite, measured on this tree.** `AppNav.tsx:215` and `StaffNav.tsx:125` both write
`className={` followed by a backtick, so both would stay exempt; while `Button.tsx:228`,
`Button.tsx:236`, `Chip.tsx:144` and `Chip.tsx:157` write `className={classes}` — an
identifier, not a template literal — and would all become measured with no readable height,
turning **four correct elements red**. That is D-41-19's forbidden direction: a gate that
reddens on correct code gets switched off, after which it guards nothing while looking like it
does. WR-04's diagnosis is right and its patch is wrong; this plan takes the diagnosis.

**The line numbers above are this tree's, not the review's.** `41-REVIEW.md` WR-04 cites
the two Chip elements at `:140` and `:152`; measured on the current tree they are at
`Chip.tsx:144` and `Chip.tsx:157`. Nothing turns on the four digits — task 1 derives every
matching fragment by reading the file and never by citation — but a line number that has
drifted is one a later reader trusts wrongly, so the SUMMARY records that the review's
citations were stale rather than silently correcting them.

**What this does not close.** RESP-03 remains PARTIAL and is not ticked. This gate asserts a
class string and never a rendered box, and **H41-4 — the smallest control measured on a large
touch screen — is still the only proof that anything is 44px**, still `human_needed`, still
untouched by anything here. `StaffNav.tsx` is not in scope at all: it is reached by no
converted surface's closure, because the three work pages get it from
`src/app/(admin)/admin/(work)/layout.tsx`, which a page's import closure does not include.
