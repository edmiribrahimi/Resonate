<objective>
**The gate declares its own limit. It does not grow a fifth pattern.**

A navigation clearance reaches the four focus routes from **outside**
`src/components/ui/PageShell.tsx` entirely — an ordinary Next route layout above
the auth group, an imported constant, a stylesheet. Reproduced twice, once by
the review and once independently by the verification, on disposable copies: a
new layout above the auth group carrying the leading inline-start clearance, a
raw palette colour and a container maximum reaches `/login`, `/register` and
`/set-password` with **the scanned-file count unchanged**, the route table still
printing no navigation for all three, and the run exiting 0.

The wrapper *is* enumerated: `layoutClosure` climbs it to ask exactly one
question — is a declared navigation module reachable from it. Its own class
strings are opened by nothing. It never enters `allScanned`, so checks A, B and D
never read it either.

**Do not plan a check for layouts. Do not teach the matcher a fifth pattern. Do
not feed the climbed set into `allScanned`.** That direction has failed four
consecutive rounds on CR-01 itself: round 1 asserted on the constant and the
defect moved to the render site; round 2 asserted on the outer element and it
moved to the inner one; round 3 asserted on the branch as a region and it moved
to the branch's shape; round 4 asserted on the file by digest and it moved to
what the digest is computed from — and to a route the digest was never asked to
cover. The mechanism is a text scanner over one file. The property that actually
matters is what reaches a route **at render**, and no textual mechanism over one
file spans that.

So the honest act, and the only one this round takes, is the one this project
already requires of itself everywhere else: **an unmeasured region must be
declared unmeasured.** The gate covers the FILE, not the ROUTE; a clearance
introduced outside that file is not measured; and that is a **boundary, not an
approval**. Shipping it undeclared — today's state — is the one option that is
not acceptable to leave as-is.

This phase has already found two false header sentences and corrected both in
place. The precedent is on the record; this is the same rule applied to a gate's
claim about its own reach.

**What this plan does NOT take, and why each absence is a decision.**

- **Group C's structural half is the owner's.** Making the clearance structurally
  unable to reach those four routes — for example by moving the navigation
  clearance to the layout that actually mounts the navigation — edits product
  files under the auth group and the payment callback. Those are `access-gating`
  and `ticketing-payments` primary, and this project requires owner validation
  before acting on a Critical path. It belongs to **41.1**, where those surfaces
  convert anyway. This plan records it; it does not decide it.
- **Group B's four items stay open**, by decision: the `NOT IN THE WALK` guard
  covering one of three branches; the refusal branch advertised in a header that
  nothing can reach; the permitted site keyed on line text rather than position;
  and the existence check whose verdict depends on the filesystem's case
  sensitivity. Polishing refusals inside a mechanism whose limit is now known is
  work that looks like progress.
- **No verdict moves.** This plan changes prose and printed strings. It touches no
  condition, no matcher, no frozen digest, no closure and no scanned set.

Purpose: RESP-01, RESP-02 and RESP-04 are guarded by a check whose reach a reader
can now state correctly without re-deriving it.

Output: the header block of `scripts/verify-conversion.mjs`, one over-claiming
printed sentence, and two entries in the phase's deferred register. **No product
file is edited.**

**No requirement closes here.** All seven stay PARTIAL. A declared limit is not a
closed gap: it is a gap somebody can now see.
