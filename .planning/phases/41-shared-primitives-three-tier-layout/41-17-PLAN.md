<objective>
Give CR-01 a gate. `41-VERIFICATION.md`'s `missing` list asks for it in those words: *"plus a
G4 assertion that a converted page whose closure contains no AppNav/MobileNav import does not
read `--nav-inset-*`."* Plan 41-13 closed the defect in code; nothing in the repository would
notice it coming back.

Purpose: G4's check D asserts that the shell declares §4's three maxima, that every converted
page imports the shell, that no page writes a maximum of its own, and that the manifest's width
agrees with §4's two closed lists. All four were green on all four broken surfaces, throughout.
Nothing asserts that the clearance a surface reserves matches the navigation it actually mounts,
which is the question CR-01 turned out to be.

Output: **check E**, in the same file as check D because it is the same gate, in two parts —
the shell's focus root reserves nothing, and every converted surface's declared width agrees
with the navigation it mounts.

**Why this is a two-way assertion and not a prohibition.** If a surface mounts no navigation it
must be on §4's `focus` list, whose form reserves nothing; if it mounts navigation it must not
be, because the focus form would leave it under the bar. The moment phase 41.1 or 41.2 declares
a navigation-free surface at `default` or `wide` width, this check goes **red** — and that red
is correct, not a false one: such a surface really would reserve a column that is not there.
That is when `PageShell` gets the `nav` prop that plan 41-13 deliberately did not write, with
its first consumer in the same commit, which is D-41-04's rule.

**What this does not close.** RESP-01 and RESP-02 remain PARTIAL; RESP-01 closes only after
phase 41.2. A green from check E says the declared width matches the mounted navigation and
that the focus root reserves nothing. It does **not** say a card is centred: **H41-1** and
`41-CR01-PASS.md` are the only things that say that, and both are owed and unmade.
</objective>

<interfaces>
**Where a converted surface's navigation actually comes from, measured on this tree.** This is
the fact the check is built on and it is not obvious from a page's imports:

| Surface | Width | Navigation mounted | Reached how |
|---|---|---|---|
| `/login` | focus | **none** | no `(auth)` layout exists; the page imports neither nav module |
| `/register` | focus | **none** | same |
| `/set-password` | focus | **none** | same |
| `/payment/callback` | focus | **none** | no `(public)/payment` layout exists; the page imports neither |
| `/gallery` | wide | `AppNav` | the **page itself** imports and renders it |
| `/admin/formats` | wide | `AppNav` | `src/app/(admin)/admin/(work)/layout.tsx` |
| `/admin/members` | wide | `AppNav` | the same layout |
| `/admin/members/register` | default | `AppNav` | the same layout |

Four mounted, four not, and the four not are exactly §4's closed `focus` list. **A check that
looked only at a page's import closure would call the three work surfaces navigation-free** —
a layout is not imported by the pages it wraps — and would redden three correct files. The walk
has to climb the route segments.

`find src/app -name "layout.tsx"` returns exactly **two** files today: `src/app/layout.tsx`
(which mounts `MotionProvider` and `ToastProvider` and no navigation) and the `(work)` one.

**The two navigation modules, and why they are two:** `src/components/layout/AppNav.tsx` carries
both tiers, and `src/components/layout/MobileNav.tsx` is the thin wrapper that renders `AppNav`
locked to its phone form so the door keeps today's layout (D-41-21). Either one mounted is
navigation mounted.

**What the file already gives you and what must not be rewritten:** `importClosure()` returns
`{ reached, unresolved }` and **refuses** when anything is unresolved, because a narrowed walk is
the failure direction that prints a tick; `surfaces[i].reached` already holds each page's full
closure including spine files; `liveLines()` blanks comments in the four shapes DEF-41-02
records; `refuse()` exits **2** and means nothing was measured; `listScannableFiles()` walks a
directory.

**What plan 41-13 leaves for this check to read:** a module-level `FOCUS_ROOT` in
`src/components/ui/PageShell.tsx`, a single-line double-quoted string literal. Check E reads that
literal by name. Naming an identifier a gate reads is the same choice §13's exemption 4 already
makes — *a marker beats a heuristic: it forces the author to say so, and it is greppable.*
</interfaces>
