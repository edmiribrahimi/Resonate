<objective>
Close **WR-05** and **WR-06** in `scripts/verify-conversion.mjs`.

**WR-05.** The gate refuses on a `layout.*` basename with an untested extension, and the
reason it gives is exactly right: *"a walk that skips one reports those surfaces as
navigation-free — which is a narrowing in the direction that prints a tick."* Next renders
`template.tsx` around a page in the same position a layout occupies, and that basename is
neither climbed nor refused on. A `src/app/(auth)/template.tsx` mounting a navigation
module would leave all four focus surfaces reported navigation-free, E2 would find
agreement, and the tick would print. A hole in the very enumeration check E depends on.

**WR-06.** Two shapes of *correct* file take the whole conversion gate to exit 2, and
through the aggregate that is `VERIFY_REFUSED` for the entire suite: a basename beginning
`layout.` with an extension outside the four — `layout.module.css` is the standard Next
name for a layout's CSS module, `layout.tsx.orig` is what a merge conflict leaves — and a
trailing `//` comment on the `FOCUS_ROOT` line, which the line-shape stripper does not
remove and the literal regex's end-of-line anchor then rejects. §0 rule 3 is quoted three
times in these files: a gate that goes red on correct code gets switched off.

Purpose: the enumeration covers what Next actually wraps with, and the refusals fire on
the cases they were written for and not on correct files.

Output: `scripts/verify-conversion.mjs` with `WRAPPER_BASENAMES` used by both the
enumeration and the climb, an extension refusal reserved for extensions that plausibly are
route modules, and a focus-root literal regex tolerant of a trailing line comment — each
proven by mutation in both directions.

**This plan closes no requirement.** RESP-02 and RESP-04 stay PARTIAL. RESP-04's runtime
half — filters and navigation visible without opening a menu from tablet width up — is
H41-6a and is unobserved.
</objective>
