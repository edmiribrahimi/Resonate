<objective>
Write the touch-target gate — the one the research flagged as **the most dangerous of the
five** — and put it through the proof D-41-19 requires before it is allowed to exist.

Purpose: RESP-03 says targets stay finger-sized wherever the input is a finger, large
touch screens included. G5 is the only mechanical part of that, and it is mechanical in a
narrow sense that must be written into the file: **it asserts a class string; it does not
assert a rendered box.** A class-string parser cannot see a flex stretch, an icon-set
height, a `line-height` override or a target padded by an ancestor. The research's figure
— 118 of 174 measurable elements under 44px — is a heuristic and stays labelled as one.

The danger is not a missed defect; it is a **red on a correct file**. Run tree-wide, G5
goes red on Phase 42's files, on decorative anchors, on icons inside stretched flex rows,
and on elements padded by an ancestor — and a gate that fires on correct code gets
switched off, after which it guards nothing while looking like it does.

So it is scoped to converted files, it exempts Phase 42 by path with the reason in the
script, and **it is proven green on `src/components/admin/MemberTable.tsx` before it is
committed — or it is not written at all.** That last clause is not rhetoric: task 3 is
allowed to end by deleting the file.

Output: one gate that survived both proofs, or one recorded decision not to have one.
</objective>

<interfaces>
§13's statement of what G5 asserts, and it is the sentence to put at the top of the file:

> **over the files named in the conversion manifest and only those: every `<button>`,
> `<a>`, `<Link>`, `<input>`, `<select>`, `<textarea>` and `<summary>` written outside a
> primitive carries `min-h-11` (or a larger explicit `h-*`/`min-h-*`) in its class
> string, or matches an exemption below. It asserts a class string. It does not assert a
> rendered box.**

The exemption list, closed today, six items:
1. **Phase 42, by path, with the reason in the script** — `src/app/(admin)/**/scanner/**`,
   `src/components/scanner/**`, `src/app/(admin)/door/**`. `ScannerClient.tsx:2909,2918`
   are ~18px and are the smallest interactive elements in the tree; they are not this
   phase's.
2. **Elements rendered by a primitive** — `Button`, `IconButton`, `Chip`, `Input`,
   `Select`, `Textarea`, `Checkbox`, `Switch`, `AppNav`, `StaffNav`. The size lives in the
   primitive and G5 does not parse the call site.
3. **The DataTable desktop branch's row actions**, carrying `pointer-fine-only:min-h-9`.
   G5 permits `min-h-9` **only** when both that variant and the `DataTable` import are
   present in the file.
4. **A wrapper whose only child is another interactive element**, which must carry
   **`data-target="child"`** — a declared marker the gate reads. A marker beats a
   heuristic: it forces the author to say so, and it is greppable.
5. **A visually-hidden input whose visible target is its label** — `peer sr-only` on the
   input plus a `<label>` carrying `min-h-11`. G5 reads the label.
6. **Non-interactive `Badge`** — G5 scans interactive elements only. **A badge that is a
   `<Link>` or a `<button>` is a Chip** and is not exempt.

`scripts/verify-tokens.mjs:535-554` `consumerPattern()` supplies the boundary-guard
technique the class-string parse needs. `liveLines` supplies comment blanking.
`refuse()` → exit **2** is *could not measure*, distinct from exit 1.

Plan 41-10's SUMMARY carries the list of every element in `MemberTable.tsx` that fits
none of the six shapes — read it before writing the parser, because that list is the
green proof's risk register.
</interfaces>
