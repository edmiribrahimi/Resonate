**Part B: Guest server actions**

Create `src/app/(public)/events/[slug]/menu/actions.ts` with `"use server"` directive. This file contains two server actions that do NOT require authentication.

**`purchaseDrinksGuest(eventId, items)`**

Mirror of `purchaseDrinks` from `src/app/(organizer)/organizer/events/actions.ts` with these differences:
- NO authentication check (no `createClient()`, no `getUser()`)
- Use `getServiceClient()` from `@/lib/supabase/service` for ALL database operations (service-role bypasses RLS)
- Set `user_id: null` in the `drink_orders` insert
- Return `{ success: true, checkoutId: response.id, orderId: order.id }` — the guest client needs `orderId` for localStorage + URL persistence
- To get `orderId`, use `.select("id").single()` on the insert (same pattern as research example)

Signature:
```typescript
export async function purchaseDrinksGuest(
  eventId: string,
  items: { drinkItemId: string; quantity: number }[]
): Promise<{ success: boolean; checkoutId: string; orderId: string }>
```

Logic (follow purchaseDrinks exactly, minus auth):
1. Validate items array is non-empty
2. Fetch drink_items by IDs using service client, filtered by `event_id` and `is_available: true`
3. Validate all items found and available (same checks as purchaseDrinks)
4. Calculate totalAmount, build itemsSnapshot
5. Fetch event title for checkout description
6. Create SumUp checkout via `createCheckout()` with same params pattern
7. Insert `drink_orders` with `user_id: null`, return orderId from `.select("id").single()`
8. Return `{ success: true, checkoutId: response.id, orderId: order.id }`

**`redeemDrinkTokenGuest(signedToken)`**

Mirror of `redeemDrinkToken` with these differences:
- NO authentication check
- Instead of ownership check (`token.user_id !== user.id`), check that `token.user_id === null` (guard: only guest tokens can be redeemed via this action)
- Use `getServiceClient()` for all DB operations

Signature:
```typescript
export async function redeemDrinkTokenGuest(
  signedToken: string
): Promise<{ success: true }>
```

Logic:
1. `verifyTicketToken(signedToken)` — throw "Invalid token signature" if null
2. Fetch token by id via service client: `.select("id, user_id, status").eq("id", tokenId).single()`
3. If `token.user_id !== null` — throw "Use authenticated redemption flow" (guard against misuse)
4. If `token.status === "redeemed"` — throw "Already redeemed"
5. Call `serviceClient.rpc("redeem_drink_token", { p_token_id: tokenId })`
6. If RPC error — throw "Redemption failed"
7. Return `{ success: true }`

Import `verifyTicketToken` from `@/utils/qr`, `getServiceClient` from `@/lib/supabase/service`, `createCheckout` from `@/lib/sumup`.

Create `src/app/api/drinks/tokens/route.ts` — a Next.js App Router GET API route that fetches drink tokens by `order_id` using the service-role client (bypasses RLS entirely).

This API exists because guests cannot use RLS-gated queries (they have no auth session). The `order_id` UUID acts as a capability token — knowing it proves access.

```typescript
import { NextRequest, NextResponse } from "next/server";
import { getServiceClient } from "@/lib/supabase/service";
```

**GET handler:**

1. Extract `order_id` from `request.nextUrl.searchParams`
2. If missing, return `{ error: "order_id required" }` with status 400
3. Validate UUID format with regex `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i` — return 400 if invalid
4. Use `getServiceClient()` to query `drink_orders` by id: `.select("id, status, user_id").eq("id", orderId).single()`
5. If order not found, return 404
6. **Security guard:** If `order.user_id !== null`, return `{ error: "Use authenticated flow" }` with status 403. This ensures the API only exposes guest (anonymous) tokens, never authenticated users' tokens.
7. Query `drink_tokens` by `order_id`: `.select("id, drink_name, price, token, status, redeemed_at").eq("order_id", orderId).order("created_at", { ascending: true })`
8. Return `{ tokens: tokens ?? [], orderStatus: order.status }`

Do NOT add any authentication middleware. This route is intentionally public, secured by UUID unpredictability + the user_id null guard.

Export only the GET function.
