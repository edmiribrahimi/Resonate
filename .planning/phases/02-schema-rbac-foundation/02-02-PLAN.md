  <name>Task 1: RBAC constants module and middleware role enforcement</name>
  <files>src/lib/rbac/roles.ts, src/lib/supabase/middleware.ts</files>
  <action>
  **Create src/lib/rbac/roles.ts:**
  Central RBAC constants module. Export:
  - Re-export `UserRole` and `UserStatus` types from `@/types/database` (single source of truth)
  - `ROLES` constant object: `{ MASTER: "master", ORGANIZER: "organizer", MEMBER: "member" } as const`
  - `STATUSES` constant object: `{ PENDING: "pending", APPROVED: "approved", REJECTED: "rejected" } as const`
  - Navigation items array with role/status requirements per item (see MobileNav task for shape)
  - `getVisibleNavItems(role: UserRole | null, status: UserStatus | null)` function that filters nav items based on role and status. Logic per CONTEXT.md:
    - Pending/rejected: only see Home, Events, and Dashboard (dashboard shows pending state)
    - Approved member: see Home, Events, Gallery, Members (dashboard)
    - Organizer (approved): same as member PLUS "Organizer" item linking to /organizer/members
    - Master (approved): same as member PLUS "Admin" item linking to /admin/members
    - Unauthenticated (role=null): see Home, Events, Gallery only (no Members/dashboard)

  **Rewrite src/lib/supabase/middleware.ts:**
  Enhance `updateSession()` to resolve user role and enforce route access. Key changes:

  1. After `supabase.auth.getUser()`, if user exists, query their profile: `supabase.from("profiles").select("role, status").eq("id", user.id).single()`. Extract role (default "member") and status (default "pending").

  2. **Header injection:** Create new request headers containing `x-user-role`, `x-user-status`, and `x-user-id`. Create the response with these headers: `NextResponse.next({ request: { headers: requestHeaders } })`.

  3. **CRITICAL: Cookie preservation.** After creating the new response with injected headers, the Supabase cookies are lost because a new response object was created. Fix: Track all cookies set by Supabase's `setAll` callback in a local array. After creating the final response with headers, re-apply ALL tracked cookies to that response. This prevents users from being logged out on every navigation.

  Implementation approach for cookie preservation:
  ```
  let pendingCookies: Array<{name, value, options}> = []
  // In setAll callback: push to pendingCookies AND set on current response
  // After creating final response with headers: iterate pendingCookies and set on final response
  ```

  4. **Route protection logic** (order matters):
     - If user is NOT authenticated:
       - Protected routes (`/dashboard`, `/membership-card`, `/attendance`, `/admin`, `/organizer`) -> redirect to `/login?redirect={pathname}`
       - All other routes -> allow
     - If user IS authenticated:
       - `/admin/scanner` -> allow if role is master OR organizer; otherwise redirect to `/dashboard`
       - `/admin/*` (except scanner) -> allow only if role is master; otherwise redirect to `/dashboard`
       - `/organizer/*` -> allow if role is master OR organizer; otherwise redirect to `/dashboard`
       - `/membership-card`, `/attendance` -> allow only if status is "approved"; otherwise redirect to `/dashboard`
       - All other routes -> allow

  5. Do NOT import from `src/lib/rbac/roles.ts` in middleware (middleware runs in Edge runtime and should minimize imports). Inline the route checks directly.

  6. Keep the existing Supabase client creation pattern and matcher config in `src/middleware.ts` (do not modify that file).
