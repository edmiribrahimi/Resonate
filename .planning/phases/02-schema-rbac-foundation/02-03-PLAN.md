  **Create src/app/(admin)/admin/members/actions.ts:**
  Mark with `"use server"` directive. Create these Server Actions:

  1. `updateMemberRole(memberId: string, newRole: "organizer" | "member")`:
     - Create Supabase server client via `createClient()` from `@/lib/supabase/server`
     - Verify the calling user is authenticated via `supabase.auth.getUser()`
     - Verify the calling user's profile has role="master" (query profiles table)
     - If not master, throw Error("Forbidden: only master can change roles")
     - Prevent changing own role: if memberId === user.id, throw Error("Cannot change own role")
     - Update the target profile: `supabase.from("profiles").update({ role: newRole }).eq("id", memberId)`
     - Call `revalidatePath("/admin/members")` after success
     - Return `{ success: true }` or throw error

  2. `deactivateMember(memberId: string)`:
     - Same auth/master verification as above
     - Prevent deactivating self: if memberId === user.id, throw Error("Cannot deactivate yourself")
     - Update target profile: `supabase.from("profiles").update({ status: "rejected" }).eq("id", memberId)`
     - Also reset role to "member" if they were an organizer (demote + deactivate in one)
     - Call `revalidatePath("/admin/members")`
     - Return `{ success: true }` or throw error

  3. `reactivateMember(memberId: string)`:
     - Same auth/master verification
     - Update target profile: `supabase.from("profiles").update({ status: "approved" }).eq("id", memberId)`
     - Call `revalidatePath("/admin/members")`

  **Create src/app/(admin)/admin/members/page.tsx:**
  Server Component page for master admin member management.

  1. Read `x-user-role` from headers to confirm master (defense in depth -- middleware already blocks non-master, but verify in page too). If not master, redirect to /dashboard.

  2. Fetch all profiles from Supabase: `supabase.from("profiles").select("id, email, full_name, role, status, membership_code, created_at").order("created_at", { ascending: false })`. The RLS policy `profiles_select_admin` allows master to see all profiles.

  3. Render the member list as a styled HTML table (no component library -- use Tailwind per research recommendation). Columns:
     - Name (full_name)
     - Email
     - Role (displayed as badge with color: master=purple, organizer=blue, member=gray)
     - Status (badge: approved=green, pending=yellow, rejected=red)
     - Joined (created_at formatted as locale date string)
     - Actions column

  4. Actions column per member row (do NOT show actions for the master's own row):
     - If role=member AND status=approved: "Promote to Organizer" button (calls updateMemberRole with "organizer")
     - If role=organizer: "Demote to Member" button (calls updateMemberRole with "member")
     - If status=approved: "Deactivate" button (calls deactivateMember) -- shown for non-master members
     - If status=rejected: "Reactivate" button (calls reactivateMember)
     - If status=pending: "Approve" button (calls reactivateMember -- same action, sets to approved) and "Reject" button (calls deactivateMember)

  5. Use a client component wrapper for the action buttons that handles `useTransition` for loading states and `useActionState` or form actions for error handling. Create this as an inline "use client" component within the same file or as a separate `MemberActions.tsx` component in the same directory. Each button should show a loading spinner during the action and display errors via a toast or inline message.

  6. Add client-side filtering: a text input that filters the table by name or email (client-side filter on the already-loaded data). Add a role filter dropdown (all/master/organizer/member) and status filter dropdown (all/pending/approved/rejected). These are client-side only -- no server round-trip for filtering.

  7. Add a count summary at the top: "X members total, Y organizers, Z pending".

  8. Page header: "Member Management" with back link or just the title. Include MobileNav with role/status props at the bottom.

  9. Style with Tailwind: dark theme consistent with existing pages (bg-background, text-foreground, border-card-border, accent colors). Table rows with hover state. Responsive: on mobile, show a card layout instead of table (use responsive Tailwind breakpoints: hidden on sm, visible on lg for table; inverse for cards).

  - "referred by" and "event count" columns: referred_by does not exist yet (Phase 3 adds it) and event count requires a join to attendances. For now: show "referred_by" as "--" (placeholder) and "event count" as a count from attendances table via a left join or separate query.
