<objective>
Name the door's three outcomes once.

The shared root of this phase is that the online path and the offline path each
invented their own vocabulary: `/api/tickets/checkin` encodes failure in the JSON
body at HTTP 200 (`route.ts:41, 44, 59, 66, 101` — five `NextResponse.json` calls
with no status argument), the scanner reads a different set of strings
(`ScannerClient.tsx:414-479`), and the sync manager reads neither
(`sync-manager.ts:36` tests `res.ok`). Nothing failed loudly because every
vocabulary was internally consistent and none of them agreed.

This plan writes the one contract everything else in the phase is built against.
In a repository with no test runner, `next build` is the only automatic gate
there is, and a shared *type* is the only way to make a divergence between the two
paths trip it.

It also adds the two small utilities the third outcome needs and nothing else
owns: `partyEndInstant` beside its siblings in `src/utils/datetime.ts`, and a
third haptic pattern in `src/utils/haptics.ts`.

Purpose: nothing else in this phase can be written against a contract that does
not exist yet.
Output: `src/lib/door/outcome.ts`, plus one function in each of two existing
utility modules.
</objective>
