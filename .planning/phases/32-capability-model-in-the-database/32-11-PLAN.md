  <what-built>
The capability model, with nothing carried in the access token. Measured on this
project: `hook_custom_access_token_enabled = false` and `jwt_exp = 3600`, so a
capability minted into a token would be stale for up to an hour after a change.
Everything else in this phase is proved by artefacts; this one is a claim about
**elapsed time between a write and a reload**, and no static assertion can express it.
  </what-built>
  <how-to-verify>
Two browser windows are needed, and the operator acts as the project owner in the
Supabase SQL editor for the grant-table edit — `private` is deliberately not reachable
over the REST API, so there is no in-product path to it and there is not meant to be.

The demonstration **removes** a permission first and restores it, rather than granting
one. Grant rows are per role, so granting a capability to `member` would widen access
for every member for the length of the demonstration; removing one narrows it, and
proves the same immediacy in both directions (D-35).

1. In window A, sign in with a **member** account. Open `/membership-card`. It loads.
   Note the time to the second.
2. In the SQL editor, run
   `delete from private.role_capabilities where role = 'member' and capability =
   'membership.card.view';`
   Note the time to the second.
3. In window A, **reload the page without signing out and without closing the tab.**
   It must redirect to `/dashboard`. Note the time to the second.
4. In the SQL editor, restore the row:
   `insert into private.role_capabilities (role, capability, requires_approved) values
   ('member','membership.card.view',true) on conflict do nothing;`
   Note the time.
5. Reload again, still without signing out. `/membership-card` loads. Note the time.
6. Confirm the row is back:
   `select count(*) from private.role_capabilities;` must read **16**.

The point is the arithmetic: steps 2→3 and 4→5 are seconds apart, and the access token
in that browser is up to an hour old and was never re-issued. Record all five
timestamps.
  </how-to-verify>

    - `private.role_capabilities` holds **16** rows at the end. Pasted.
    - If the reload does **not** change the verdict, stop: a capability is being cached
      somewhere it must not be, and CAP-04 fails. Report where it was cached.
  </acceptance_criteria>
