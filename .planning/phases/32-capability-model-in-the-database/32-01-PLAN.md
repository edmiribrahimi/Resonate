<objective>
Build the read-only half of the CAP-03 evidence harness: a zero-dependency Node
script that captures **B1** (all 67 rows of `pg_policies`) and **B5** (both
Supabase advisors) from a live target and writes them as deterministic,
committable JSON.

Purpose: CAP-03 says a master, an organizer and a member can do neither more nor
less than before this phase. That is a measurement problem, not a coding one, and
**a baseline taken after the change is not a baseline**. Nothing in this phase may
write DDL until this harness and its siblings have run and their output is
committed.

Output: `scripts/rls-baseline.mjs` with its `capture` mode covering B1 and B5, and
one `package.json` script entry. No artefact is committed by this plan — the first
capture is plan `32-04`.

`verify-persona.mjs`'s shape: shebang, a header comment saying why the file exists

Environment. Load `.env.local` with `process.loadEnvFile` (Node 25.6.1 is installed;
`.env*` is gitignored). Require `SUPABASE_ACCESS_TOKEN` and
`NEXT_PUBLIC_SUPABASE_URL`; derive the project reference from the URL's first
hostname label. **The project reference, the access token and the Supabase URL are
never written to stdout and never written into an artefact** — `.planning/` is
public (`CLAUDE.md` Guardrail 5). A missing variable exits **2**, not 1.

Target abstraction. Export one function that runs a SQL string against the target
and returns rows. For this plan the only target is `management-api`: `POST` to
`/v1/projects/{ref}/database/query` with `Authorization: Bearer`, and a `read_only`
flag the caller sets. Global `fetch`; no HTTP dependency. Plan `32-04` adds a second
target behind the same function signature, so keep the SQL strings free of anything
API-specific.

CLI. `--target=production` (default) and `--only=B1,B5` so later plans can capture a
subset. Write artefacts under
`.planning/phases/32-capability-model-in-the-database/baseline/`, creating the
directory if absent. A `--phase-point=<label>` flag names the capture (`pre` for the
first one); it is written into the artefact and used in the filename suffix only
when it is not `pre`, so that `32-BASELINE-policies.json` is the pre-phase file and
`32-BASELINE-policies.post-07.json` is a later one.

Determinism contract (D-15), written as a comment block in the file because a
non-deterministic artefact produces a diff that hides the real one: build the
top-level object with its keys in the declared order; sort every row array by a
declared composite key before serialising; sort every nested array;
`JSON.stringify(value, null, 2)` and one trailing newline. No timestamp finer than a
date — a capture that differs only in its clock is a diff that trains the reader to
ignore diffs.

Reporter and exit codes, copied from `verify-persona.mjs`: `0` green, `1` a check
failed, `2` the environment is wrong. Print one line per artefact written with its
row count.

Add `"baseline:rls": "node scripts/rls-baseline.mjs"` to `package.json` scripts.
