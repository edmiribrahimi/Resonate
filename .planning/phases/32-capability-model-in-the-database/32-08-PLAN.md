<phase_decisions>
- **D-05** — **the middleware fork, resolved.** The header-injection block at
  `src/lib/supabase/middleware.ts:135-139` still needs `role` and `status` as values,
  and removing it is CAP-05 in phase 33 across 46 files. Therefore
  `public.my_access_context()` returns `role` and `status` alongside `capabilities`,
  and the middleware replaces its `profiles.select("role, status")` with **one** RPC
  call. Delta: **zero** extra round trips. The alternative — keeping the profile read
  beside a capabilities-only RPC — was rejected: the matcher includes `/api/*`, so it
  would add a database round trip to **every door scan**, and at the door a slow query
  is a queue. The cost of this choice is that two fields exist in the payload for a
  consumer scheduled for deletion; phase 33 removes them.
- **D-28** — **a resolver failure fails closed to the identical verdict, and says so
  out loud.** Today the middleware discards the profile query's error at `:49` and
  silently defaults to `member` / `pending`. Preserving that verdict is required by
  CAP-03; preserving the silence is forbidden by `meta-gates.md`, and there is no error
  tracking in this project, so a log is a place nobody looks. On failure the middleware
  keeps the fail-closed defaults **and** sets a diagnostic header on the **response**,
  and deletes that header name from the inbound request headers alongside the three
  `x-user-*` names, because an inbound copy would be attacker-supplied input.
- **D-13** — exactly **one** server-action guard is converted in this phase, as the
  reference: `requireMaster` in `src/app/(admin)/admin/newsletter/actions.ts:15`. The
  other 45 header readers stay for phase 33. Newsletter is chosen over the
  byte-identical copy in `admin/finance/actions.ts` because finance is a money surface
  and this phase should not touch one.
- **D-29** — `NAV_ITEMS` is **not** converted. Its `/admin/scanner` entry disagrees
  with the middleware rule for the same path, and B4 records that disagreement
  verbatim. Resolving it is a product decision, not a refactor.
</phase_decisions>

wrapped in React `cache()`, which builds the cookie-bound client from

file, the way `outcome.ts` writes its own.

Both exports take no user identifier: the resolver answers about the current session
only, which is the same shape rule as the SQL wrapper (D-04).

middleware runs in a separate execution and cannot share it, so a page that asks
independently pays one round trip; prefer passing a resolved set down over re-asking
in a leaf component.

`getAccessContext` twice in the converted server action of Task 3 during a temporary
instrumented run, count the requests reaching PostgREST, confirm it is one, then
remove the instrumentation. Record the observation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → middleware | inbound headers are attacker-supplied; the middleware is the only writer of `x-user-*` |
| middleware / server action → PostgREST | the anon-key, cookie-bound client, so RLS applies to the caller |
| resolver failure → the user | a failure here is a total denial, and there is no error tracking in this project |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-08-01 | Spoofing | the new diagnostic header being sent inbound by a client and read downstream | mitigate | the name is deleted from `requestHeaders` in the same block as the three `x-user-*` names, with the reason written beside it; it is only ever set on the response |
| T-32-08-02 | Elevation | the RPC called outside the `if (user)` branch, so an anonymous request errors and the failure path is entered on every anonymous hit | mitigate | the call stays inside the existing `if (user)`; `public.my_access_context()` is revoked from `anon` by design |
| T-32-08-03 | Elevation | the resolver built on the service-role client, which bypasses every policy and would prove nothing | mitigate | `src/lib/capabilities/server.ts` imports the cookie-bound client only; asserted by grep in the acceptance criteria |
| T-32-08-04 | Denial of service | a resolver failure denying everything, indistinguishable from a correct refusal | mitigate | D-28: fail closed to the identical verdict, a categorised log line, **and** a diagnostic response header; the degraded path is exercised manually and recorded |
| T-32-08-05 | Elevation | the `/admin/scanner` rule falling into the general `/admin` branch, locking organizers out of the door | mitigate | the `if` / `else if` ordering is preserved verbatim and no lookup table replaces it; the 44-cell verdict table covers `organizer/approved` on `/admin/scanner` explicitly |
| T-32-08-06 | Information disclosure | `role` and `status` in the exposed payload tempting new callers to branch on them again | accept | no new exposure — a subject can already read its own profile row under `profiles_select_own`; the payload comment forbids new consumers and phase 33 removes both fields |
| T-32-08-SC | Tampering | npm installs | mitigate | this plan installs nothing; `react`'s `cache` is already a dependency |
</threat_model>
