# Phase 52.4 Plan 05: la coda offline porta l'ora limite e l'eccezione — Summary

Il telefono conserva per ogni biglietto l'istante limite calcolato dal server (`entryUntil`, senza bump di `DB_VERSION`), scrive «Admit anyway» dentro la stessa entrata `pending` della coda (`override`, `overrideBy`, `overrideAt`), e il drain lo consegna a `/api/tickets/checkin` come `override: "entry_until"`.

## Cosa e' stato fatto

**Task 1 — store (`a3570a2f`)** — `src/lib/offline/checkin-store.ts`
- `AttendeeRecord.entryUntil?: string | null` con docblock nello stile di `benefit`: istante ISO del server, assente/null = nessun limite = si ammette; il telefono non converte mai un orario di Torino.

- `PendingCheckin.override?: "entry_until"`, `overrideBy?: string` (id del dispositivo), `overrideAt?: string` (= `scannedAt` dell'entrata).
- `checkInLocally(partyId, subjectType, subjectId, opts)`: firma invariata nei primi tre parametri, `opts.override?` aggiunto; l'eccezione si scrive solo nel `pending.put` dentro `if (!queued)`, con il caso dichiarato nel commento.
- `const DB_VERSION = 6;` invariata.

- `targetFor`, ramo `"ticket"`: `...(entry.override ? { override: entry.override } : {})`. `overrideBy`/`overrideAt` non viaggiano (dichiarato nel commento). Conteggio di `source: "offline_sync"` invariato (2). La rotta (piano 04, `route.ts:338-339`) accetta solo il valore esatto `"entry_until"`.
