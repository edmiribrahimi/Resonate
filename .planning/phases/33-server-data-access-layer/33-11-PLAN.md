<objective>
Convert the six public pages that read a header and gate **nothing** with it.

Four of them — the home page, the gallery, the newsletter page and the ticket
page — read `x-user-role` and `x-user-status` solely to hand both to
`<MobileNav>`. There is no `redirect`, no `notFound`, no query change. They are
the purest form of what the census found: 42 of the 44 readers pass the values
to a client component, and those props are presentation, not permission.

Two of them — `artists/[slug]` and `venues/[slug]` — additionally render an edit
affordance behind `(role === "master" || role === "organizer")`. That is still
presentation: it decides whether a link is drawn, not whether a route answers.

**This plan changes nothing but the source of two values, six times.** It is in
wave 2 in parallel with eight other conversions because its six files belong to
no other plan. State the triviality plainly in the commit — a reviewer who sees
`(public)` and "capability" in the same diff will otherwise look for a security
change that is not there.

Purpose: CAP-05 criterion 1. The requirement is about the SOURCE of identity,
not about the vocabulary a page uses afterwards.

Output: six converted files.
</objective>

<conversion_contract>
**Before**
```ts
import { headers } from "next/headers";
const headersList = await headers();
const role   = (headersList.get("x-user-role")   as UserRole)   || null;
const status = (headersList.get("x-user-status") as UserStatus) || null;
```
**After**
```ts
import { getAccessContext } from "@/lib/capabilities/server";
const { role, status } = await getAccessContext();
```

1. **Add no gate.** None of these six redirects, and none of them may start.
   Criterion 4 says every role reaches exactly the surfaces it reached before,
   and a new refusal path on a public page is exactly that kind of change.
2. **Keep `role` and `status` flowing to `<MobileNav>`.** It is a `"use client"`
   component and cannot import the DAL; Next.js's guidance is to resolve in a
   parent Server Component and pass props down. Converting the nav to consume
   capabilities is STAFF-03, **phase 34**, against four roles.
3. **No `try`/`catch` around the resolve.** A failure throws; Next's error
   boundary is the observable effect and the `[capabilities.resolve_failed]`
   line is the diagnosis. `catch` returning an empty set refuses a master
   exactly the way it refuses a pending member.
4. **Delete the `headers` import and any orphaned `UserRole`/`UserStatus`
   import.** `npm run build` will name them.
5. **The `as UserRole` cast disappears, and that is a real gain.**
   `headers().get()` returns `string | null` and the cast asserted a union the
   header could not guarantee. `getAccessContext()` returns `string | null`
   honestly. If the JSX now complains, widen the prop rather than re-adding a
   cast.
6. **On a public page, `getAccessContext()` costs one Supabase round trip that
   the page did not previously pay** — the header was already there. Accept it:
   D-13 accepted the same cost for the middleware, and CAP-04 (a grant takes
   effect on the next request) is what buys it. Do not attempt to avoid it by
   caching across requests: `cache()` is per-render by design, and a hand-rolled
   cache keyed by anything other than the React request store leaks across
   requests.
</conversion_contract>

   to**, in the commit. That is the gate satisfied concretely rather than
   asserted.
