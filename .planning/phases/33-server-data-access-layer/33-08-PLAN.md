Apply the conversion contract to all six. Each already fetches the event before
the ownership line, so `ownsOrIsMaster` costs **nothing** — it is a pure
function over data both operands of which are already in hand.

Two things that will change behaviour if done carelessly, both flagged:

**The polarity inversion is safe here, and here is why it is safe.** Today, a
master falls through the ownership `if` because the condition begins
`role === "organizer"`. After conversion a master returns `true` from
`ownsOrIsMaster` at step 1, before `createdBy` is even looked at. The truth
table for the three roles that exist today is identical. What changes is that a
master's verdict no longer depends on `event.created_by` having been read
successfully — which matters because these pages read the row through the cookie
client, so the `events` SELECT policy is in the path. Under the old form, if a
future policy stopped returning `created_by` to a master, the page would show
them a broken row; under the new one, the master case never touches it. That is
a strictly better failure mode, and it is the same shape `verifyEventOwnership`
already uses.

**A null identity must refuse.** The old form compared against
`headersList.get("x-user-id") || ""` — an empty string, which is unequal to
every real `created_by`. `getAccessContext().userId` is `string | null`, and a
naive transcription of `event.created_by !== userId` would compare `null !==
null` and **admit** on a row whose `created_by` is null. `ownsOrIsMaster` refuses
on both nulls explicitly (steps 2 and 3). **Do not re-inline the comparison for
"clarity" in any of these six files.** That is precisely the seven-chances-to-
get-it-wrong that this consolidation removes.

`[id]/guest-list/page.tsx`, `[id]/sales/page.tsx` and `[id]/review/page.tsx`
additionally read through `getServiceClient()`. Do **not** change which client
reads what — that is a behaviour change wearing a refactor's clothes. Record in
the commit, per file, that the service client is retained and that on that path
the code is the only boundary because there is no RLS behind a service-role
read (`access-gating.md`, gate *service role*; `meta-gates.md` requires the
statement in writing).
