# Plan 30-01: Membership Door Check-in

## Goal
Membership QR scan at the door records attendance for the selected party. Invalid codes show red flash with reason.

## Requirements
- MEMB-01: Membership QR scan → verify member → instant check-in for selected party
- MEMB-02: Record attendance in database for membership-based check-in (no ticket created — cash tracked via SumUp app)
- MEMB-03: Invalid/unknown membership code → red flash with "Member not found" message

## Context

### Current State
- Membership verify API at `/api/membership/verify` — GET only, looks up `profiles.membership_code`, returns member name but does NOT record attendance (has TODO)
- ScannerClient already detects membership QR (`code=RSN-` pattern) and calls verify API (lines 445-473)
- Shows green flash "Member" on valid, red flash "Member not found" on invalid
- `attendances` table exists: `(id, event_id, user_id, checked_in_at, checked_in_by)` with `UNIQUE(event_id, user_id)`
- `event_parties` table: `(id, event_id, type, title, ...)` — party → event FK
- Scanner operates at party level (selectedPartyId) — need to resolve event_id from party for attendance insert

### What's Missing
1. Membership verify API doesn't accept `partyId` or record attendance
2. ScannerClient doesn't send `partyId` with membership verify
3. No undo capability for membership check-ins
4. Membership scan records in history have `canUndo: false`
5. Bare `RSN-XXXX` codes (without URL) don't match any pattern in scanner branching

### Key Files
- `src/app/api/membership/verify/route.ts` — verify + record attendance
- `src/app/(admin)/admin/scanner/ScannerClient.tsx` — membership scan flow (lines 445-473)
- `src/app/api/tickets/checkin/undo/route.ts` — add membership undo
- `supabase/schema.sql` — attendances table reference

## Tasks

### Task 1: Upgrade Membership Verify API to POST + Record Attendance

**File:** `src/app/api/membership/verify/route.ts`

**Keep existing GET** for backward compatibility (membership card view uses it).

**Add POST handler:**
1. Accept `{ code: string, partyId: string }` in body
2. Require authenticated user (staff scanning)
3. Look up member by `membership_code` in `profiles` table
4. If not found: return `{ valid: false, status: "not_found" }`
5. If found: resolve `event_id` from `event_parties` where `id = partyId`
6. INSERT into `attendances` table: `(event_id, user_id, checked_in_at, checked_in_by)` with ON CONFLICT (event_id, user_id) DO NOTHING
7. Check if INSERT affected rows (use `.select()` after insert or check response):
   - If 0 rows affected (already exists): do a SELECT on `attendances` WHERE `event_id` AND `user_id` to get the existing `checked_in_at`. Return `{ valid: true, status: "already_checked_in", member_name, checked_in_at }`
   - If INSERT succeeded: return `{ valid: true, status: "checked_in", member_name, membership_code, attendance_id }` — **must include `attendance_id`** (the UUID from the new row) for undo support

**Use service client** (createServiceClient from `@/lib/supabase/service`) to bypass RLS for the insert.

### Task 2: Update Scanner Membership Flow

**File:** `src/app/(admin)/admin/scanner/ScannerClient.tsx`

**Add bare membership code pattern** at the top with existing patterns:
```typescript
const BARE_MEMBERSHIP_PATTERN = /^RSN-[A-Z0-9]{6,10}$/i;
```

**Update the branch condition** (line ~445) to also match bare codes:
```typescript
} else if (MEMBERSHIP_PATTERN.test(code) || BARE_MEMBERSHIP_PATTERN.test(code)) {
```
Remove the `UUID_PATTERN.test(code)` from this branch — bare UUIDs should not be assumed as membership codes.

**Extract membership code from QR:**
```typescript
let membershipCode: string;
if (MEMBERSHIP_PATTERN.test(code)) {
  // URL: extract code param
  const url = new URL(code);
  membershipCode = url.searchParams.get("code") || code;
} else {
  // Bare RSN-XXX code
  membershipCode = code;
}
```

**Change from GET to POST:**
```
POST /api/membership/verify
body: { code: membershipCode, partyId: selectedPartyId }
```

**Handle response statuses:**
- `status: "checked_in"` → green flash: "{member_name}" / "Member" → add scan record with `id: data.attendance_id`, `canUndo: true`
- `status: "already_checked_in"` → red flash: "Already checked in" / "{member_name} · Checked in at {time}" → add scan record with `canUndo: false`
- `status: "not_found"` → red flash: "Member not found" → add scan record with `canUndo: false`

**Important:** Use `data.attendance_id` (returned from Task 1) as `record.id` for undo support — NOT the user_id.

**After successful check-in:** call `fetchAttendance(searchQuery || undefined)` to refresh the attendee list.

### Task 3: Add Membership Undo Support

**File:** `src/app/api/tickets/checkin/undo/route.ts`

**Add membership undo:**
1. Accept `{ attendanceId: string }` as third option (alongside ticketId and guestListEntryId)
2. Delete the attendance record from the `attendances` table where `id = attendanceId`
3. Return `{ success: true }`

**File:** `src/app/(admin)/admin/scanner/ScannerClient.tsx`

**Update `handleUndoCheckIn`** — modify the body construction to handle all three types:
```typescript
const body: { ticketId?: string; guestListEntryId?: string; attendanceId?: string } =
  record.type === "guest"
    ? { guestListEntryId: record.id }
    : record.type === "membership"
      ? { attendanceId: record.id }
      : { ticketId: record.id };
```
