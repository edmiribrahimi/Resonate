line this phase is most likely to destroy by tidying.

`api/media/finalize`, and the nights half of `admin/events/actions.ts`. What it does not

alive **by accident** — `localStorage.removeItem` happens to sit inside the `.then`. A
single tidy of that promise chain deletes it, in silence, in a repository with no error
tracking.

  <action>
    Create `src/lib/failure/money-path.ts`. It exports three things and no more.

    **`SafeError`** — a type with optional, nullable `code` and `message` string fields and
    nothing else. Its docblock carries the reason, in this repository's own terms: on a
    CHECK or constraint violation PostgREST returns the whole rejected row in
    `error.details`, a `profiles` or `tickets` row carries `membership_code`, and a
    membership code is the door credential. Roughly twenty sites in this repository already
    pass a whole error object to `console.error`; this phase opens several files that would
    otherwise become the twenty-first. Cite
    `.planning/todos/pending/postgrest-details-leaks-the-row.md`. State that application
    branching stays on `code`.

    **`logMoneyPathFailure(scope, error)`** — takes a scope string and a `SafeError | null`,
    and writes one `console.error` line carrying the scope, `code=` and `message=`, with
    the literal `none` where a field is absent. Same shape as
    `admin/events/actions.ts:382-387`, generalised so more than one file can use it. It
    **cannot** accept a whole error: the parameter type is the guard, which is the point of
    the type existing rather than a convention existing.

    **`ReadResult<T, R extends string>`** — a discriminated result: an `ok: true` arm
    carrying `value: T`, and an `ok: false` arm carrying `reason: R`. This is the shape the
    guest custody read in plan 46-05 returns, and the shape any later read adopts when its
    empty value is also a legitimate answer.

    The module's head docblock is the load-bearing part, and it says four things:

    1. **The construction.** Constants first, the union built from `typeof` over those
       constants, then a `Record` over the union. Not a bare string union with a `switch`
       — the `Record` is what turns a missing sentence into an `npm run build` error. Use
       `as const satisfies Record<…>` where the values must stay literal (statuses); plain
       `Record<Union, string>` for sentences. Point at `outcome.ts:278-302` and
       `finalize/route.ts:236-254` as the two in-tree instances.
    2. **Where the union lives.** Each surface declares its **own** union and its **own**
       total `Record`, in its own file, because a category on a bar screen and a category
       in a cron report are not members of one vocabulary. What is shared is the
       construction and this log line — that is what "one shape" means here, and saying so
       is what stops a later reader from building a god-union.
    3. **Why a category never travels as a thrown message**, citing
       `src/lib/capabilities/server.ts:58-63`. A client that branches on message text works
       in `next dev` and stops working where it counts.
    4. **The third member is always the *could-not-answer* category, and it is never merged
       with *no*.** `DOOR_NIGHT_UNRESOLVED` is the template. `api/media/finalize` gives the
       same idea its own HTTP status with an explicit meaning: the question could not be
       answered, and this is not a refusal of you.

    No other export. No default export. No React import — this module is used from a Server
    Action, a Server Component, a route handler and a client component, so it must stay
    free of anything that pins it to one of those.
  </action>
