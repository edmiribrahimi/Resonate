<task type="auto">
  <name>Task 2: Real-time password strength validation (UIBR-08)</name>
  <files>src/app/(auth)/register/page.tsx</files>
  <action>
The registration form currently only enforces `minLength: 6`. Upgrade to enforce: minimum 8 characters, at least one uppercase letter, one number, one special character. Show real-time inline feedback as the user types.

Implementation:

1. Add a password validation helper function (inside the component file or above the component):
   ```typescript
   function validatePassword(password: string) {
     return {
       minLength: password.length >= 8,
       hasUppercase: /[A-Z]/.test(password),
       hasNumber: /[0-9]/.test(password),
       hasSpecial: /[!@#$%^&*()_+\-=\[\]{};':"\\|,.<>\/?]/.test(password),
     }
   }
   ```

2. In the component, compute validation state from the password state variable:
   ```typescript
   const rules = validatePassword(password)
   const isPasswordValid = Object.values(rules).every(Boolean)
   ```

3. Below the password input field, render real-time validation indicators (only show when password field has been interacted with / has content):
   - Each rule shows a small indicator (checkmark or cross) with text:
     - "8+ characters" -- green check when met, muted when not
     - "One uppercase letter" -- same
     - "One number" -- same
     - "One special character (!@#$...)" -- same
   - Style: small text (text-xs), arranged vertically or in a 2x2 grid below the input
   - Use text-green-500 (or similar accent) for met rules, text-muted for unmet
   - Show a simple checkmark character or bullet for met/unmet status

4. Disable the submit button when `!isPasswordValid`:
   - Add `disabled={!isPasswordValid || loading}` to the submit button
   - Style the disabled state: `opacity-50 cursor-not-allowed`

5. Update the password input:
   - Remove the old `minLength` attribute (now handled by the validation function)
   - Keep the `required` attribute
   - Optionally set `minLength={8}` as a fallback for HTML5 validation, but the primary validation is the JS function

6. If there's a server-side error check for password, update the error message to reference the new requirements.

Design decision (Claude's Discretion - password UX): Use real-time inline feedback (checkmarks per rule) rather than a strength meter or submit-time error. This is friendlier for users and more informative than a generic strength bar.

Do NOT add a "confirm password" field -- that was not requested and adds friction.
