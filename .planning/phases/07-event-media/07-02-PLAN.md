  <action>
Create three client components in `src/components/media/`:

**MediaGrid.tsx** -- Shared responsive thumbnail grid:
- Props: `items: { id: string; url: string; type: 'photo' | 'video'; uploaded_by?: string }[]`, `onItemClick?: (item) => void`, optional `actions?: (item) => ReactNode` (for delete buttons, moderation buttons)
- Responsive grid: `grid-cols-2 sm:grid-cols-3 gap-2`
- Photos: `<img>` with `object-cover` in `aspect-square` container (do NOT use next/image for storage URLs to avoid optimization issues with user-uploaded content -- or use `<Image>` with `unoptimized` prop)
- Videos: dark gradient background with centered play icon (triangle) overlay -- do NOT generate video thumbnails
- Each item is a button that calls `onItemClick`
- If `actions` render prop provided, show it overlaid on the item (top-right corner)
- "use client" directive

**Lightbox.tsx** -- Full-size viewer using native `<dialog>`:
- Props: `item: { url: string; type: 'photo' | 'video' } | null`, `onClose: () => void`
- Use `useRef<HTMLDialogElement>` and `useEffect` to call `showModal()` when item is set, `close()` when null
- Close button (X) in top-right corner with semi-transparent background
- Photos: `<img>` with `max-h-full max-w-full object-contain`
- Videos: `<video>` with `controls autoPlay` and same sizing
- Dialog styled: `fixed inset-0 bg-black/90 backdrop:bg-transparent` for full-screen dark overlay
- Handle `onClose` via the dialog's native `onClose` event (Escape key support built-in)
- Click on backdrop (the dialog element itself, not the content) also closes
- "use client" directive

**MediaUpload.tsx** -- Upload interface with drag-and-drop, preview, progress:
- Props: `eventId: string`, `onUploadComplete?: () => void`
- "use client" directive
- **File validation constants:** ALLOWED_PHOTO_TYPES = ['image/jpeg', 'image/png', 'image/webp'], ALLOWED_VIDEO_TYPES = ['video/mp4', 'video/quicktime'], MAX_PHOTO_SIZE = 10MB, MAX_VIDEO_SIZE = 100MB
- **State:** `files: { file: File; preview: string; type: 'photo' | 'video'; error?: string }[]`, `uploading: boolean`, `uploadProgress: Map<string, number>`
- **Drag-and-drop area:** Dashed border container with drop handler. Use `onDragOver`, `onDragEnter`, `onDragLeave`, `onDrop` events. Visual feedback on drag (border color change). Also include a hidden `<input type="file" multiple accept="image/jpeg,image/png,image/webp,video/mp4,video/quicktime">` triggered by clicking the drop area.
- **File selection handler:** For each file, validate type and size using the constants. Create preview URLs with `URL.createObjectURL()`. Add valid files to state. Show error message for rejected files (inline, next to the file name or in a toast).
- **Preview grid:** Show selected files before upload in a small grid. Each has a thumbnail (or video icon), file name, file size, and a remove button (X). Member can review and remove individual files.
- **Upload flow** (triggered by "Upload" button):
  1. Call `validateMediaUpload(eventId)` server action -- if fails, show error and abort
  2. For each file in parallel (or sequential for rate limiting):
     - Upload to Supabase Storage via browser client: `createClient().storage.from('event-media').upload(path, file)` where path = `${eventId}/${userId}/${Date.now()}-${index}.${ext}`
     - Track progress via upload callback or state updates
     - On success, call `registerMedia(eventId, storagePath, type, file.size)` server action
     - Update progress state per file
  3. On all complete, clear file list, call `onUploadComplete` callback
  4. Show success message: "Media uploaded! It will appear after organizer approval."
- **Error handling:** If upload fails for a file, show error next to that file but continue other uploads. Allow retry.
- Import `validateMediaUpload` and `registerMedia` from the co-located `actions.ts` (adjust import path as needed -- may need `@/app/(public)/events/[slug]/actions` or relative import if component is used only on this page).

NOTE: For the Supabase Storage upload, the browser client does not support `onUploadProgress` in the standard `.upload()` method. Use a simple approach: set progress to 0% at start, then 100% on complete. If the Supabase JS client version supports XMLHttpRequest-based progress, use it; otherwise, just show a loading spinner per file. Do not over-engineer progress tracking.
