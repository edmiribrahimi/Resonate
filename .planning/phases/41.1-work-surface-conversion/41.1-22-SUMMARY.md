### 2.5 The proof, and why it is not a diff grep

A diff filtered for the attribute forms shows what *moved*; it cannot show
what was *dropped*, because a dropped attribute produces a deletion that looks
exactly like a relocation. So each file's attributes were extracted as a
**sorted multiset over comment-stripped source** — line comments, block
comments including an unterminated one running to end of file, and JSX comment
wrappers all blanked first, because two plans in this phase have already caught
a false positive that a raw grep produced from prose.

Attributes captured: `type` · `name` · `min` · `max` · `step` · `maxLength` ·
`minLength` · `pattern` · `value` · `defaultValue` · `defaultChecked` ·
`checked` · `required` · `readOnly` · `disabled` · `inputMode`, in both the
`attr={…}` and the bare-boolean forms.

| File | multiset difference |
|---|---|
| `AddTierForm.tsx` | one `type="checkbox"` fewer, nothing else |
| `AddDiscountCodeForm.tsx` | two `type="checkbox"` fewer, nothing else |
| `TierCard.tsx` | two `type="button"` and one `type="checkbox"` fewer, nothing else |
| `DiscountCodeCard.tsx` | two `type="button"` and two `type="checkbox"` fewer, nothing else |

**Every one of the seven differences is accounted for and none is a loss.** The
checkbox primitive writes `type="checkbox"` itself (`src/components/ui/Checkbox.tsx:107`),
and the button primitive writes `type="button"` as its default before the caller's
spread (`src/components/ui/Button.tsx:236`) — so the literal left the call site
and arrived in the component. **Not one price, quantity, discount value, minimum,
step, required flag or length bound differs.** `type="submit"` is present in both
versions of both cards, unchanged: it is still written at the call site, because
the primitive's default would otherwise make Save inert.

### 2.6 The checkbox pair, which is behaviour written as an order

Four checkboxes on this surface are followed by a hidden field of the same name
carrying the opposite value. That pair **is** the flag: an unchecked box submits
nothing, so the reader takes the hidden value; a checked box submits first and
wins. The order survived every substitution and is now commented at each of the
four sites, because reversing two sibling elements would invert a flag without
changing a single attribute — the kind of edit a reviewer reads as tidying.

## 5. What changed that is not a substitution

Five judgements. Each is styling or structure; none is validation, and none is
on a money path.

**5.1 The money figure became a mark (D-41.1-13).** A tier's price, a discount's
value and a pending refund's amount all used to sit inside the recessed meta
row at the same size and ink as a sold count. Each is now set beside the thing
it belongs to, at the interface ink and the heavier weight. The number, its
formatting and its currency are byte-identical — what changed is where the eye
lands, and on a surface where an operator scans a column of tiers that is the
difference between reading the price and reading past it.

**5.2 The two-column field grids gained a phone rung.** They were two columns at
every width. The two date controls carried a minimum-width override, which is
the file's own record that the row did not fit. They are now one column below
tablet width and two above. This is not a rename of the retired first
breakpoint tier — there was none written here to rename; it is a two-column grid
acquiring the step it never had.

**5.3 The pressable card became the static card.** Both cards were built on the
press-scaling container. Nothing about either card is pressable — the controls
inside them are — so the press feedback was an affordance promising an action
the card does not have. `Card.tsx`'s docblock draws exactly that line.

**5.4 The tier form's identifiers are scoped per sub-event.** The component
mounts once per paid sub-event plus once for the event pass, and its identifiers
were fixed strings — so the moment a night had two paid sub-events, every
visible label bound to the *first* control of that name rather than to its own.
The sibling discount form already scoped its identifiers this way; this one now
matches. **No submitted name changed**: the server reads `name`, never `id`, and
the multiset in §2.5 shows every `name` unchanged.

**5.5 The pending-refund block lost its raw hue.** It was drawn in a raw warning
colour that no token owns. It is now the card primitive under a heading that
says *Pending Refund Requests*, and the block still renders only when there is
something in it. D-41.1-25 holds — the word is the channel — and D-41.1-29
measured the two semantic fills at 1.23 : 1, under WCAG 1.4.11's 3 : 1, so the
palette could not have carried it as an adjacent fill anyway.

## 7. The destructive controls whose hit area grew — named, per the requirement

Two, and the plan asks that they be said out loud rather than left to read as an
endorsement:

| Control | Before | After | Guard, before and after |
|---|---|---|---|
| **Delete** a tier | outline pill, roughly 28px tall | **secondary rung, 44px** | native confirmation naming the tier, plus the control renders only while nothing has sold — **both unchanged** |
| **Delete** a code | outline pill, roughly 28px tall | **secondary rung, 44px** | native confirmation naming the code, plus the control renders only while the code is unused — **both unchanged** |

**This is a mis-hit correction, not an invitation.** D-41.1-31 records that this
product's irreversible controls are, on average, already easier to reach than
its reversible ones, and it is explicit that a conversion commit is the worst
place in the project to add or remove a confirmation. So no confirmation was
added, none was removed, and neither control was promoted: both take the
**secondary** rung — which is the shape the refund control in this same closure
took when it converted in wave 7, where the destructive fill is reserved for the
control *inside* a confirmation and never for the one that opens it.

**The cost, stated rather than hidden:** Edit and Delete now differ by their
word and not by their colour. That is the same trade D-41.1-25 makes everywhere
else on this surface, and it is the one the converted sibling already made.

## 12. Carried forward — one finding, not fixed here

**The refusal region relays one sentence, and it did not write it.** Each of the
four components renders whatever the server action threw, in an announced alert
region. That is an improvement on the hand-drawn coloured box it replaces — the
region is now announced, and it is a token rather than a raw palette hue. It is
**not** one-cause-one-sentence in the sense §11 means, because the causes are
separated upstream in the action and this markup cannot separate what arrives as
one string.

Recorded rather than fixed: rewriting refusal copy is outside a conversion, and
§11 says *none introduced*. It matters because this project has **no error
tracking**, so a refusal a person cannot read is a refusal nobody ever reads —
and §8 rows 6a and 6b are written specifically to find out whether two different
causes currently arrive as two different sentences or as one.
