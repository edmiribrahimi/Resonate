## 2. The shim: before and after, and why the order was binding

**Before** — two elements around the children. The outer declared the clearance
at the tablet tier *and* applied it as leading padding; the inner re-declared the
same custom property as zero for its subtree, so a converted page rendering the
shell did not add a second column's width on top.

**After** — one element. It declares the clearance at the same tier and applies
nothing. Every page below applies it for itself through the shell, which reads
the same declared value. One declaration, twenty-three consumers.

The unused type import went with the inner element.

**The precondition, checked on the tree rather than inherited from a plan.** All
23 declarable pages import the shell. That is what made the removal safe, and it
is the check the ordering rule exists to force:

- stop the padding one commit early → a still-unconverted page sits under the
  navigation column, the exact failure the shim was written to prevent,
  reintroduced at the end;
- remove the inner element early → every converted page gets two columns' worth
  of leading clearance from the tablet tier up, squeezing content on a
  768-pixel screen.

Both edits are in commit `b4bc6a8`:

```

 src/app/(admin)/admin/(work)/layout.tsx | 129 ++++++++++++++----------------
 2 files changed, 134 insertions(+), 72 deletions(-)
```

**What may still never change:** the layout may not stop *declaring*. Check E
holds that the files declaring the clearance are exactly the files mounting the
responsive navigation form, and it fails in both directions. It still names the
two-file set after this commit.

**Untouched, deliberately:** the shell was not edited, which is what keeps the
closure gate's two frozen digests valid.

## 4. An empty list is a decision, and the gate now reads it

Deleting the table gate's last entry tripped a deliberate guard that refuses an
empty list, with its own sentence: *the emptiness should be a decision written
above the constant — not a list that quietly emptied itself while nobody was
reading.*

That decision is now written above the constant, dated, with the plan that took
it, and the guard reads it. An emptiness **without** one still refuses, and a
truthy placeholder does not satisfy it — all three fields are required.

**Why an empty list here does not become a number that lies.** This gate's first
check is a *tree-side* accounting, not a list-side one: it counts every table
element under the source tree and requires each to be the primitive, on the list,
or the declared exemption. With the list empty the arithmetic is 2 = 1 primitive
+ 0 remaining + 1 exempt, and an eighth hand-rolled table added tomorrow fails
that check as an unaccounted file. The migration closes without the gate losing
its teeth.

**Proved by mutation, with the mutation asserted applied before its result was
read.** The declaration was replaced with a null, the substitution was asserted
to have landed (the assertion printed 1, not 0), the gate refused with the
expected sentence, and the file was restored from a copy taken first. Restoration
confirmed by the same assertion returning 0 and the gate exiting 0.

## 5. The four re-assigned items

**1 — the lineup labels had no binding. RESOLVED.** It was a binding, not
behaviour. The lineup control now takes an optional identifier and applies it to
its text input; the two visible labels in the event form name it. The identifier
is scoped per sub-event, because that block renders once per night on the bill
and a fixed name would bind every visible label to the first control of that
name — the same defect plan 41.1-22 found and scoped in the tier form. The
second call site takes a bare name and needs no prefix: it renders only when
there are no sub-events, so it never coexists with the prefixed ones. **Nothing
about the search, the debounce, the keyboard handling, the creation path or the
option list moved.** The prop is optional, because a required one would have been
a breaking change dressed as an accessibility fix.

**2 — the cover preview's width cap. DECIDED: it stays dropped.** It was a
**container maximum**, not a typographic measure — no text reads across it — so
the declared-measure mechanism of D-41.1-27 does not apply, and inventing a width
to satisfy a grep would be moving a number without moving the work. Plan 41.1-18
had already reasoned this correctly and written it into the file; this plan
confirms it rather than reopening it. **The visible consequence stands and is a
human-pass row:** on a desktop the thumbnail is a wide short strip rather than a
card. It is reversible and changes no behaviour.

**3 — the wrong-surface reason string. CORRECTED, and it is the seventh.** The
gate's own header already recorded six and predicted where the seventh would be.
It is the comparison route, and the prediction held exactly: the sentence was
written from the **route segment** and not from the file that renders. It was
wrong twice — it named a *table* on a surface that renders none (the whole tree
holds two table elements, the primitive's and the exemption's), and it said *two
editions* where plan 41.1-14 measured up to **four series**. The superseded
sentence is kept beside its measurement. **Nothing reads these strings** — the
manifest check and check D compare the declared width and never the reason — so
no gate will catch the eighth. Only a person re-deriving it will.

**4 — the chart-colour blind spot. STAYS OPEN, and no colour was chosen.**
D-41.1-30 carries forward unchanged: **eight raw palette values across three
files**, three of them on a data row returned by a query function and therefore
invisible to every class-string gate. They are neither a format identification
colour nor a sunset stop, which is the halt test, and both pass it. Choosing them
is a question for the owner, and this plan did not answer it.

## 7. `npm run verify` does NOT exit 0 — and that is the finding, not a formality

Recorded as unmet. Two separate things, and only one is a finding.

**The refusal.** `verify:capabilities` **refuses** (exit 2) for want of Supabase
credentials. That is its honest state in a worktree: **nothing about the
capability model was measured**, so it is neither a pass nor a failure.
Credentials were deliberately not copied in. It is closed on the main checkout.

**The failure — DEF-41.1-24-01, logged in full to `deferred-items.md`.**
`verify:touch-targets` fails on **nine elements in five files**, and they are a
**gate defect, not a product defect**, by two mechanisms:

- at least four are **hidden inputs**, which render nothing and can never be a
  touch target — a category error, not a threshold set too tight;
- the rest take their height from a constant that **does** carry the
  unconditional minimum, and interpolate it into the class attribute; the gate
  reads lines and cannot see through a class built by concatenation.

**They are pre-existing and not this plan's.** All five files were last written
in waves 7 and 8. This plan's diff on the one file it opened adds a prop, a
destructured field and an attribute, and touches **no class string** — asserted
with a diff filtered to class-bearing lines, which printed nothing.

**Not fixed here, deliberately.** The gate's own failure text says to fix the
element and never to widen the gate — and the elements are already correct, so
there is nothing to fix on that side. Editing a gate at the close of a phase, on
a red this plan did not cause, is what the single-writer discipline exists to
prevent.

**Why it matters more than a normal deferral.** This is precisely the shape the
phase's own documents name and that this repository has already done once: **a
gate that reddens on correct code is a gate somebody switches off.** It is red at
the moment the phase would be declared closed.

`npm run build` exits 0. Its only warning is a Next.js workspace-root notice
caused by two lockfiles being visible from a worktree — not a malformed-rule
warning, and not from this change.
