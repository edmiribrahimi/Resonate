# Phase 41.1 Plan 01: The Shared Comment Stripper Summary

One comment stripper in `scripts/lib/comments.mjs`, proved by asserted mutation
against the eight shapes six review rounds found, and imported by all ten gates
that carried a private copy — with a measured before/after showing that not one
gate's verdict line moved.

## What Was Built

**`scripts/lib/comments.mjs`** — three exported names and nothing else:
`stripLeadingComments(text)`, `liveLinesFrom(rawLines)`, `liveLines(absPath)`.
Family B's span logic as the base, plus family D's block multi-line state, plus
the three fixes round 5 and the gap review named:

| Fix | What it does |
|---|---|
| **CR-01** | the multi-line branch resumes span-stripping **after** the closer instead of pushing an empty line, so live code on a terminating line stays visible |
| **CR-02** | the JSX closer is a run-time-assembled regular expression (block terminator · optional whitespace · closing brace), never the exact three-character token |
| **WR-04** | a **per-opener** `searchFrom`: 2 for the JSX opener so the degenerate single-line form still blanks whole, 2 for the block opener so its degenerate form is not read as already closed, 0 for the docblock continuation star |

The module never calls `process.exit`. It reports an unterminated comment through
`unterminated` / `unclosed`; refusing is the caller's decision and the caller
owns its exit code. `grep -c "process.exit" scripts/lib/comments.mjs` → `0`.

**`scripts/verify-comment-stripper.mjs`** — the harness, registered in
`verify-all.mjs` and `package.json` as `verify:comment-stripper`.

**Ten gates** now import the module. Zero private copies remain:
`grep -n "function isCommentLine" scripts/*.mjs` returns nothing.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 — Blocking] `package.json` gained the gate's script entry**

- **Found during:** Task 2.
- **Issue:** the plan's `files_modified` names `scripts/verify-all.mjs` but not
  `package.json`. The aggregate reads `package.json` as *"the single source of
  every command"* and **refuses (exit 2)** when its own `OFFLINE` list declares a
  gate `package.json` does not — `missingRequired` at `verify-all.mjs:304-315`.
  Registering the gate in one file without the other makes the aggregate refuse.
- **Fix:** `"verify:comment-stripper": "node scripts/verify-comment-stripper.mjs"`
  added in the same commit as the `OFFLINE` entry, which is what that file's own
  comment asks for (*"the entry was removed and this list moves with it in the
  same commit"*).
- **Commit:** `1365c21`.

**2. [Rule 3 — Blocking] the three per-line `isCommentLine` call sites**

- **Found during:** Task 3.
- **Issue:** the plan describes deleting `isCommentLine` and `liveLines`, but
  `verify-media-strip.mjs` (3 sites), `verify-sunset-gradient.mjs` (2 sites) and
  `verify-tokens.mjs` (1 site) asked the predicate **per line**, not through
  `liveLines`. The module exposes no per-line predicate, by design.
- **Fix:** each site now asks the live line whether it came back blank —
  `live[i] === ''` — which is the same question answered *with* the multi-line
  state family A never had. `verify-media-strip.mjs` and
  `verify-sunset-gradient.mjs` gained a cached `liveLines` for it.
- **Commit:** `69c8559`.

**3. [Rule 3 — Blocking] the glyph scan is exempted from the refusal, deliberately**

- **Found during:** Task 3.
- **Issue:** `verify-tokens.mjs`'s glyph check scans a **wider** set than `src/`
  — `.css`, `.json`, `.svg`, `.txt`, `.webmanifest`, including under `public/`.
  Refusing the whole TOKENS gate because an SVG or a manifest happens to contain
  a block opener would be a red on a correct tree, which is the failure mode
  `verify-media-strip.mjs:51-62` records.
- **Fix:** the glyph loop calls `liveLinesFrom` without the refusal, with the
  reason written above it. The flag only decides how a hit is **reported**; the
  hit itself is found on the raw line either way, so a mis-flag cannot hide one.
- **Commit:** `69c8559`.

**4. [Rule 1 — Bug] the docblock continuation star opens no multi-line state**

- **Found during:** Task 1.
- **Issue:** family B returned `unclosed` for a star-leading line with no closer,
  and its caller ignored it. Carrying that through naively would make the merged
  module enter a **block state** from a stray `*` line and blank forward to the
  next terminator anywhere in the file — a new **blindness** no incumbent had,
  in the dangerous direction.
- **Fix:** the continuation star blanks its own line and opens nothing
  (`opens: null` in `LEADING_COMMENT_OPENERS`), with the reason written beside
  the entry.
- **Commit:** `e28dd24`.

### Process deviation — recorded because it cost work and could cost data

**5. [Process] uncommitted Task 3 edits were destroyed by `git checkout HEAD --`**

To produce the per-gate before/after diff, the ten gates were checked out at the
base commit (`git checkout d76ca65 -- <ten>`), run, and then "restored" with
`git checkout HEAD -- <ten>`. **HEAD was the Task 2 commit, which did not contain
the Task 3 edits** — they were uncommitted working-tree changes. `git checkout
<ref> -- <paths>` rewrites index and working tree both, so the ten files were
reset to their unmodified state and the work was lost.

Nothing outside `scripts/` was touched and no committed history was harmed; the
two capture files lived in the session scratchpad and survived. The ten edits
were redone, and the reconstruction was then **asserted equivalent**: re-running
all ten produced a file byte-identical to the captured AFTER (`diff` exit 0). So
the before/after diff quoted above is a diff of the committed state, not of a
state that no longer exists.

**The rule this establishes, and it is the same shape as
`ai-engineering.md`'s *una rimozione si fa per chiave, mai per interfaccia*:**
never check a ref out over uncommitted work to produce a measurement. Commit
first and then check out the older ref (which is safe, because the work is
recoverable), or read the older version out of the object store with
`git show <ref>:<path>` into a location outside the tree. The failure direction
matters: a checkout over committed work is recoverable, a checkout over
uncommitted work is not.

**No `git stash`, no `git clean`, no `git reset --hard` outside the startup base
check was used at any point.**

## What a Green Here Does Not Mean

- **Eight shapes, not every shape.** These eight are the ones six review rounds
  found. A ninth exists until somebody measures that it does not.
- **The module, not the ten gates.** A gate that imported the module and then
  read the raw file anyway would pass this harness and measure nothing — which is
  why this plan greps for the private copies rather than trusting the green.
- **Not a tokeniser, on purpose** (D-41.1-07; `40-REVIEW.md` WR-07 records that a
  real comment parser written here was unsound). The stated error direction is
  inherited verbatim from family D: a line whose first characters are a block
  opener inside a string blanks **more** than it should. More, never less — so a
  gate can under-count, but cannot be handed a comment as if it were code.
