# Phase 41.1 Plan 25: Closing the touch-target red by amending the contract Summary

Nine correct elements were reddening G5; the gate had predicted one of the two
shapes verbatim and named the resolution in advance, so the resolution was taken
rather than invented — a dated contract edit in the spec's gate section plus two
matching declared entries in the script, no threshold moved and no element
touched.

## This is a repair, not a plan

There is no `41.1-25-PLAN.md`. Plan 41.1-24 finished with `npm run verify` red on
exactly one gate, and the failing gate's own source had written down, before it
ever ran, what to do when this happened. The owner authorised the edit on
**2026-08-14**. That authorisation covers the two classes below and nothing
else; it is not a licence to loosen a number, and none was loosened.

## What was red, and why every one of the nine was correct

**Class A — four non-rendering inputs**, in the two ticketing forms and the two
ticketing cards. An input declared as the hidden type **renders no box at all**:
it cannot be pressed, cannot take focus, is not in the tab order, and any height
written on it would apply to a box that does not exist. It is not a target that
is too small — it is not a target. This is the case the gate predicted in its own
`KNOWN_FUTURE_REDS`, in those words, and declined to pre-empt.

**Class B — five call sites whose declared minimum lives in a module constant**,
three in the autocomplete control and two in its tag-input sibling. The minimum
**is declared** — in the constant the class attribute interpolates. What cannot
read it is the parser, which reads class strings and has never been able to
resolve an interpolation; the gate already documents that residual three times
and already forgives it for the navigation entry, for the checkbox and for the
switch.

## The two mechanisms, and why they differ

They were chosen per class, because the two classes fail for different reasons
and collapsing them would have made both entries weaker.

**Class A is an EXCLUSION.** The other entries forgive an element whose minimum
the parser cannot *read*. This one is different in kind: the element is not
interactive. So it is handled where the existing badge entry is — outside the
measured set — one level down: that entry says a span is not interactive by its
**tag**, this one says an input is not interactive by its **attribute**. And it
is read **at the element's own tag**, not from a per-site list, because the four
sites are four instances of one shape and a list of four would go stale the
moment a fifth form is converted — the exact staleness the gate's other refusals
exist to catch.

**Class B is an EXEMPTION**, declared element by element in the shape the gate
already prescribes: file, tag, a fragment resolving to exactly one element, the
constant it rests on, and its reason. Five entries, each printed on every run
with how many times it was reached.

**The rejected alternative is recorded because somebody will propose it again:**
writing the minimum onto each of the five call sites would have cleared the red
without moving any work, and would have put a hard-coded value on five sites
whose entire purpose is one shared string — after which the next edit to that
string would silently disagree with five call sites. That is a worse tree than
the one that produced the red.

## The guards, so neither entry is a blanket

Class A opens one obvious abuse: writing the attribute on something that renders,
to clear a red. The abuse cannot actually work — an element with that attribute
renders nothing, so dressing a visible control in it deletes the control rather
than hiding its size — but the **attempt** leaves a fingerprint, and the gate now
refuses on it. An input declared hidden that *also* carries a height utility is a
contradiction: one of the two statements is false and the parser cannot say
which, so it exits 2 and reports that nothing was measured. That is the same call
the gate already makes for two conflicting plain heights.

Class B carries three, each pointing away from a green:

| Guard | What it catches | Verdict |
|---|---|---|
| fragment resolves to zero or several elements | stale, or naming an element nobody chose | refuse, exit 2 |
| the element does not interpolate the named constant | the entry's stated reason is false about its target | refuse, exit 2 |
| the constant no longer declares the minimum | the premise is dead and the entry forgives for nothing | **fail**, exit 1 |

The third is a failure and not a refusal on purpose: it mirrors the existing
per-file premise check, one level down to the constant. A dead premise is a
defect in the tree, not an inability to measure.

## Proven by mutation, in both directions

Five cycles. Every mutation was asserted **present** by `command grep -c` before
the gate was run and asserted **absent** after the revert; the tree ends
byte-identical, asserted by an empty `git status` on tracked files.

| # | Mutation | Asserted landed | Result |
|---|---|---|---|
| M1 | the minimum removed from a measured element in the densest converted file | yes, 1 occurrence | **exit 1**, naming the file, the line, the tag and the class string as written — verdict *absent* |
| M2 | a non-rendering input dressed with a height class | yes, 1 occurrence | **exit 2**, a REFUSAL naming the file and line and printing the element. Not forgiven, not measured |
| M3 | the shared constant shrunk below the minimum | yes, 1 occurrence | **exit 1**, two failures, and the resolution table printed *DOES NOT DECLARE IT* against both affected entries while the sibling file still read *declares the minimum* |
| M4 | one entry's fragment pointed at a string nothing matches | yes, 2 occurrences | **exit 2**, naming the stale entry and its fragment. Nothing measured, no tick printed |
| M5 | one entry's constant swapped for a real but unused one | yes, 1 occurrence | **exit 2**, naming the element and the constant it does not interpolate |

**M1 and M2 are the two that matter.** M1 is the half that proves the gate still
fires on a genuinely undeclared minimum — the amendment did not make it lenient
about anything it measured before. M2 is the half that proves the new entry is
not a door: the attribute this plan added cannot carry an element past the
measurement, because the one way to try it is a refusal.

**Counted and printed, not silent.** The report gained two categories and a
section: the exclusion applied **4×**, the exemption **5×**, and all five
declared call sites print with their file, line, tag, constant, reason and reach
count. A green states what it forgave.

## What this does not close

Nothing here taught the gate to read an interpolation, and nothing here measures
a rendered box. Five more elements are now forgiven on a stated reason rather
than measured. **H41-4, on a large touch screen, remains the only thing in this
repository that proves anything renders at 44px**, it is still owed, and no green
from this gate ticks it. The report says so on every run and this summary does
not say otherwise.
