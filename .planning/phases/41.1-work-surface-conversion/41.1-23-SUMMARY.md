### The four deletions, applied twice each

Both files carried the shape PATTERNS §2.1 names, and both carried it **twice** —
once in the branch that renders the form and once in the branch that refuses to,
when the catalogue read fails. Each of the four went in all four places:

1. the page root that declared its own minimum height and its own bottom
   clearance — replaced by the shell's outer element;
2. the gutter and the top rhythm on the header, and the repeated gutter on the
   inner section;
3. the header's own bottom padding, which becomes a margin inside the shell;
4. the hand-written top-level heading, which becomes `PageTitle`.

The width is written on all four calls and is `default`. §4's wide list is
closed and names neither route, and default is not a fallback — it is the answer
for every surface nobody had to argue about.

**A decision worth naming:** the refusal branch takes the *same* width as the
branch it replaces. A page that narrows when its data fails would tell a reader
that something structural changed, when what changed is that a query came back
empty.

## The three stop conditions

1. **`venue_reveal_sent` is monotone.** No line of either file reads it, writes
   it, or decides anything from it — before or after. What this route decides is
   whether the panel is *drawn*, and that decision is quoted above and is
   identical. Not drawing the panel was never the guard, and this conversion did
   not turn it into one: the reveal module re-asks its own key inside every
   export.
2. **A payment reaching `completed` corrects forward.** No status transition, no
   refund amount, no idempotency key and no webhook path is in either closure.
   Asserted by the grep above, which returns nothing.
3. **A series progressivo is already on a poster.** Neither route renumbers,
   re-sorts or re-derives one. Both hand a night's format, series and number to a
   component that was converted in wave 7, and the projection that reads them is
   in the untouched table above.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 2 — missing critical functionality] Both refusal regions were
announced to nobody.**

- **Found during:** Tasks 1 and 2.
- **Issue:** each route's catalogue-read failure rendered a coloured box with a
  sentence in it and no role. There is no error tracking in this project, so a
  refusal that is only *visible* is a refusal that reaches whoever happens to be
  looking at that part of the page. `meta-gates.md`'s zero-silent-failures rule
  asks for an effect a person actually receives.
- **Fix:** the region is now an alert region, matching the shape the converted
  form uses for its own refusal. The sentence itself is unchanged in both files —
  §11: *none introduced* — and each still names its own cause rather than
  borrowing a generic one.
- **Files:** both.
- **Commits:** `f76926d`, `b93e55f`.

### Adopted rather than deviated

Four sites carried a raw palette and had to land somewhere; each landed on the
vocabulary an already-converted neighbour uses, not on a new one.

| Site | Before | After |
|---|---|---|
| the two refusal boxes | a raw red family, three utilities | the semantic critical ink, at the same shape the converted form's own refusal uses |
| the non-holder sentence beside the reveal | a hand-written card edge and fill | the card primitive |
| the reveal section's heading | a hand-written large bold heading | the §7.3 section heading |
| three navigation affordances | two of them dressed as controls | chips (D-41.1-26) |

**D-41.1-25 held:** no outcome tone was introduced anywhere. The critical ink is
on a *refusal*, which is the one place §11 allows it, and it is ink — not a fill
adjacent to another fill, which is what D-41.1-29's 1.23 : 1 forbids.

**D-41.1-30 held:** nothing here invents a colour for a series. The reveal
section names nights by their title, as it did.

**D-41.1-31 — one hit area grew, and it is named.** The back link on each route
went from a line of text to a 44px target. It is *navigation*, reversible in one
press, and it goes to the list the reader came from — so the decision does not
bite. The three sites whose reach did **not** grow are the ones that matter: the
reveal panel's own control is inside a file this plan did not open, and the two
refusal branches offer only a way back.

**D-41.1-27 — the cover preview's width cap.** Plan 41.1-18 recorded that the
form's cover preview lost its cap because it was a container *maximum*, not a
typographic *measure*, so the declared form for a measure did not apply. **That
loss is inside `EventForm.tsx`, which is not one of this plan's two files.** It
is re-assigned, not resolved here: neither route file carried a width cap of any
kind, before or after.
