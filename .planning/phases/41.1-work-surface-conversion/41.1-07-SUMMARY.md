## The two findings owed to the owner

### 1. `Chip` cannot carry a dynamic address, and neither can the ladder be a `next/link`

**Measured, not argued.** Written as the plan specifies —
`<Chip href={`/admin/events/${event.id}/edit`}>Edit</Chip>` — and typechecked:

```
src/components/events/EventList.tsx(192,19): error TS2322:
  Type '`/admin/events/${string}/edit`' is not assignable to type 'Route | undefined'.
```

The cause is the one `EventList.tsx`'s own docblock recorded in plan 34-01, from
the other side: `Chip`'s prop is the bare route type, which is that type **at its
default parameter**, and at the default parameter the dynamic arm of the route
implementation collapses. `Link` does not have the problem because **`Link` is
generic** and infers the parameter from the template.

Three ways out existed. **Two were refused:**

- **casting the href** — forbidden by this file's own docblock, and rightly: the
  cast is what would make the annotation compile, and it switches off the only
  check that makes a stale address a build error instead of a 404 found by
  whoever clicks it;
- **widening `Chip` to be generic** — correct in kind, and **not this plan's to
  make**. `Chip.tsx` is spine, outside this plan's `files_modified`, and
  D-41.1-15's partition rule says a shared component two plans would both touch
  is either converted earlier as spine or assigned to exactly one plan. Nobody
  assigned it. Editing it from one of five parallel worktrees is the shape that
  rule exists to stop.

**The third was taken**, and it is `41.1-PATTERNS.md` §2.5's own *"best single
call site to copy"* — a `<Link>` carrying the composed shape with the focus
expression **imported**, never re-spelled. To keep the string from being written
six times it is **one `<Link>` mapped over a literal union of the six segments**,
so the class string is written once and written literally inside the attribute
the gate reads.

**The build-time check survives, and that is proved by mutation rather than
claimed.** One segment was changed to a near-miss, the mutation was asserted
applied (`grep -c 'guest-lst'` → 1) *before* its result was read, and the
compiler refused, naming the offender:

```
src/components/events/EventList.tsx(272,17): error TS2322: Type
  '… | `/admin/events/${string}/guest-lst`' is not assignable to type
  'UrlObject | RouteImpl<…>'.
  Type '`/admin/events/${string}/guest-lst`' is not assignable …
```

The revert was asserted too (`guest-lst` → 0, `guest-list` → 1) and `npx tsc
--noEmit` returned to exit 0. The working tree at the time held only the
intended edit.

**The same gap, from the other end, on the Create Event control.** That address
is static, so the type is not the obstacle there — the *element* is. The button
ladder's `href` branch renders a **plain anchor**, which in the App Router is a
full document load. Converting the primary action of a work surface onto it
would have converted the appearance and quietly removed client-side navigation
and prefetching, which is a behaviour change a visual conversion may not make.
So that control is also a `<Link>` with a composed string.

> **The question owed, in one sentence:** *should `Chip` become generic over its
> route the way `Link` is, and should the ladder gain a rung that renders a
> `next/link` rather than an anchor — so that an internal address can be a chip
> or a button without a call site re-spelling the string?*
>
> Three call sites in this plan alone are composed rather than composed-from-a-
> primitive because the answer is currently no. It is a **primitive API
> decision**, it touches a file every converted surface imports, and it is
> therefore an owner's or the reconciliation plan's, not an executor's.

## Deviations from plan

### 1. `[Rule 3 — the plan's prescription could not be executed]` The six controls are Links, not Chips

Full account under **finding 1** above, with the compiler's exact words and the
mutation proof. In short: `Chip` rejects a dynamic address by type, the two ways
to make it accept one were refused for stated reasons — one forbidden by the
file's own docblock, one outside this plan's authorized file set — and the third
is the pattern map's own named alternative. **Every measurable property the plan
asked for is met**: the floor, no shrink, the wrap, the imported focus
expression, zero raw palette, zero legacy tokens. What is not met is the *form*,
and the form is now a question owed rather than a silent divergence.

### 2. `[Rule 3 — the criterion's arithmetic was not the gate's]` `REMAINING = 13`, not 14

Full account above. The list is untouched at 14 declared entries, which is what
the criterion protects; the printed count is a live measurement and fell because
the tree changed.

### 3. `[Rule 2 — missing critical property]` The events refusal branch gained the shell

The plan's four deletions are written for the success branch. `events/page.tsx`
has **two** branches, and the error one carried its own page root, its own
gutters and its own hand-written heading. Converting only the branch a person
sees when things work would have left a surface that **changes width at the
moment it fails** — and the heading would move under the eye of someone reading
a failure. Both branches now render `PageShell width="default"`.

### 4. `[behaviour, supplied by the primitive and stated rather than buried]` Escape now closes the venue edit modal

The overlay this replaces handled **none** of Escape, the focus trap or
background inertness; `showModal()` supplies all three by specification, which
is the whole argument for the conversion and is T-41.1-24's mitigation. The one
visible consequence: Escape closes the dialog, where before it did nothing. A
save already in flight still completes — both controls are disabled while it
runs and the reload on success is unchanged — and the close route resets the
refusal so a stale sentence cannot be on screen the next time it opens.

### 5. `[DEF-41-04, a loss and not a tidy]` The venue bio lost its reading measure

The same casualty `(work)/formats/page.tsx` already records: a converted page
writes no container maximum, the gate reads that literally, and a typographic
*measure* on a paragraph is the same string to it as a container *maximum* on a
page root. Recorded in the file, and it is row 3 of the observation table above,
because whether the loss is acceptable is something a person has to look at.
