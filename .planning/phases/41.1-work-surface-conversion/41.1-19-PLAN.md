## Written before the diff

**Classification: Structured.** These five draw a form; none of them moves money
and none of them touches the reveal. But two of them **create records** — a venue
and an artist — and one of those records is a venue, which is the object the
secrecy guard is about.

**Cross-domain impact:**
- *Venue secrecy.* The venue creation modal writes a venue. It does **not** set a
  secrecy flag — that is the event form's field, converted by plan 41.1-18 — and
  this plan adds no such field, no address preview and no map. If a conversion
  would surface an address anywhere it is not surfaced today, that is a **halt**.
- *Brand and production.* The artist creation modal writes a name that will be
  read off a poster. `brand-visual-system.md`'s gate on artist spelling is a
  production rule, not a code rule, and this plan neither enforces nor relaxes it;
  it changes no field, no validation and no placeholder text.
- *Access and gating.* Both modals are drawn for roles whose write may be refused.
  Every refusal path stays reachable and keeps its own sentence.

## The three stop conditions, verbatim

1. **`venue_reveal_sent` is monotone.** Work may only make the reveal harder to
   trigger, never easier. Nothing in these five reaches the reveal; asserted by
   grep, not assumed.
2. **A payment reaching `completed` corrects forward.** No status transition,
   refund amount, idempotency key or webhook path is anywhere in this file set.
3. **A series progressivo is already on a poster.** No conversion renumbers,
   re-sorts or re-derives one.
