## 4. The four findings and two decisions wave 3 handed forward

### 4.1 `Chip` is generic over its route — D-41.1-26, implemented

`href: Route` was that type **at its default parameter**, where the dynamic arm
of Next's route implementation collapses to `never`. Plan 41.1-07 measured the
consequence with the compiler and hand-composed six links rather than cast (its
own docblock forbids the cast, and rightly: the cast switches off the only check
that turns a stale address into a build error) or generify spine from one of five
parallel worktrees (D-41.1-15).

Now `href: Route<T>` on a `Chip<T extends string>`, which is `next/link`'s own
`LinkProps<RouteInferType>` shape rather than a new idea. `ChipProps` keeps a
default parameter, so the three existing call sites are untouched.

**Proved by compiling, then by mutating.** A temporary type-only probe was
created under `src/`, imported by nothing:

```
npx tsc --noEmit            → exit 0
   <Chip href={`/admin/events/${id}/edit`}>          compiles
   <Chip href={`/admin/events/${id}/guest-list`}>    compiles
   <Chip href="/admin/events">                       compiles
   <Chip onClick={…}>                                compiles
```

Then the segment was mutated to a near-miss, **the mutation asserted applied
before its result was read** (`grep -c "guest-lst"` → 1):

```
src/components/ui/__chip-route-probe.tsx(11,13): error TS2322:
  Type '`/admin/events/${string}/guest-lst`' is not assignable to type
  'Route<`/admin/events/${string}/guest-lst`> | undefined'.
```

**The dead-address check survives the generification**, which is the property the
cast would have destroyed. The probe was then deleted and its absence asserted;
`git status --porcelain` showed only `src/components/ui/Chip.tsx`.

**This change is type-only. No rendered output differs by a byte, so no converted
surface needs re-observing** — which is precisely why it was safe here and was not
safe in a five-worktree wave.

### 4.2 `Button` with `href` — NAMED, refused, and the refusal recorded

D-41.1-26 names this as a standing constraint and explicitly does **not**
authorise the change. It was not made. `Button.tsx` was not opened at all — not
even for a comment — because the instruction was unambiguous and a spine file
opened "just for a docblock" is how a scope grows.

The constraint is written at the foot of `Chip.tsx`, which is the file a person
is reading when they are choosing between the two: **a converted surface that
needs internal navigation uses `Chip` or `Link`, never `Button href`.** The
measurement travels with it — the `href` branch renders a bare anchor with a
`string` href, so an internal address gets neither client-side navigation nor
prefetching nor a build-time existence check, all silently. It is not a defect
phase 41 introduced; it is a trap for every conversion still to come, and
changing it is a **runtime** change to spine that does not belong in a
reconciliation.

*(Written as a comment rather than an exported constant: a symbol nobody imports
is the orphan shape D-41-04 exists to prevent, and a rule does not become more
binding by being given a runtime value nobody reads.)*

### 4.6 The typographic measure gets a declared form — D-41.1-27

**Check D was not narrowed, and refusing to narrow it is the whole content of the
decision.** Narrowing the matcher so it stops flagging a width on a paragraph
would make the gate find *less*, and the thing it would stop finding is a genuine
container maximum written on an inner element — a page taking the width back one
element down. That is the silent direction.

Instead a measure is now **stated**: `TYPOGRAPHIC_MEASURES`, shape `[pageFile,
maximum, fragment, reason]`, the same construction as
`verify-touch-targets.mjs`'s exemption 2a, with the fragment an attribute rather
than a line number because a line drifts and a stale entry reads exactly like a
live one. Three refusals (exit 2, not failure): an entry naming an undeclared
page, an entry matching zero widths, an entry matching two or more.

**Proved by mutation, four directions, each mutation asserted applied before its
result was read**, on a disposable copy under the session scratchpad:

| # | Mutation | Assertion it landed | Result |
|---|---|---|---|
| A | a width written on a converted page, with no entry | `grep -c 'data-measure="venue-bio"'` → 1 | **exit 1** — `✗ D 1 maximum(s) written on a converted page itself`, `CONVERSION_FAIL` |
| B | the same width, with a matching entry | `grep -c "venue-bio"` in the gate → 1 | **exit 0** — `typographic measures declared : 1, applied 1 time(s)`, printed as forgiven with its reason |
| C | the entry left, the width removed | the attribute count → 0, the entry → 1 | **exit 2** — `FATAL … matches NOTHING: stale` |
| D | the entry pointed at an undeclared page | `grep -c "(work)/finance/page.tsx',"` → 1 | **exit 2** — `FATAL … no CONVERTED surface declares this page file` |

Direction A is the load-bearing one: the width in that mutation sat on an

anyway. The matcher finds no less than it did.

**The list is empty today, and that is the measured state rather than an unfilled

would not be on a `REMAINING` list; `ORPHANS_DECLARED` in the same file is the
precedent for the shape. It is written **before the first red run**, which is
D-41-16's rule and the reason the mechanism is trustworthy: an exemption
discovered on a red run is an exemption nobody trusts, and the gate is what gets
edited next.

#### The design that was considered and NOT taken — recorded, because it is arguable

A **two-key** design was weighed: the source line must carry an explicit
declaration marker **and** the gate must carry the entry, so neither side can
forgive alone. It reads closer to D-41.1-27's phrase *"the measure gains a
declared form"*, and it would make a page unable to be forgiven for a width it
did not mark.

It was refused on three grounds, and the third is the decisive one:

1. the one-key form is **this repository's own established shape** for *forgive
   exactly this element, with the reason on the line* — exemption 2a, which this
   plan also extended in §1.4, so the two edits are one idea rather than two;
2. a source-side marker means **editing converted product files** to add
   attributes, in a reconciliation wave whose whole justification is that it
   changes no rendered output;
3. **there is no live site to mark.** A second key that no real entry exercises
   is a mechanism nobody has run, and this plan would have been shipping it on
   the strength of a mutation alone.

If the measure returns to a paragraph in a later plan and the one-key form turns
out to be too loose, the second key is an additive change to the same list. It is
recorded here so that would be a decision rather than a discovery.

**What this does NOT do:** it does not decide whether the measure comes back to
the format catalogue's paragraph or the venue bio. `DEF-41-04` stays open on that
question. What changed is that answering it is now **an entry** rather than an
argument with a gate — and that closes it on a schedule instead of on goodwill,
because nothing about a paragraph that got wider protests on its own.
