## 1. The column declaration, verbatim

Every column names a slot, and revenue's is `mark`.

```tsx
const columns: DataColumn<DrinkSalesItem>[] = [
  {
    key: "name",
    header: "Name",
    card: "title",
    cell: (d) => d.drinkName,
  },
  {
    key: "revenue",
    header: "Revenue",
    card: "mark",
    figure: true,
    align: "end",
    // The mark slot is a bare span: emphasis and the data face are the cell's
    // own, in both branches, so the money figure reads as money on the card too.
    cell: (d) => (
      <span className="font-mono text-sm font-semibold text-ink">
        {eur(d.revenue)}
      </span>
    ),
  },
  {
    key: "quantity",
    header: "Qty",
    card: "meta",
    figure: true,
    align: "end",
    cell: (d) => d.quantity,
  },
  {
    key: "redeemed",
    header: "Redeemed",
    card: "meta",
    figure: true,
    align: "end",
    cell: (d) => <span className="text-sem-done">{d.redeemed}</span>,
  },
  {
    key: "refunded",
    header: "Refunded",
    card: "meta",
    figure: true,
    align: "end",
    cell: (d) => <span className="text-sem-crit">{d.refunded}</span>,
  },
];
```

**Slot assignment, as settled by the plan and as shipped:**

| Column | Slot | Note |
|---|---|---|
| Name | `title` | |
| **Revenue** | **`mark`** | D-41.1-13 — the figure that decides money |
| Qty | `meta`, figure | |
| Redeemed | `meta`, figure | the completion semantic |
| Refunded | `meta`, figure | the critical semantic |

No column takes `none`. Both hand-written branches were deleted whole; the
file is 112 lines of which the declaration and one call are the rendering, and
the rest is the docblock.

**Why the mark cell carries its own classes.** The primitive renders a mark
inside a bare `<span>` (`DataTable.tsx:430-432`) and gives it **position, not
weight** — opposite the title, at the top of the card. A money figure that
inherited nothing there would land at the card's ambient size. So the renderer
supplies the emphasis and the data face itself, and it does so in **one**
renderer serving both branches, which is the property the primitive exists for.

**Re-stating the data face on a descendant is safe, and it is measured rather
than assumed.** `globals.css:441-449` records the two facts: an equivalent
numeric utility on a descendant *"merely re-states the value"*, and only the
ordinal and slashed-zero utilities rebuild the shorthand and drop the inherited
alignment. Neither appears here.

**The four raw palette hits are deleted, not recoloured.** The green-family
utility on the redeemed figure and the red-family one on the refunded figure
appeared **twice each** — once per hand-written branch — and both are colours
this system does not have. `globals.css:169-173` says so in capitals: the
semantic set **contains no green**, and adding one is adding a colour to the
brand, which is the owner's. So the completed count takes `--sem-done` and the
refunded count `--sem-crit`, read off `41-UI-SPEC.md` §5 rather than matched by
eye to the nearest hue.

**And colour was never the only channel (§10).** Above the primitive's
breakpoint each figure sits under its own header cell; below it the `meta` slot
prints `Redeemed:` and `Refunded:` before the value. Confirmed on the primitive:
`DataTable.tsx:447-458` renders the label with the value, and `labelOf()` falls
back to the header, which is a plain string for all five columns. **With the two
semantics closer in hue than the green/red pair they replace, that label is now
the primary distinction and not a redundancy** — which is why it is asserted
here rather than left to have survived.

## 5. Questions owed to the owner

Three, and none of them is answered in a call site. Each is here because the
contract does not contain the rule and a conversion is not where a design system
should acquire one.

### 5.1 The accent has no clause for a chart series

`41-UI-SPEC.md` §5.1 reserves `--accent` for four things — the primary button
fill, the active navigation entry, a link inside prose, and the lineup pills on
an event card — and names five it is never for: a format marker, a chip swatch,
a chip border, a state signal, and the focus ring. **A single-series bar chart is
on neither list.**

Two charts on this surface fill their bars with it today. The choices were:

1. leave it and report — no visual change, the gap stated;
2. replace it — which would put a chart-series colour into this system by the
   act of writing one, with no document behind it.

**Chosen: 1.** The precedent is the manifest's own refusal to make a convenient
claim (`conversion-manifest.mjs:206-214`), and the cost of the alternative is
concrete: the next chart to convert would copy whatever this file picked, and by
the fourth one it would be the rule.

**What is owed:** either a fifth clause on §5.1's reserved list naming a chart
series, or a replacement value. Two files carry it today; the other three chart
surfaces in this phase will meet the same question.

### 5.2 A categorical chart palette exists, and it lives outside every list

`src/lib/analytics/event-queries.ts:352-357` builds a four-step palette for the
purchase funnel: one token reference and **three literal hexes**. It is the only
categorical colour vocabulary in the product and no document declares it.

**It was not edited**, for two independent reasons and either would have been
enough:

- **The file is not on the authorized list.** D-41.1-19's list grows *by owner
  decision or not at all*, and its sixth entry is the precedent — measured,
  the measurement right, the inclusion still refused until the owner decided.
- **Deciding a four-colour categorical scale is not a conversion.** It is a brand
  decision with an accessibility argument attached, and it belongs to whoever
  owns the palette.

**Measured, so the owner does not have to:** the file carries **zero** class
attributes, so no class-string walker sees anything in it — the three hexes are
invisible to every gate in `scripts/`. None of the three is a format
identification value and none is a sunset stop.

**A second site exists and is not this plan's:** `EventComparisonChart.tsx:16`
carries the first of the same three hexes, on a surface another plan owns. It is
reported here and untouched.

### 5.3 A rate has no graded vocabulary

The attendance meter used to fill in three steps — green at or above 70%, amber
at or above 40%, recessed below. All three legs fail:

- **there is no green** (`globals.css:169-173`);
- **amber cannot be a bare fill** — the warning semantic holds SunSet's
  identification value, so an amber mark cannot tell *caution* from *this is a
  SunSet night* by hue, which is why anything amber carries text
  (`globals.css:161-163`), and a bar carries none;
- **the thresholds are written nowhere.** No document in this project says what
  a good attendance rate is. A meter grading against undeclared numbers in
  colours the system does not have asserts a judgement twice.

**Shipped:** one fill, reporting a proportion. The grade, if there is one, is
read off the percentage directly above it — which was always the primary channel,
since §10 never allowed colour to be the only one.

**What is owed:** whether a rate wants a graded vocabulary at all, and if so what
it is made of. Until then the number carries it.

## 6. Deviations from plan

All within Rules 1–3; none needed permission. Each is a colour or a type step the
contract already decides, met while converting a file the plan named.

**1. [Rule 2 — missing critical] The page carried a fifth raw palette hit the
plan did not count.**
- **Found during:** task 2, reading `RevenueCard.tsx` in full.
- **Issue:** the discount line was drawn in a purple-family utility. The plan
  counted four raw palette hits on this surface, all in the table.
- **Fix:** the hue is deleted and the line takes the surrounding recessed ink. A
  discount is not an outcome and not a state, and the semantic set has nothing
  meaning *discounted* — inventing one at a call site is §5.1's failure mode with
  a different noun. The channels that carry it are the word `Discounts`, the
  count in brackets and the minus sign, all of which were already there.
- **Commit:** `85d62a4`

**2. [Rule 2 — missing critical] Two more raw palette hits on the token
lifecycle meter, and one on the attendance meter.**
- **Found during:** task 2. `TokenLifecycleCard` filled its stacked bar and its
  three legend swatches in green/red/recessed; `AttendanceCard` graded its bar in
  green/amber/recessed through a helper.
- **Fix:** the lifecycle bar's three segments **are** three states, so they take
  the completion semantic, the critical semantic and the tertiary ink — a
  substitution the spec decides. The attendance grade has no such mapping and is
  removed rather than approximated (§5.3 above). The legend words are untouched,
  so §10 holds in both.
- **Commit:** `85d62a4`

**3. [Rule 1 — bug] Type steps this system does not have, on five figures.**
- **Found during:** task 2.
- **Issue:** weight 700 and the 18px step appeared on the surface's figures. §7's
  scale has **two weights, 400 and 600, and nothing else**, and its four sizes do
  not include 18px.
- **Fix:** weight 600 and the 16px step. The 30px figures keep their size and
  lose their weight, which is the same change §7.1 describes for the 34 headings
  that already shared that string.
- **Commit:** `85d62a4`

**4. [Rule 2 — missing critical] Recessed ink at partial opacity on four empty
states.**
- **Found during:** task 2. The three charts and the table each rendered their
  empty message in the tertiary ink at 60% alpha.
- **Issue:** the tertiary ink clears AA on the card surface at full strength; at
  60% it does not. An empty state a person cannot read is the silent-failure
  shape with a neutral face.
- **Fix:** full strength. The table's empty state now comes from the primitive's
  own contract, which never had the alpha.
- **Commit:** `422ea8e`, `85d62a4`

**5. [Rule 2 — missing critical] A dashboard figure with no unit.**
- **Found during:** task 2, converting the peak-hour pills.
- **Issue:** the count rendered as a bare number inside an accent-filled pill,
  which reads as a rank as easily as a total. `comms-analytics.md`'s *gate metrica
  onesta* asks a figure on a dashboard to carry its unit.
- **Fix:** the unit is written. Measured at the source rather than guessed —
  `event-queries.ts:300-307` counts ticket and drink-order timestamps together,
  so the unit is a purchase.
- **Commit:** `85d62a4`

**6. [Rule 3 — blocking] The back link was not a target.**
- **Found during:** task 2. It was a bare inline anchor with no declared minimum
  and no focus expression.
- **Fix:** the shape the two converted work pages already use — the 44px floor
  declared unprefixed, and `FOCUS_RING` **imported**, never re-spelled. D-41.1-26
  is satisfied by construction: this is a `Link`, not a button carrying an href.
- **Commit:** `85d62a4`

**Not a deviation, recorded so it is not read as one:** the revenue card's accent
tint and accent border are gone, and the panel is now the same card as the
others. §5.1 does not reserve the accent for a card ground. The hierarchy it
carried survives in a vocabulary the contract owns — the panel is still first,
still full width where the two below it share a row, and still the only one whose
figure is set at the display size.
