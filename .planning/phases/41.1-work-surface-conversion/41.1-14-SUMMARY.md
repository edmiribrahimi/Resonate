## 3. The three chart colour sources — read, not scanned

This is the first time this tree has converted a chart, and the plan's rule 7 is
the reason it took reading: **a colour set through a rendering prop is invisible
to every gate in `scripts/`**, all of which count class strings. The three files
were opened and every colour-bearing value was read out.

| Chart | What carries a colour | Source | Verdict |
|---|---|---|---|
| `EventComparisonChart.tsx` | the series fills, four of them | **one design token** read through the token layer, plus **three raw values** named nowhere else in the repository — an indigo, an emerald and an amber from a palette this product does not use | **not** a format identity colour, **not** the sunset gradient |
| `EventComparisonChart.tsx` | axis ticks, tooltip ground, tooltip edge, tooltip label | **design tokens**, four of them; three were the retired aliases and now name the tokens those aliases already resolve to | clean |
| `MemberGrowthChart.tsx` | the two stacked bands | **one design token** at 60% fill, plus **one raw three-digit grey** at 30% | **not** a format identity colour, **not** the sunset gradient |
| `MemberGrowthChart.tsx` | axis ticks and the same four tooltip properties | **design tokens**; the same three aliases moved | clean |

**Rule 7's halt does not fire**, and the two questions that would have fired it
were both asked explicitly:

- *Is any value a format's identity colour?* No. A format identification colour
  is data on a catalogue row and never a CSS token (§5, inherited from Phase 40),
  and none of the six values is one a format carries.
- *Is any value the sunset gradient?* No. That signature is four stops at a
  declared angle, it exists once in the token file, and `verify-sunset-gradient.mjs`
  asserts it exists nowhere else — it exits 0 on this tree after these edits.
  Nothing in either chart is a gradient at all.

### The gap that is reported instead of filled — a question owed to the owner

**This design system has no colour vocabulary for a chart series.** §5.1 assigns
four grounds, four inks, three line weights, one accent with a **closed
reserved-for list**, and four semantics with literal values on both sides. A
chart series is none of those things:

- it is **not a format**, so DS-02's format colours are out — those appear only
  where a format is identified, and a bar is not a format;
- it is **not a state**, so the four semantics are out — and D-41.1-25 is the
  standing decision that they are not to be recruited for grading anything;
- the accent's reserved-for list names four things — the primary button fill,
  the active navigation entry, a link inside prose, the lineup pills on an event
  card — and a chart band is not among them, **so the one token already in use
  in both charts is itself outside its own list**.

Choosing four replacements inside a component would be this design system
acquiring a rule nobody decided, which is precisely the failure §3.1 describes
about a spacing step and §7.3 about a heading weight. **Nothing was picked.** The
finding is written into both chart files at the values themselves — where the
next person to touch them will meet it — and it is raised here as a decision the
owner owns:

> **Open, for the owner: what colours may a chart series take?** Four bars on
> the comparison surface and two bands on the growth surface need a vocabulary
> that is neither a format's identity nor a semantic state. Until one exists, the
> six values in these two files are what they were, one of them is a token used
> outside its own reserved-for list, and five of them are raw. No gate can see
> any of it.

## 7. Findings raised rather than acted on

### 7.1 Growth is drawn without the number that gives it meaning — for the owner

`community-membership.md`'s gate is explicit: growth is looked at **next to how
many seats a night actually has**, because the venues in target hold 150–300
people and a community that grows faster than the nights it can seat produces
members who never get in — *and a member who never gets in is a former member.*
The gate's imperative says the two go in one place, **not in two dashboards.**

`/admin/members/growth` draws a rising total and a referred/organic split. It
draws no capacity, no ratio against one, and nothing that implies either.

**This plan deliberately added none of them**, and the refusal is written into
the page's own docblock so it reads as a decision rather than an omission. A
capacity figure is a product decision — what counts as capacity, which nights

### 7.3 A gate that cannot read an interpolation — named, not fixed

### 7.4 Two placeholders now write the card contract by hand

All three placeholders write the card shell per region rather than reaching for
the generic card-shaped export, because that export renders a title line and two
body lines — the right box for a list row, the wrong box for a KPI tile (a label
and a figure), a picker row, or a feed. A placeholder whose box differs from the
loaded box causes the jump it exists to prevent.

The consequence is that the card contract's three values are now written out in
three placeholder files as well as in the two primitives. **That is a duplication
and it is declared rather than hidden**: if the card's shell ever changes, these
three files are among the sites that must change with it. A fourth skeleton
export would close it, and D-41-04 says such an export ships with its consumer in
the same plan — so it is named here for whoever wants it, not built here.
