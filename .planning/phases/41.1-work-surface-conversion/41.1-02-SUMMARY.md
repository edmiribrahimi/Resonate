## Task 1 — the guard that covered one branch of three

The repaired function, with the three branches each reached only after the
obligation is satisfied (`scripts/verify-dialogs.mjs:1602-1624`):

```js
function neverOpenedReason(path) {
  if (!existsCaseExact(path)) return null;

  if (!walked.has(path)) {
    return ('NOT IN THE WALK — this path is on disk, and this gate\'s walk does not produce\n' + …);
  }
  const skip = NEVER_MEASURED_BY_B.get(path);
  if (skip) return `${skip.kind}\n         ${skip.reason}`;
  const behind = fenceMatch(path);
  if (behind) {
    return ('fenced — behind that glob, never opened; a SCOPE BOUNDARY that says nothing\n' + …);
  }
  return null;
}
```

The obligation is discharged **once, above all three**, rather than copied three
times. That is a stronger statement than "all three are guarded": nothing below
line 1603 is reachable by a path that is not on disk, so a fourth branch added
later inherits the guard instead of having to remember it.

**The walk is consulted before `existsSync`, on the same condition**
(`:1427-1433`):

```js
function existsCaseExact(relPath) {
  if (walked.has(relPath)) return true;
  if (!existsSync(`${ROOT}/${relPath}`)) return false;
  return spelledExactly(relPath);
}
```

`spelledExactly` walks the path segment by segment against `readdirSync`, which
returns names as the filesystem stores them on APFS and on a case-sensitive
volume alike — APFS is case-**insensitive** but case-**preserving**. `existsSync`
survives only as a cheap negative: it can rule a path out and can never rule one
in on its own.

`missing` is computed with the same function, because it is the verdict a
mis-cased entry now reaches.

## Task 2 — the self-check that could not see what it claimed to test

Every `MATCHER_PROBES` row is now a **line array** run through `liveLinesFrom`,
and a row matches when **any** of its live lines matches — the same question
`shellShapes` asks of a real file.

```
grep -n "liveLinesFrom" scripts/verify-dialogs.mjs        → the self-check calls it
grep -n "stripLeadingComments(p.line)" …                  → (nothing)
```

Four rows carry more than one line, and they come in **two pairs**:

| Row | Shape | Expect |
|---|---|---|
| CR-01 | an overlay on the **terminating line** of a multi-line JSX comment | match |
| CR-01 control | the same comment with the three parts quoted **in its body** | no match |
| CR-02 | a closer with **whitespace before the brace**, overlay on a later line | match |
| CR-02 control | the same spaced closer, three parts quoted **in the body** | no match |

**The controls are the discriminating half, and that is the one design judgement
in this task.** A `match` expectation cannot catch a stripper that sees too much
code: a blind one matches too, for the wrong reason, and the row goes green. The
plan asked for the two `match` rows — they are the evidence the shapes are now
*expressible* — and they cannot on their own be the evidence the self-check can
*fail*. The two controls can, and do.

## Deviations from Plan

### 1. [Rule 1 — Bug] `DEF-41-07` item 4's one verdict is the **FAILURE**, not the refusal

The plan's acceptance criterion asks that a case typo *"produces the **same**
verdict (refusal, naming the path) as it would on a case-sensitive volume"*. The
delivered behaviour is the same verdict on both volumes — and that verdict is the
**failure**, `✗ B names a path that does not exist`, exit 1.

The parenthetical could not be honoured, because three sources say the refusal is
the wrong half of the pair:

- `deferred-items.md` DEF-41-07 **item 4** ends: *"on the house machine it is the
  refusal — the laundering the guard exists to prevent."*
- DEF-41-07 **item 1** calls a typo'd entry *"today a FAILURE"* and calls turning
  it into a refusal *"a failure laundered into 'nothing was measured'"*.
- The gate's own docblock argues it at length and calls it *"this defect wearing
  the fix's clothes"*.

The plan's own `<plan_rules>` settles it independently: *a refusal is exit 2 and
means nothing was measured*. A typo **is** measured — the walk measured that no
such file exists — so exit 1 is the honest code. A refusal would also suppress
the other thirteen entries' verdicts, reporting **less** about a tree the gate
can read perfectly well.

The plan's load-bearing requirement — *one typo, one verdict, on any filesystem*
— is met and proved above in both directions.

### 2. [Rule 1 — Bug] four reason strings corrected, not two

The plan names two (`EditArtistButton`, `CreateVenueModal`) and then asks that
`grep -n "the artists work surface"` and `grep -n "the venues work surface"`
return nothing. Neither grep can pass while two further entries carry the same
strings:

- `CreateArtistModal.tsx` was filed under an artists admin surface beside the
  event form — **wrong by the same measurement**: its only importer is
  `EventForm.tsx:8`. This is a Rule 1 correction, not a courtesy.
- `EditVenueButton.tsx` was filed under a venues admin surface, which is **true**
  — but stated as a surface name rather than as something a command prints. It is
  reworded, not corrected, and now names `(work)/venues/[slug]/page.tsx:4`.

### 3. [Rule 3 — Blocking] the withdrawn phrases are described, not quoted verbatim

This file's habit — and Task 1's instruction — is to keep a superseded sentence
visible word for word (`PageShell.tsx:42-46`). Doing that for the two wrong
reason strings would leave `grep -n` unable to answer *does any entry still name
the wrong surface?*, which is the only cheap check a later reader has, and would
have made the plan's own acceptance criterion unsatisfiable.

The withdrawal is recorded in full; the exact strings are not, and the reason is
written beside them. It is the same discipline that keeps whole utility class
strings out of this file (DEF-41-01) applied to a withdrawn sentence.

### 4. [Rule 2 — Missing critical functionality] a malformed probe now refuses

A probe row whose own comment never closes blanks every line after its opener, so
the row would report `no match` for a reason that has nothing to do with the
matcher — a green with a hidden cause, in a gate whose whole subject is exactly
that. Added as a refusal beside the disagreement refusal. It fires on zero of the
fourteen rows today.

### 5. [Process] the probe tree lived outside the repository, and nothing was checked out over uncommitted work

41.1-01 recorded losing a task's edits to `git checkout <ref> -- <paths>`. Applied
here without exception:

## What a Green Here Does Not Mean

- **The self-check is not the evidence.** Fourteen strings written by the same
  hand as the matcher share its blind spots. The evidence is the live run on 263
  real files, and the gate says so in its own output.
- **A `match` row proves expressibility, not sensitivity.** Only the two controls
  can go red when the multi-line state is removed — which is why they exist, and
  why "we added two multi-line rows" would have been a weaker claim than it
  sounds.
- **`leading spans consumed = 0` means the repair has no visible effect today.**
  It is prevention. A reader who takes the zero as "nothing to see" has read it
  backwards: the counter exists to report the day it stops being zero.
- **The case-sensitive half is emulated, not run on such a volume.** `existsSync`'s
  answer was forced to the one that volume gives and the verdict did not move;
  `readdirSync` is case-exact on both by specification. No case-sensitive
  filesystem was mounted, and that is stated rather than glossed.
- **`WORK GROUP REMAINING = 4` counts shells, not correctness.** Every one of the
  four is still a dialog without a focus trap, and check B reads class strings
  and import clauses, never behaviour — H41-2 is a person at two widths.
