## The three judgements this plan had to make

### 1. The rank — gap G-a, and why `none` was refused

The primitive's cell renderer receives only the row, never its position, so the
rank cannot be derived inside a cell. The plan offered two resolutions: the rank
as a title prefix, or `none`.

**`none` was refused.** A card carrying no rank would carry it only as *position
in a scrolling list*, and that is not the fact — a phone user cannot count to
fourteen while scrolling. The primitive's own contract permits `none` "where the
card carries the fact another way", and list position is not another way.

So the rank stays a column, takes the title slot and is declared first, which
puts it above the name in the card's title block. That is what the deleted card
branch said: the position led the name on one line, and it leads it here.

The rank is **precomputed onto the row** in the map that builds the array, where
the ordering is known. The alternative — widening the primitive's cell signature
to pass an index — would edit a published contract that already has an adopter,
to give every table a parameter one table wants.

### 2. The money mark gives position, not weight — gap G-c

The primitive stacks marks at the end of the card inside a bare span, and
applies the data face only in the table branch; the card's *title* is what
carries weight. So each money column's own cell renderer supplies its emphasis.
No contract edit, and the renderer already existed.

Re-declaring the data face on a descendant of a figure cell is the **same
value**, not a second one. The primitive's warning is about the numeric-variant
shorthand, which nothing here writes.

### 3. The section wrappers became cards rather than disappearing

Each table sits inside a wrapper that spelled the legacy edge and ground names,
so it had to change. Two routes existed: delete it, letting the table own its
own container; or substitute the card primitive.

**Substitution was chosen**, because the incumbent already nested row-shaped
blocks inside those wrappers on a phone — the card branch's card-per-row is that
same structure with the primitive's tokens, not a new nesting.

## The client-boundary crossing, stated

`ReferralChainTable` was a server component and is now a client one. The
expansion apparatus is **controlled** — it takes an is-expanded predicate and a
toggle rather than owning the open state — so it needs state.

`nextjs-architecture.md`'s gate on what a client boundary drags into the bundle
asks that such a move be stated rather than discovered in a diff. Stated, here
and in the file's own docblock:

> The referral chain carries member names and per-member spend. **That data is
> already rendered to HTML today** — the incumbent server component printed
> every name and every figure into the markup the browser receives, including
> the ones inside the collapsed disclosure. **No new audience is created.** What
> changes is the mechanism: the same values now travel as props in the
> server-component payload instead of only as markup. The page's guard is
> untouched, and the security boundary was never this file — it is the row-level
> policy on the read.

The alternative — keeping the native disclosure inside a cell renderer — was
considered and refused: it puts the disclosure in one column of the table branch
and nowhere sensible in the card branch, which is the two-lists-that-drift
construction the primitive exists to prevent, reintroduced one level down.

## The announced visible change

**`ReferralChainTable` becomes a real table for the first time.** Its body held
one row per chain whose single cell spanned all three columns, with a native
disclosure laying out its own values inside; the three header cells therefore
labelled columns that **no cell aligned to**. Under the primitive the three
become actual cells and line up under their own headers.

That is an improvement and it is a change a reader will see. It is announced
here and in the file, because a visible change discovered by a reader is worse
than one announced by the plan.

Two smaller ones, for completeness:

- **One chain opens at a time.** The native disclosures allowed any number open;
  the primitive's expansion is a single controlled selection. The figure that
  compares two chains is already on every row, so nothing needs two open.
- **The KPI empty branch stops being drawn at partial opacity.** A sentence
  somebody is meant to read is not dimmed.
