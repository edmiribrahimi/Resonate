## 0. Why this map reads differently from a normal one

The usual pattern-mapper question — *what is the closest analog for this new
file?* — has no purchase here. `41.1-RESEARCH.md:1388` states the phase's own
thesis: *"this phase builds nothing. Every primitive it needs exists and has at
least one adopter."* Nothing in the 21 pages is a new file.

So the question this map answers is the other one:

> **For each file that gets converted, which already-converted file is its
> closest precedent, and what exactly did that precedent do?**

Phase 41 converted **8 surfaces** (`scripts/conversion-manifest.mjs:341-374`),
**15 spine files** (`:82-168`) and published **12 primitives** under
`src/components/ui/` (`ls src/components/ui/` → 12 files). Those are the
analogs. A plan that says *"convert `/admin/analytics`"* without naming which
converted page it should look like is a plan that produces a different answer
per executor.

**One consequence for the planner.** Where §4 says *no analog*, the phase is
genuinely inventing — and one of those five is a **primitive that does not
exist** (§4.4). A phase that claims to build nothing needs to know that before
it schedules wave 4.

## 2. Pattern Assignments

### 2.1 The `PageShell` adoption pattern — every one of the 21 pages

**Analog:** all 10 current importers, and the two that are work pages are the
primary specimens — `src/app/(admin)/admin/(work)/formats/page.tsx:147`
(`default`) and `src/app/(admin)/admin/(work)/members/page.tsx:159` (`wide`).

`grep -rln 'components/ui/PageShell' src` → 10 files. **The exact call shape for
each of the three widths, read from the tree:**

```tsx
// default — (work)/formats/page.tsx:147, (work)/members/register/page.tsx:321
<PageShell width="default">

// wide — (work)/members/page.tsx:122,159 · (work)/members/loading.tsx:38
//        (public)/gallery/page.tsx:82 · (public)/gallery/loading.tsx:26
<PageShell width="wide">

// focus — (auth)/login:142 · (auth)/register:108,130 · (auth)/set-password:50
//         (public)/payment/callback:108,193
<PageShell width="focus">
```

**`width` is always written, never left to default.** All ten importers pass it,
including the eight that could have omitted `default`. Copy that: a width written
is a width a reader can check against §4's closed lists, and
`checkManifest()` (`conversion-manifest.mjs:417-422`) compares it to the manifest.

**Two branches only** (`PageShell.tsx:151-168`). `focus` reads **neither**
navigation property (`FOCUS_ROOT = "flex min-h-dvh items-center justify-center p-6"`,
`:125`); `default`/`wide` read both:

```tsx
// PageShell.tsx:159-168 — the branch every work page renders
<div className="min-h-dvh ps-[var(--nav-inset-inline-start)]">
  <div className={`mx-auto w-full ${width === "wide" ? "max-w-7xl" : "max-w-5xl"}
                   px-6 pt-12 pb-[calc(var(--nav-inset-block-end)+1rem)] ${className}`}>
```

**What a page deletes when it adopts it** — the diff, from
`git show f51eddd -- "src/app/(admin)/admin/(work)/members/page.tsx"`:

```diff
-      <div className="min-h-dvh pb-24">
-        <header className="px-6 pt-12 pb-6">
-          <h1 className="text-3xl font-bold tracking-tight">Members</h1>
+      <PageShell width="wide">
+        <header className="mb-6">
-        <div className="px-6">
-      <AnimatedSection delay={0.1} className="px-6">
```

Four things leave, and they are the same four every time:

1. **the outer `min-h-dvh pb-24` root** — the shell's outer element replaces it;
2. **the gutter and top rhythm `px-6 pt-12`** on the header, and **every
   repeated `px-6`** on inner sections (three sites in this one file);
3. **the header's own bottom padding**, `pb-6` → `mb-6` (a margin inside the
   shell, not a padding on a page root);
4. **the hand-written `<h1>` class string** — `text-3xl font-bold tracking-tight`
   → the `PageTitle` primitive, `src/components/ui/Typography.tsx:53`, which
   carries weight 600 and the display face (§7.1).

**A converted page writes no `max-w-*` at all.** `MAX_WIDTH_RE`
(`verify-conversion.mjs:2546`) enforces it, and `formats/page.tsx:197-207`
records the one legitimate casualty — a typographic *measure* on a `<p>` reads to
the gate as a container *maximum* and had to go (DEF-41-04).

**What differs, per page:** the width, and only the width. §4's `wide` list is
closed (`verify-conversion.mjs:1097-1113`) and names ten of the 21; the other
eleven are `default`, *"which is not a fallback: it is the answer for every
surface nobody had to argue about"* (`conversion-manifest.mjs:367-369`). **No
width judgement is open in this phase.**

#### 2.3a Form dialog — analog: `CreateFormatModal.tsx`

For `EditVenueButton.tsx`, `CreateVenueModal.tsx`, `CreateArtistModal.tsx`.

```tsx
// CreateFormatModal.tsx:365-399
<Dialog
  open={open}
  onClose={close}
  title={…}
  size="lg"                                    // >4 fields ⇒ max-w-lg, §8.3's closed list
  status={formError ? { tone: "crit", message: formError } : null}
  actions={ <> <Button …>Cancel</Button> <Button form={FORM_ID} type="submit" …>…</Button> </> }
>
  <form id={FORM_ID} onSubmit={handleSubmit} className="space-y-4">
    <Input … />
```

Two things to copy that are not obvious:

- **The buttons live outside the `<form>`**, in the `actions` region, and reach
  it through HTML's form-owner attribute (`:126`, `:373-380`). The primitive puts
  `actions` below the scroller (`Dialog.tsx:89`), so a submit inside the form
  would scroll away.
- **The error is `status`, not a hand-rolled box.** `Dialog.tsx:316-322` renders
  `role="alert"` for `tone: "crit"` and `role="status"` otherwise, in
  `--sem-crit` / `--sem-done`. Compare `EditVenueButton.tsx:165-171`, which today
  hand-rolls `border-red-500/30 bg-red-500/10 … text-red-400` and
  `border-green-500/30 … text-green-400` — four raw palette hits that the
  `status` prop deletes outright.

**How the trigger and the open state are wired** — the parent holds the state,
never the dialog: `FormatsCatalogue.tsx:193-198` declares
`useState` per dialog and passes `open={addingFormat}` (`:385-386`) or a bare
`open` inside a conditional render (`:393-394`, `:413-414`, `:435-436`). The
dialog's own `close()` resets its local refusal and calls `onClose()`
(`RetireFormatDialog.tsx:161-164`).

**What `EditVenueButton.tsx` deletes** — `:155-162`:

```tsx
className="fixed inset-0 z-[60] flex items-center justify-center bg-black/60 backdrop-blur-sm px-4"
  className="w-full max-w-md max-h-[85vh] overflow-y-auto rounded-2xl border border-card-border bg-card p-6"
    <h3 className="text-lg font-semibold mb-4">Edit {venue.name}</h3>
```
