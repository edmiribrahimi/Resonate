<decisions>
## Implementation Decisions

### The navigation clearance — and why DEF-41-08 is not the Critical intervention it looked like

Round 5 handed this phase a structural question it declared too dangerous to
answer inside a gate-authoring round: *the clearance reaches the four focus
routes from outside the shell, and the resolution edits files that are
`access-gating` and `ticketing-payments` primary.* **Measured on the live tree,
that premise does not hold.**

- **D-41.1-01: `--nav-inset-inline-start` stops being ambient.** `:root` declares
  it `0px` unconditionally; the sites that mount the **responsive** navigation
  form declare `14rem` at the `md` tier on the wrapper around their content.

  **The measurement that decides it.** There are **13 navigation mount sites**.
  Only **two** mount `AppNav` in its responsive form — the one that becomes a
  224px leading column at `md` and up:

  | Mount site | Form | Column at `md`+ |
  |---|---|---|
  | `src/app/(admin)/admin/(work)/layout.tsx` | responsive | yes |
  | `src/app/(public)/gallery/page.tsx` | responsive | yes |
  | 11 others, all via `MobileNav` | phone, locked | **no, at any width** |

  `src/app/globals.css:300-305` declares `--nav-inset-inline-start: 14rem` at
  `@media (min-width: 48rem)` on `:root`. **That statement is already false for
  eleven of the thirteen mount sites**, and false for every route that mounts no
  navigation at all. Nothing breaks visibly today only because the eleven
  hard-code `pb-24` and never read the variable. DEF-41-08's reproduction — a
  route wrapper above the auth group that reads the variable and receives 224px —
  is not a hole waiting to open; it is the first place an already-false ambient
  default produced a visible effect.

  With the default at zero, a wrapper anywhere that reads the variable resolves to
  nothing. **The clearance becomes structurally unable to reach a route that
  mounts no navigation** — which is DEF-41-08's resolution (2), the one round 5
  called the owner's.

- **D-41.1-02: only the inline axis moves. `--nav-inset-block-end` stays
  ambient.** The bar *is* mounted at phone width on twelve of the thirteen sites,
  so the ambient value is approximately true where it is read; `PageShell`'s focus
  branch does not read it; and moving it would change `Dialog`'s sheet padding and
  `ToastContainer`'s offset on unconverted 41.2 surfaces **to fix no measured
  defect**. Narrowing the change to the axis that is wrong is the opposite of the
  five-round pattern chase — and the asymmetry is stated: forgetting the inline
  declaration puts content under a column (loud, first look); leaving the block
  axis alone changes nothing at all.

- **D-41.1-03: `:has()` was considered and rejected, and the reason is not
  browser support.** `:root:has([data-app-nav])` would have expressed the exact
  invariant with zero mount-site edits. It is **Baseline widely available since
  December 2023**, and Tailwind v4's own floor — Chrome 111, Safari 16.4, Firefox
  128 — already sits above it, so it would have added no new boundary. It is
  rejected because **MDN explicitly warns against anchoring `:has()` to `:root` or
  `body`**: any DOM change in the subtree forces re-evaluation, and this product
  re-renders a live attendee list on a phone at a door. Written down so the next
  reader does not re-derive it as an oversight.

- **D-41.1-04: the impact analysis, stated before the diff.** Under D-41.1-01 the
  files that change are `src/app/globals.css`,
  `src/app/(admin)/admin/(work)/layout.tsx` and `src/app/(public)/gallery/page.tsx`
  — **two of them already converted, all three in this phase's own territory.**
  **Zero files under `src/app/(auth)/**`, zero under
  `src/app/(public)/payment/callback/**`, zero behind the Phase 42 fence, zero
  unconverted 41.2 pages.** This work is therefore **Structured, not Critical**.

  **And that boundary is a stop condition, not a prediction.** If planning or
  execution discovers the fix cannot land without opening a file under the auth
  group or the payment callback, that is a **halt and a fresh impact analysis put
  to the owner** — not a judgement made at execution time. The delegation covers
  choosing the approach; it does not pre-approve a Critical path the approach was
  chosen to avoid.

- **D-41.1-05: check E stops freezing a shape and starts asserting a pairing.**
  Five consecutive rounds taught the matcher one more shape and watched the defect
  move. With the ambient value gone, *reading* the variable is harmless and the
  property that matters becomes **who declares the column clearance** — a closed
  set with one token. The assertion becomes: *the files declaring the column
  clearance are exactly the files mounting the responsive navigation form.* Local,
  textual, and reachable by a grep — the first form of this check in five rounds
  that is not chasing a shape. The exact assertion is the planner's.

- **D-41.1-06: the door gains no column clearance, and D-41-21's fence holds
  verbatim.** `MobileNav` stays the bar-locked wrapper; `DoorSurface.tsx` and
  `src/app/(admin)/door/**` are not opened. Any mechanism that would give the door
  a leading column at tablet width is rejected on that ground alone — a tablet at
  an entrance losing 224px is a change to the door's surface, and the door is
  Phase 42's.

### The gate that can go quiet — the stripper, and why it lands first

- **D-41.1-07: the comment stripper becomes ONE module, imported by all eight
  gates that carry a copy today.** Measured: `verify-breakpoints`,
  `verify-conversion`, `verify-dialogs`, `verify-no-viewport-read`,
  `verify-semantic-separation`, `verify-tables`, `verify-tokens`,
  `verify-touch-targets` — **eight copies of one heuristic**, of which round 5
  repaired two. `DEF-41-06` asked whether four copies were worth keeping; the
  answer is that there were never four. Cross-script ESM import is already house
  style (`verify-capabilities.mjs` imports from `rls-baseline.mjs`).

  The module takes the **strongest** existing version, not the average: G5's
  block-comment state (DEF-41-06's fifth shape) plus round 5's two — the
  terminating line of a multi-line JSX comment, and `{/* … */ }` with whitespace
  before the closing brace. It stays a line-shape state machine and does **not**
  become a tokeniser: `40-REVIEW.md` WR-07 records that a real comment parser
  written in this repository was unsound.

- **D-41.1-08: it lands before the first conversion plan of this phase.** Every
  `REMAINING` deletion in 41.1 is a claim these gates measure, and round 5 measured
  a money-domain entry (`src/components/admin/RefundDialog.tsx`) going invisible
  through exactly this hole, with the gate printing *"converted; remove this
  entry"* and exiting 0. Converting first and repairing after would mean deleting
  entries on the authority of a mechanism known to be blind. **This is the one
  ordering constraint in the phase that is not negotiable at plan time.**

- **D-41.1-09: proved by asserted mutation, with the mutation asserted applied
  before its result is read.** `ai-engineering.md`'s *prova per mutazione*, whose
  whole point is that a substitution which did not land produces a green that
  means nothing. The harness runs on a disposable copy under the session
  scratchpad, never inside the repository — round 5's own reproduction did exactly
  this and confirmed `git status --porcelain` empty before and after.

- **D-41.1-10: `DEF-41-07`'s four refusal defects land in the same plan**, because
  they live in the same two files and those files are open anyway. **With one
  exception decided here:** item 2 — the refusal branch nothing can reach — is
  closed by **retiring the advertisement**, not by making the branch reachable.
  A header that promises a guard the code cannot deliver is a false header
  sentence and this phase has found three; deleting the sentence adds no code and
  removes the lie, and making the branch reachable would add both.

- **D-41.1-11: every `REMAINING` entry gains a group tag, and each gate prints a
  per-group count.** Criterion 4 says *"G6's `REMAINING` list is empty for the
  work group"*, and the lists are flat today: 19 files carry `sm:`, of which
  roughly fifteen are work-group and four are `(public)/events/[slug]/**`, which
  is 41.2's. Without the tag, the phase's own exit condition is eyeballed. A
  criterion that cannot be read off a gate is a claim.

### The five tables

- **D-41.1-12: the five adopt `src/components/ui/DataTable.tsx`; no table invents
  a second card layout.** The contract already exists and is written —
  `DataCardSlot = "title" | "subtitle" | "mark" | "meta" | "none"`, one renderer
  serving both branches *"so there is nowhere for the two to disagree"*. What
  remains is per-table slot assignment, which is a judgement about which fact is a
  row's identity, not an open design question. The five: `MemberSpendTable` (8
  columns), `DrinkSalesBreakdown` (6), `ReferralChainTable` (4), `SalesDashboard`
  (7), `TransactionList` (6, and 835 lines).

- **D-41.1-13: on a surface that carries money, a figure that decides money is a
  `mark`, never `meta`.** `TransactionList` is the finance transaction list and
  `SalesDashboard` is the event's sales; a card that buries an amount among the
  meta line is a card that changes what an operator reads first. `none` is
  permitted only where the card carries the fact another way — the primitive's own
  docblock already says so, and this decision only refuses the money exception.

- **D-41.1-14: `ReviewListClient` stays exempt, unchanged (D-41-16).** It is the
  copy-out diagnostic grid, and its own copy says it exists to be pasted into a
  diagnostic tool. Cards would destroy the thing it is for.

### Waves, and the shim's exit

- **D-41.1-15: a wave's plans partition files, and a shared component two plans
  would both touch is either converted in an earlier wave as spine, or assigned to
  exactly one plan.** `DEF-41-03` records this failure twice in one phase: two
  plans in one wave each satisfied their own contract and left a joint obligation
  that belonged to neither afterwards, and nothing in the workflow looks for one.
  21 pages will parallelise harder than 41 did.

- **D-41.1-16: after each wave merges, one task re-runs the gates and reconciles
  the `REMAINING` lists against the tree.** The round-5 lesson stated plainly: **a
  debt tracked by a proxy metric is closed by anything that moves the metric.** A
  count that fell is not evidence that work happened.

- **D-41.1-17: the plan that removes the `(work)` layout shim is named at planning
  time, not discovered.** Its own docblock already declares the exit — *"removed by
  the plan that converts the last page under this layout"* — and criterion 1 makes
  its removal a condition of the phase closing, so it cannot be inherited by 41.2.

  **The end state, written now rather than inferred:** the navigation-mounting
  layout **declares** the clearance and `PageShell` **consumes** it; the shim's two
  nested elements collapse to one carrying a declaration. Until the last page
  converts the layout must keep padding as well, because an unconverted page does
  not render `PageShell` and would otherwise sit under the column. The shim
  therefore shrinks in two steps, and the second one is the last conversion plan.

### Human observation

- **D-41.1-18: H41-1 runs per wave, not accumulated to the end.** A look at three
  widths at every converted surface is the only thing that says a surface is
  workable, and a batch of 21 surfaces looked at once, at the end, is a batch that
  gets skipped. `41-CR01-PASS.md` rows 7-13 are still `pending` and H41-4 is still
  `human_needed`; nothing in this phase substitutes for either, and no gate here
  should be written as if it could.

## Existing Code Insights

### Reusable assets
- **`DataTable` + `DataCardSlot`** — the table↔card contract, already written, one importer (`MemberTable.tsx`). The five remaining tables are adoption, not construction.
- **`PageShell`** — 10 importers today; the width and the clearance both come from it.
- **The `(work)` layout** — already resolves the access context once and mounts both navigation forms for all 24 work pages. Every page under it inherits the conversion of one file.
- **`Dialog`** — the extracted primitive; `REMAINING` is 14 files, of which the work-surface modals are this phase's and the public/member/money ones are 41.2's.

### Established patterns
- **A gate declares its debt as a number that can only go down**, printed loudly on every green (`REMAINING`, `ORPHANS_DECLARED`). Round 5 proved the number can also fall because the gate stopped looking — D-41.1-16 exists for that.
- **A refusal is exit 2 and means nothing was measured**; a failure is exit 1. `verify-all.mjs` counts the two separately and prints what it did not run.
- **An exemption is written into a gate before the gate's first run** (D-41-16). An exemption discovered on a first red run is an exemption nobody trusts.

### Integration points
- `:root` in `globals.css` is where the clearance is declared today and where D-41.1-01 empties it.
- `scripts/conversion-manifest.mjs` is the single list both G1 and G4 read — a wrong entry makes a gate assert the right thing about the wrong file.
- `verify-all.mjs` is where a new or changed gate becomes visible to anyone who is not the person who wrote it.

## Specific Ideas

- The stripper module's first consumer should be one of the six gates that
  **still carry the unrepaired copy**, not one of the two round 5 already fixed —
  the extraction is provably correct when a gate that was blind stops being blind.
- `TransactionList.tsx` appears on three lists at once: the tables `REMAINING`,
  the `sm:` list, and the money domain. It is the single best first table to
  convert, because it is the one where a mistake is visible in the place it
  matters.
- The `(work)` layout is one file that clears 21 pages. Converting it early makes
  every subsequent page cheaper; converting it late makes every subsequent page
  carry a workaround.
